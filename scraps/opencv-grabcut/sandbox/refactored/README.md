# 共通処理を整理した比較用の版

`submissions/` の6本を元に、複数のスクリプトで使う処理と設定だけを共通化しました。
1目的1スクリプトと実行順、入力・計算・保存の機能を維持しています。
GUIは `02` を基準に「上部＝入力と状態、左＝操作、右＝画像・表・グラフ」へ揃えました。
提出版と独立して比較できるように、`sandbox/` に置いています。

このフォルダを別の場所へ持ち出すときは、実行するスクリプトと共通ファイルを一緒にコピーします。
単独ファイルで持ち出せる提出版との違いです。

## 共通化の判断

- **入出力先**：`workflow_settings.py` を変更すると全工程が同じ基準に従います。`01` の補正画像の出力先と、`02` の読込開始先は同じ `RECTIFIED_DIRECTORY` です。
- **画像の読込・保存**：日本語パスへの対応、PNG変換の成否確認、保存フォルダの作成を `file_io.py` にまとめました。画像・CSV・グラフの保存先の拡張子と入力保護にも、同じ確認処理を使います。
- **CSVとグラフ**：CSVの書込と読込を `measurement_csv.py` へ集め、列名・文字コード・数値の扱いを同じ場所で読めるようにしました。比較順とグラフは `length_comparison.py` にあります。
- **GUIの枠とファイル操作**：画面の3領域、CSV選択・重複除外・事前検証、PNG保存先の選択、グラフの破棄・再配置を `gui_parts.py` にまとめました。
- **個別の計算とGUI操作**：補正、GrabCut、側辺長、累積圧下率の計算は担当するスクリプトに残しました。ボタンと計算のつながりや、GUIごとの状態は同じファイルで追えます。

共通化は現在の重複を減らせる箇所に限りました。
板を作る数行の処理やGUIの短い重複は残し、継承クラス・一括実行・設定ファイルの自動読込は追加していません。
例えば `02` のGrabCutから長さ計算までを別モジュールへ分けても、現在は利用元が1本だけです。
今回は計算の順序を同じファイルで追えることを優先しました。

### 読み進める順序

1. 使う実行スクリプトの先頭で、入力・出力・importしている共通処理を確認する。
2. CLIは `main()`、GUIは `main()` 内のボタンの処理から、入力→計算→保存を追う。板生成も `main()` に揃え、読込時にはファイルを保存しない。
3. ファイル選択や画面構成は `gui_parts.py`、画像操作は `file_io.py`、CSVの受渡しは `measurement_csv.py`、グラフは `length_comparison.py` を読む。

例えば局所比較GUIでは、「CSVを追加」→ `choose_csv_paths()` で選択・事前確認 → `read_measurements()` で読込・換算 → `create_graph()` と `replace_graph()` で描画、という流れです。
厚さ版は `compare_lengths_with_thickness()` が同じ `read_measurements()` を使い、その結果へ厚さと累積圧下率を加えます。
自作モジュールを読む必要は増えますが、比較する2本に同じ検証コードを重ねて置かずに済みます。

処理の役割に合わせ、次の名前へ揃えています。

- 比較GUIの再計算・表の更新は両方とも `update_comparison()`。
- ファイルへ書く処理は `write_*`、ダイアログから保存するGUI操作は `save_*`。CSVとPNGを組で保存する操作は `save_measurement()`。
- 上部の操作領域は `header`、保存ボタンは `save_measurement_button`・`save_graph_button`。
- 厚さの文字入力は `initial_thickness_text`・`thickness_text`、数値は `initial_thickness_mm`・`thickness_mm`。

## GUIの配置と状態

| 領域 | 計測GUI | 局所比較GUI | 厚さ付き比較GUI |
| --- | --- | --- | --- |
| 上部 | 画像読込・ファイル情報・状態 | CSV追加・件数・状態 | CSV追加・件数・状態 |
| 左側 | 矩形・区間・計測・結果・保存 | 表示切替・選択CSVの削除・保存 | 初期厚さ・表示切替・横軸・保存 |
| 右側 | 画像と計測区間・側辺 | CSV一覧とグラフ | 撮影ごとの厚さ入力・計測値とグラフ |

`02` は計測ボタンで計算し、比較GUIは入力の変更に合わせて自動更新します。
厚さ版の表は上下・左右にスクロールでき、狭い画面でも全列と各行の削除ボタンを操作できます。
最小サイズは計測が1000×760、比較が960×640で、各画面の用途に合わせて維持しています。

結果を消す処理は各GUI内の `clear_results()` に揃えました。状態管理全体を別モジュールには移していません。
選択ダイアログを取り消した場合や、新しいファイルを受け付けられない場合は、現在の有効な入力・結果を保ちます。
使用中の入力や条件を変えた場合は古い結果を無効にし、計算に成功してから保存を有効にします。
CSVの追加は選択した全件を確認してから行い、途中の1件で失敗した場合はその選択全体を追加しません。
比較時はCSVを読み直すため、追加後にCSVが変更・削除された場合の検出も維持しています。

比較が成功したときの説明文や件数の重複表示は出しません。件数は上部、追加順は表の見出しで確認できます。
ステータスは `計測中…`・`計測完了`・`保存: ファイル名`、必要な入力の不足、失敗の理由に絞っています。
空画像や読めないCSVは、OpenCVやOSの詳細文をそのままGUIへ表示せず、対象ファイル名を付けた短いエラーにします。

計測の「CSV・画像2枚を保存」でCSV名を選ぶと、計測CSV・初期指定PNG・計測結果PNGをまとめて保存します。
例えば `shot_lengths.csv` を選ぶと、矩形の色を重ねた `shot_lengths_initial.png` と、
赤い側辺・黄色の区間を重ねた `shot_lengths.png` を元の解像度で保存します。画面の表示切替には依存しません。
既存の3ファイルは確認なしで上書きします。2枚ともPNGへ変換できることを確認してからCSVを書きます。
書込途中で失敗した場合には `保存失敗: CSV・PNGを確認してください` と表示し、部分的に保存されている可能性を知らせます。

### 拡大して矩形・計測区間を選ぶ

- ホイールでカーソル位置を中心に拡大縮小し、右ドラッグで画像を移動します。「全体表示」で画面内に戻します。
- 「矩形」を選んで左ドラッグすると、選択中の種類の矩形を追加します。前景候補・確実な背景・確実な前景のいずれも複数追加できます。
  一覧で選んで削除できます。前景候補の追加時にも既存の矩形を残します。
- プレビュー上部の「開始y」「終了y」を選び、画像をクリックすると、その行を計測区間に設定します。従来の数値入力も使えます。
- 拡大・移動・表示切替・画面サイズの変更では、矩形・計測区間・計測結果を保ちます。描画は画面に見える範囲だけを作ります。

GrabCutは、前景候補と確実な前景を囲む矩形に、幅・高さの10%（最低10px）の余白を足した範囲だけで実行します。
範囲外の物体や背景は計測に使いません。前景候補は測りたい試料の両側辺と計測区間全体を含め、
確実な背景はその近くの床・ローラーなどへ指定します。余白は `02` 冒頭の `GRABCUT_MARGIN_RATIO` で変更できます。
試料が処理範囲の側端へ接した場合は、側辺が欠けたまま計測せず、前景候補を広げるよう表示します。
複数の矩形は同じ試料の初期指定です。従来どおり、抽出後の最大領域1つの側辺を測ります。
推論用に範囲を絞っても、画像座標・画素間隔・mm/pxは元の補正画像の値です。

画像の左側をDR、右側をOPとして、結果表・プレビューの両隅・保存PNG・比較GUIとグラフへ表示します。
CSVの列名は既存の `left_*`（DR）・`right_*`（OP）を使い、過去のCSVも比較できます。

### 補正画像を中央部分に絞る

`01_rectify_images.py` と `01_rectify_frames_from_reference.py` は、共通設定の `RECTIFY_ROI` を使います。
既定値は `(0.25, 0.0, 0.75, 1.0)` で、歪み補正後の画像の中央50%の幅・縦全体を出力対象にします。
値は左・上・右・下の比率です。縦方向も不要な場合は、例えば `(0.25, 0.1, 0.75, 0.9)` へ絞れます。
`(0.0, 0.0, 1.0, 1.0)` にすると従来どおり全体を出力します。

元の写真・基準画像・動画フレームは、カメラ校正と同じ元解像度のまま渡してください。
板の検出には画像全体を使い、その後に指定範囲の4隅から遠近補正の出力枠を求めます。
傾いた範囲を囲む長方形を保存するため、周辺が少し入る場合や、出力画素数が比率どおりにならない場合があります。
リサイズはせず `MM_PER_PX` を維持するので、GUIも同じ倍率で測れます。
固定カメラ版は基準画像と全フレームに同じ出力枠を使います。実行時に出力の縦横pxを表示します。
範囲を変えた場合は補正PNGを作り直し、試料の両側辺と測りたい区間が残っていることを確認します。

## 設定と実行

`opencv-grabcut` フォルダから実行します。依存関係は題材の `pyproject.toml`・`uv.lock` を共用します。

```powershell
uv sync
uv run sandbox/refactored/00_1_generate_charuco_board.py
uv run sandbox/refactored/00_2_calibrate_camera.py
uv run sandbox/refactored/01_rectify_images.py
uv run sandbox/refactored/02_measure_edge_lengths_gui.py
uv run sandbox/refactored/03_compare_edge_lengths_gui.py
# 厚さとの関係も見る場合はこちらを選ぶ
uv run sandbox/refactored/03_compare_edge_lengths_with_thickness_gui.py
```

初期準備は次の順序です。

1. `workflow_settings.py` の板の寸法を確認して印刷し、実寸を測る。
2. 校正写真を `sandbox/refactored/input/camera_calibration/` に置く。
3. `00_2` を実行し、表示された `CALIBRATION_SIZE`・`CAMERA_MATRIX`・`DIST_COEFFS` を、この版の `01` の冒頭に貼る。現在は未設定なので、校正するまで補正は実行できない。
4. `workflow_settings.py` の `MM_PER_PX` を確認し、写真を補正してから計測する。既定値は `0.25`。

写真の枚数と撮り方は [撮影手順](../../CAPTURE.md) で管理し、この版では枚数の下限による停止や枚数不足の案内を行いません。
校正・補正とも `find_images()` で入力フォルダ直下の画像を取得し、フォルダがない場合や画像がない場合は同じ処理で停止します。
`00_2` は、次の写真を理由・ファイル名とともに表示してスキップし、残りで係数を求めます。

- 読み込めない画像。
- 板の角を縦横に6点以上検出できない写真。
- 最初に板を検出できた写真と解像度が違う写真。
- 魚眼校正で `Ill-conditioned matrix for input array ...` と特定された写真。この写真を除いて再計算し、別の写真が同じ理由で失敗した場合も繰り返します。

読めた写真には従来どおり確認PNGを保存し、検出・解像度の判定を `OK` / `NG` で示します。
`OK` でも後の校正計算で除外されることがあるため、最終的な採否は実行時のスキップ表示で確認します。
最後に使用枚数・スキップ枚数と、使用した写真だけの再投影誤差、コピペ用の3設定を表示します。
画像を読み込めなかった場合には、その画像の確認PNGは作成できません。

使える写真がなくなった場合、原因の写真を特定できない計算エラー、係数が不正な場合、確認PNGの保存失敗では停止します。
枚数による下限や、再投影誤差のしきい値による自動除外は追加していません。写真を除外して係数が出ても、校正結果の精度確認は必要です。

板の寸法を変えたら、板を印刷し直してカメラ校正もやり直します。
倍率を変えたら、変更後の設定で補正画像を作り直します。
設定は起動時に読み込むため、変更後は実行中のスクリプト・GUIを起動し直してください。
この設定は元の `submissions/` には反映されません。

入出力先は `workflow_settings.py` の冒頭で変更します。既定では、この `refactored/` フォルダを基準にしています。
`OUTPUT_DIRECTORY` を変更すると、補正画像・校正の確認画像の保存先、計測・比較GUIの保存開始先も追従します。
`RECTIFIED_DIRECTORY` を個別に変更した場合も、補正の出力先と計測の読込開始先は揃います。
既定の場所は次のとおりです。元の提出版の入出力とは分かれています。

| 用途 | 題材フォルダからのパス |
| --- | --- |
| 校正写真 | `sandbox/refactored/input/camera_calibration/` |
| 補正する写真 | `sandbox/refactored/input/` 直下 |
| 板・読取確認画像・計測・比較結果 | `sandbox/refactored/output/` |
| 補正画像 | `sandbox/refactored/output/rectified/` |

既存の写真を使う場合は、`workflow_settings.py` の `INPUT_DIRECTORY`・`CALIBRATION_DIRECTORY` を変更するか、写真をコピーします。
既存の補正PNGや長さCSVは、各GUIのファイル選択から直接読み込めます。
CSVの列、数値の丸め方、UTF-8 BOMは提出版と同じです。
確認PNG・比較PNGの表示名はDR・OPで、補正PNGの出力範囲は上記の共通設定に従います。
各GUIで任意の保存先を選ぶ場合は、元の出力を残せる名前を指定してください。
撮影条件・板と試料の高さ・GUI操作・エラー時の扱いは [提出版の手順](../../submissions/README.md) と [撮影手順](../../CAPTURE.md) を参照してください。
提出版の手順にある入出力先・板・倍率の設定先は、この版では `workflow_settings.py` に読み替えます。

## 動画からフレームを保存する

`opencv-grabcut` フォルダから実行します。追加の依存関係はありません。

```powershell
uv run sandbox/refactored/video_frame_gui.py
```

1. 「動画を開く」で動画を選ぶ。先頭フレームを表示する。
2. 「再生／一時停止」で再生を切り替える。スライダーで位置を移動すると一時停止する。
   「1コマ戻る」「1コマ進む」で保存する瞬間を選ぶ。
3. 「フレームを保存」で一時停止し、PNGの保存先を選ぶ。

画面に合わせて縮小表示しますが、保存するPNGは元解像度・元の画素です。
回転メタデータによる自動回転は無効にし、補正前の切り抜き・寸法変更も行いません。
音声は再生せず、動画のFPSに合わせて順に表示します。処理が追い付かない場合は再生が遅くなります。
フレーム番号は0から数え、時刻は `フレーム番号 / FPS` の目安です。
末尾で自動停止し、もう一度「再生」を押すと先頭から再生します。

保存開始先は `input/video_frames/`、ファイル名の初期値は `動画名_frame_000000.png` です。
ボード付きの瞬間は `input/video_reference/reference.png` として保存すると、次の一括補正でそのまま使えます。
保存ダイアログの取消後も一時停止を保ちます。同名PNGへの保存は上書きを確認します。
読込の取消や失敗では現在の動画を保持します。OpenCVで開けて、フレーム数とFPSを取得できる動画を使ってください。

## 固定カメラの動画フレームを補正する

`01_rectify_frames_from_reference.py` は、動作前のボード付き基準画像から補正を1回求め、
動作中の全フレームへ同じ歪み補正・遠近変換・出力範囲を適用します。
各フレームにはボードが不要です。毎画像のボードを使う従来の `01_rectify_images.py` と使い分けます。
上のGUIやFFmpegでフレームを切り出し、このスクリプトにはPNG・JPEGなどの画像を渡します。

### 設定と実行

1. 基準画像と測定フレームを、同じ動画条件・元解像度で書き出す。リサイズ・切り抜き・回転は加えない。
2. このスクリプトの冒頭へ、動画条件に適合する `CALIBRATION_SIZE`・`CAMERA_MATRIX`・`DIST_COEFFS` を貼る。
   既存の `01_rectify_images.py` の係数は自動では読み込まない。魚眼モデルの歪み係数4個を使う。
3. 同じ冒頭の `REFERENCE_IMAGE_PATH`・`FRAMES_DIRECTORY`・`RECTIFIED_FRAMES_DIRECTORY` を確認する。
   既定値は次のとおり。板の仕様と `MM_PER_PX` は既存GUIと同じ `workflow_settings.py` を使う。

| 用途 | `refactored/` を基準にした既定の場所 |
| --- | --- |
| ボード付き基準画像 | `input/video_reference/reference.png` |
| 補正するフレーム | `input/video_frames/` 直下 |
| 補正フレーム | `output/rectified_frames/` 直下 |
| 基準画像の補正結果 | `output/rectified_frames/reference/reference.png` |

入出力の既定値は共通の `INPUT_DIRECTORY`・`OUTPUT_DIRECTORY` から決まります。
撮影ごとに保存先を変える場合は、このスクリプトの `RECTIFIED_FRAMES_DIRECTORY` を変更してください。
基準画像の補正結果は `reference/` 内に基準画像の名前をPNGへ変えて保存します。
入出力のフォルダは混ぜず、結果を再現するため基準画像・設定済みスクリプト・共通設定を保管します。

`opencv-grabcut` フォルダから実行します。


まず基準画像の補正結果で既知寸法を照合し、次に補正フレームで側辺を測ります。

同じ `MM_PER_PX` で作った補正PNGを使うので、計測CSV・確認PNG・比較の手順は既存のままです。
測れるのは各フレームに見える指定区間の左右側辺長です。全長の復元や同じ材料区間の追跡は行いません。

### 撮影条件と結果の扱い

- 基準撮影から動作中までカメラの位置・高さ・向き・画角・ズームを固定する。
  手ぶれ補正・水平維持・自動クロップなど、画像の対応関係を変える処理は使わない。
  基準画像も同じ動画から切り出し、カメラ係数が動画の撮影モードに適合していることを確認する。
- ボードを測定予定の試料面に近い高さ・傾きで平らに置く。
  高さの差や反りによる誤差は補正しない。結果はボードの基準面に換算した長さとして扱う。
- 写真内の向きを保つため、試料の長手は画像の縦方向へ揃え、区間内の左右両側辺を写す。
  動体ブレ・反射・影で境界が読めないフレームは測定に使わない。
- カメラを動かしたら、新しい基準画像と別の出力先を使う。
  設備の動かない部分や終了後のボード画像で構図の変化を確認する。
  同じ画像サイズでも画角・カメラ姿勢の変化はコードでは検出できない。

基準画像で角を縦横に6点以上読めない、再投影誤差が2pxを超える、補正画像が大きすぎる場合は停止します。
表示する角数・再投影誤差は基準画像の値であり、動作中のフレームの寸法精度を表す値ではありません。
フレームは基準画像と同じ解像度であることを確認します。解像度不一致はファイル名を示して停止します。
既存の出力PNGは同名で上書きしますが、基準画像・入力フレームへの上書きと出力名の重複は実行前に拒否します。
途中で失敗した場合、基準画像の補正結果と処理済みフレームは残ります。
入力を直し、結果を退避するか同じ条件で上書きして再実行してください。

## 2点間の距離を確認する

補正後の寸法を定規や既知間隔の印と照合する場合は、補助GUIを使います。
`opencv-grabcut` フォルダから実行します。

```powershell
uv run sandbox/refactored/measure_point_distance_gui.py
```

1. 「補正画像を読み込む」で、`01` が保存した補正PNGを選ぶ。
2. 画像上の始点と終点を順にクリックする。2点と接続線、直線距離のmmが表示される。
3. 次のクリックを新しい始点として、続けて測る。

目盛や印が小さい場合は、マウスホイールでカーソル位置を中心に拡大縮小できます。
右ボタンを押したままドラッグすると画像を移動し、「全体表示」で画面内に収まる表示へ戻します。
これらの操作でも測定点と距離を保持します。

倍率は `workflow_settings.py` の `MM_PER_PX` を使います。補正画像を作ったときと同じ設定で起動してください。
読込時は画像の縦横比を保って画面内へ縮小表示し、距離は元画像の座標から計算します。
ウィンドウの大きさを変えても測定点と距離を保持します。画像外のクリックは無視し、別画像を読み込むと測定点をリセットします。
読込の取消や失敗では現在の画像と測定を保ちます。撮影時は基準物とChArUco板を計測面と同じ高さ・平面に置いてください。
