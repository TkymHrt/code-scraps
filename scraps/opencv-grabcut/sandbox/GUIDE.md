# 比較試験のガイド: 旧方式と反射除去

このガイドは `sandbox/` に保存した旧方式と反射除去の比較試験を説明します。
フル解像度で条件を統一した実践用は [../GUIDE.md](../GUIDE.md) にまとめています。
以下の実行コマンドは `opencv-grabcut` フォルダが基準です。
コードの中には説明コメントを書いていません。その代わり、ここに全部まとめています。

## 1. 全体のやりたいこと

- `input.png` という写真を読み込む
- 写真の真ん中に写っている「板」だけを見つける
- `ex03`〜`ex05` はふちを描く。`ex06` はマスクと抽出画像だけを保存する

## 2. 使い方

```sh
uv run sandbox/ex03_outline.py
# input.png -> result_03.png

uv run sandbox/ex04_side_edges.py
# input.png -> result_04.png

uv run sandbox/ex05_side_lengths.py
# input.png -> result_05.png / result_05.csv。ターミナルにも長さを表示

uv run sandbox/ex06_mask.py
# input.png -> result_06_initial.png / result_06_mask.png / result_06.png
```

旧方式は `sandbox/input.png`、反射除去の試験は `sandbox/input_ai.png` を読み込みます。
全ての出力は `sandbox/results/` に保存します。入力が無いとエラーで止まります。

## 3. 4つのコードの役割

| ファイル | 役割 | 出力 | 特徴 |
| --- | --- | --- | --- |
| `ex03_outline.py` | 基本形。元の大きさのまま板を見つけて、輪郭を赤で囲む | `result_03.png` | シンプルで見通しが良い |
| `ex04_side_edges.py` | 応用形。半分の大きさで高速に探して、左右のふちだけ赤線を引く | `result_04.png` | 速い。後の計測に使いやすい形 |
| `ex05_side_lengths.py` | 計測形。左右のふちに沿った長さと合計を出す | `result_05.png` / `result_05.csv` | 左はオレンジ、右は水色。単位はpx |
| `ex06_mask.py` | マスク実験用。先頭の数値を変えて抽出を見比べる | `result_06_initial.png` / `result_06_mask.png` / `result_06.png` | GUI・コマンドライン引数なし。縦長・横長の画像で使える |

`ex04` は `ex03` のほぼコピーに、3つの工夫を足したものです。

1. 最初に画像を半分に縮小する（速くするため）
2. 最後に一番大きい白い塊だけ残す（ゴミ除去）
3. 輪郭ではなく「各行の左端と右端」を線で結ぶ（左右のふちだけ欲しいため）

## 4. 共通の考え方: 画像とマスク

### 画像 = 数字の表

OpenCVでは画像は `numpy` の配列です。

- カラー画像の形は `(高さh, 幅w, 3)` です。3は青・緑・赤(BGR)の3色分です。
- `h, w = image.shape[:2]` は「高さと幅だけ取り出す」という意味です。
- `image.copy()` は「元の写真を壊さないようコピーを作る」という意味です。

### マスク = 付箋

マスクは画像と同じ大きさの表で、画素ごとに「ここは何？」というメモを書きます。
GrabCutでは4種類だけ使います。

| 値 | 名前 | 意味 |
| --- | --- | --- |
| 0 | `GC_BGD` | 絶対に背景。ここに板は無いと断言する |
| 1 | `GC_FGD` | 絶対に前景(板)。ここに板があると断言する |
| 2 | `GC_PR_BGD` | たぶん背景。迷ったらこっちに入れておく初期値 |
| 3 | `GC_PR_FGD` | たぶん前景(板)。板がありそうな場所 |

コードではこう初期化しています。

- 全体を `2: たぶん背景` で塗る
- 左右の端を `0: 絶対背景` で塗る
- 中央あたりを `3: たぶん板` で塗る
- ど真ん中だけ `1: 絶対板` で塗る

書き方 `mask[:, :int(w * 0.33)]` の読み方:

- `:` の前が行、後ろが列です。`:` だけだと「全部」という意味です。
- `mask[:, :int(w * 0.33)]` = 「全ての行について、左から33%までの列」
- つまり画面左端の縦帯です。

## 5. `ex03_outline.py` の流れ

上から順番に読みます。

### 5-1. 画像を読む

`cv.imread("input.png")`

- 引数: ファイル名1つだけ
- 返り値: 読めたら画像の配列、読めなかったら `None`
- 次の `if image is None:` は「読めなかったら止める」おまじないです

### 5-2. 初期マスクを作る

`np.full((h, w), cv.GC_PR_BGD, np.uint8)`

- 引数1 ` (h, w)` : 作りたい表の大きさ。高さ・幅の順
- 引数2 `GC_PR_BGD` : 中身を全部この数字で埋める
- 引数3 `np.uint8` : 0〜255の小さな整数型にする。画像用のお約束です

### 5-3. GrabCutで板を探す

`cv.grabCut(image, mask, (0, 0, 1, 1), background, foreground, 5, cv.GC_INIT_WITH_MASK)`

GrabCutは「色の似たものを集めて、前景と背景を分ける」命令です。引数は7個で順番が決まっています。

| 順番 | 引数 | 今回の値 | 意味 |
| --- | --- | --- | --- |
| 1 | `img` | `image` | 元の写真 |
| 2 | `mask` | `mask` | 入力兼出力。前章の付箋を入れて渡すと、実行後に答えに書き換えられて返ってくる |
| 3 | `rect` | `(0, 0, 1, 1)` | 四角の指定 `(x, y, 幅, 高さ)`。今回は使わないが省略できないのでダミーを入れる |
| 4 | `bgdModel` | `np.zeros((1, 65), np.float64)` | 背景の色の傾向を覚えるメモ帳。大きさは `(1, 65)` で固定。中身は空で渡す |
| 5 | `fgdModel` | 同上 | 板の色の傾向を覚えるメモ帳 |
| 6 | `iterCount` | `5` | 何回繰り返してきれいにするか。大きいほど丁寧だが遅い |
| 7 | `mode` | `GC_INIT_WITH_MASK` | マスクを使って始めるという合図 |

`rect` のダミーについて:

- `GC_INIT_WITH_MASK` の時は `rect` は無視されます
- それでもPythonの決まり上、引数自体は省略できません
- 型チェック用の定義書(型スタブ)でも必須になっています
- だから動作に影響しない `(0, 0, 1, 1)` という1ピクセルの四角を入れています

`background` の `(1, 65)` について:

- `65 = 5つのグループ × (重み1 + 平均の色3 + 広がり9)` という内訳です
- 覚える必要はありません。「お約束の大きさの空メモ帳」と思ってください

取りうる別の値:

- `mode` に `GC_INIT_WITH_RECT` を入れると、マスクではなく `rect` の四角を使って始めます
- `iterCount` は `1` だと速いが雑、`10` だと遅いが丁寧になります

### 5-4. 答えを白黒画像にする

`np.isin(mask, (cv.GC_FGD, cv.GC_PR_FGD)).astype(np.uint8) * 255`

- `np.isin(mask, (...))` : マスクが1か3なら `True`、それ以外は `False`
- `.astype(np.uint8)` : `True/False` を `1/0` に変える
- `* 255` : `1/0` を `255/0` に変える。つまり「板=白255、背景=黒0」にする

### 5-5. 一番大きい塊を選ぶ

`cv.findContours(mask, cv.RETR_EXTERNAL, cv.CHAIN_APPROX_SIMPLE)`

- 引数1: 白黒画像
- 引数2 `RETR_EXTERNAL` : 一番外側の輪郭だけ取る。他には `RETR_LIST`(全部取る)などがある
- 引数3 `CHAIN_APPROX_SIMPLE` : 輪郭の点を間引いて軽くする。他には `CHAIN_APPROX_NONE`(間引かない)がある
- 返り値1 `contours` : 輪郭のリスト
- 返り値2 `_` : 使わない情報なので `_` という名前で捨てる

`largest = max(contours, key=cv.contourArea)`

- `cv.contourArea(輪郭)` は面積を返す
- `max(..., key=...)` で「面積が最大の輪郭」を1つ選ぶ
- 小さなゴミを無視するコツです

### 5-6. 赤で描いて保存する

`cv.drawContours(result, [largest], -1, (0, 0, 255), 2)`

| 引数 | 値 | 意味 |
| --- | --- | --- |
| 画像 | `result` | 描く相手 |
| 輪郭 | `[largest]` | 描きたい輪郭のリスト。1個でもリストに入れる |
| 番号 | `-1` | -1は「全部描く」。今回は1個しかないのでその1個 |
| 色 | `(0, 0, 255)` | BGRの順なので赤になる |
| 太さ | `2` | 線の太さ。`-1` にすると塗りつぶしになる |

`cv.imwrite("result_03.png", result)`

- 引数1: 保存名、引数2: 画像
- 成功すると `True` を返すが、ここでは確認していません

## 6. `ex04_side_edges.py` の流れ: `ex03` との違いだけ説明します

### 6-1. 半分に縮小する

`small = cv.resize(image, None, fx=0.5, fy=0.5, interpolation=cv.INTER_AREA)`

- `None` : 出力サイズを直接指定しないという合図。代わりに `fx, fy` で倍率指定する
- `fx=0.5, fy=0.5` : 横・縦を0.5倍にする
- `interpolation` : 縮め方の種類
  - `INTER_AREA` : 縮小に向いている。平均を取る感じできれい
  - `INTER_NEAREST` : 一番近い画素をそのまま使う。白黒マスクを拡大する時に使う(中間のグレーを作らないため)
  - `INTER_LINEAR` : 普通の拡大縮小。写真向き

`sh, sw = small.shape[:2]` で縮小後の高さ・幅を取り直します。
この後のマスク作りとGrabCutは縮小画像 `small` に対して行います。速いのはこのためです。

### 6-2. マスクを元に戻す

`mask = cv.resize(mask, (w, h), interpolation=cv.INTER_NEAREST)`

- 第2引数 `(w, h)` は幅・高さの順です。`shape` と逆なので注意してください
- 白黒マスクなので `INTER_NEAREST` を使います。`INTER_AREA` や `INTER_LINEAR` だと白と黒の中間の灰色が生まれて後の処理が壊れます

### 6-3. 最大領域を塗りつぶす

```python
mask = np.zeros((h, w), np.uint8)
cv.drawContours(mask, [largest], -1, 255, thickness=-1)
```

- 真っ黒な表を用意して、そこに最大輪郭を白で塗りつぶします
- 色が数字1個の `255` なのは、相手が白黒画像だからです。カラーなら `(255, 255, 255)` ではありません
- `thickness=-1` が「塗りつぶし」の合図です
- `ex03` が「赤い縁を描く」だったのに対し、ここでは「次の行ごとの調査用のきれいな白地図」を作っています

### 6-4. 各行の左端と右端を探す

```python
for y in range(h):
    xs = np.where(mask[y] > 0)[0]
    if len(xs) == 0:
        continue
    left_points.append([int(xs[0]), y])
    right_points.append([int(xs[-1]), y])
```

- `mask[y]` は上から `y` 行目の横1列です
- `mask[y] > 0` は「白かどうか」の `True/False` の列になります
- `np.where(...)[0]` は「`True` だった場所の番号のリスト」を返します。つまり白い画素のx座標一覧です
- `len(xs) == 0` は「その行に白が1つも無い」=「板が無い行」なので飛ばします
- `xs[0]` が一番左、`xs[-1]` が一番右です。`[-1]` は「最後の1個」という意味です
- `[x, y]` の順で保存します。OpenCVの点は `(x, y)` の順だからです

### 6-5. 左右のふちだけ線で結ぶ

`cv.polylines(result, [np.array(left_points, dtype=np.int32)], isClosed=False, color=(0, 0, 255), thickness=2)`

| 引数 | 値 | 意味 |
| --- | --- | --- |
| 画像 | `result` | 描く相手 |
| 点列 | `[np.array(...)]` | 線で結びたい点のリスト。`numpy` の整数配列にする。外側の `[ ]` が必要 |
| `isClosed` | `False` | `True` だと一周して閉じる。左右のふちは開いた線なので `False` |
| `color` | `(0, 0, 255)` | 赤 |
| `thickness` | `2` | 太さ |

`np.array(left_points, dtype=np.int32)` は「PythonのリストをOpenCVが読める整数配列に変える」作業です。

`if left_points:` は「点が1つも無いのに描こうとしてエラーになるのを防ぐ」保険です。

## 7. `ex05_side_lengths.py` の流れ: 左右の長さを測る

`ex05` は画像の読み込みからGrabCut、左右の点列の作成までを自分で行います。
`ex03` や `ex04` を先に動かす必要はありません。

### 7-1. 点列の長さを測る

```python
left_edge = np.array(left_points, dtype=np.int32)
right_edge = np.array(right_points, dtype=np.int32)
left_length = cv.arcLength(left_edge, closed=False)
right_length = cv.arcLength(right_edge, closed=False)
total_length = left_length + right_length
```

`cv.arcLength` は隣り合う点どうしの距離を全部足します。
例えば `(10, 0)` → `(13, 4)` の距離は `sqrt(3² + 4²) = 5 px` です。
単なる高さや、最初と最後を直線で結んだ距離ではなく、凹凸に沿った線の長さになります。

`closed=False` は「最後の点から最初の点へ戻る線を足さない」という指定です。
左と右を別々に測るので、両側を横につなぐ上辺・下辺も入りません。
描画にも `isClosed=False` を使い、測る線と描く線を一致させています。

### 7-2. 数値を保存する

- `result_05.png`: 左をオレンジ、右を水色で描き、左上に `Left` / `Right` / `Total` の数値を表示
- `result_05.csv`: `edge,length_px` の2列で、`left` / `right` / `total` の3行を保存
- ターミナル: 同じ3つの長さを小数点以下2桁で表示

座標は元画像の大きさに戻した後のものなので、数値も元画像上の **px（ピクセル）** です。
mm が必要なら、既知の長さの基準物などから換算率を求めて、
`長さpx × 1 px あたりのmm` で変換します。

### 7-3. この計測で拾う形

`ex04` と同じく、各行の「一番左」と「一番右」を結ぶ方法です。
同じ行に複数の境界がある折り返した裂け目では、最外側の端だけを拾います。
また、半分に縮小すると細かな凹凸が消え、マスクの拡大でできる階段も長さに影響します。
この数値は、抽出して画像に描いた線の長さとして比較に使ってください。
画像の上下で切れている部分の、画面外の長さは含みません。

## 8. `ex06_mask.py`: 数値を変えてマスクだけを試す

このコードは「画像を読む → 初期範囲を作る → GrabCut → 画像を保存する」だけです。
他のスクリプトを読み込まず、GUIやコマンドライン引数も使いません。

### 8-1. 先頭の4つの数値を変える

```python
LEFT = 0.30
RIGHT = 0.75
TOP = 0.00
BOTTOM = 1.00
```

数字はピクセル数ではなく、画像の幅・高さに対する割合です。

- `LEFT = 0.30`: 左から幅の30%の位置で始める
- `RIGHT = 0.75`: 左から幅の75%の位置で終える
- `TOP = 0.00`: 上端から始める
- `BOTTOM = 1.00`: 下端まで使う

`0 <= LEFT < RIGHT <= 1`、`0 <= TOP < BOTTOM <= 1` の範囲で指定してください。
板全体と少しの周囲が矩形の中に入り、矩形の外には背景が残るようにします。
画像全体を候補にすると、背景の色を学習できません。

縦長・横長の画像はそのまま読み込めます。`h, w` を画像から求めるため、画像サイズの設定は不要です。
板が横向きに写る場合も、上下の割合で範囲を指定できます。例えば次のようにします。

```python
LEFT = 0.00
RIGHT = 1.00
TOP = 0.30
BOTTOM = 0.75
```

### 8-2. 初期マスクとGrabCut

`mask = np.zeros((sh, sw), np.uint8)` で、全体を0（確定背景）にします。
指定した矩形だけを3（`GC_PR_FGD`: 前景候補）に変えます。
矩形の中は「全部が板」と確定するわけではありません。GrabCutが板と背景を分けます。

今回の実験では、板の位置や幅を数値で指定します。
中央の決まった帯を確定前景にする指定、色による候補選び、輪郭の加工、長さ計測はありません。
処理後のマスクをそのまま保存するので、まず抽出の様子だけを見比べられます。

### 8-3. 実行して3枚を見る

```sh
uv run sandbox/ex06_mask.py
```

| 出力 | 内容 |
| --- | --- |
| `result_06_initial.png` | 初期の板候補の範囲だけを元画像から表示。範囲外は黒 |
| `result_06_mask.png` | 処理後のマスク。白が前景、黒が背景 |
| `result_06.png` | 抽出した部分だけを元画像から表示。背景は黒 |

`cv.bitwise_and(image, image, mask=mask)` は、白い場所の画素を残し、黒い場所を黒にします。
マスクを元画像サイズへ戻すときは `INTER_NEAREST` を使い、白黒の中間色を作りません。
出力3枚は元画像と同じ幅・高さです。

数値を変えてもう一度実行すると、同じ名前の画像を上書きします。
比較を残すときは、先頭の `OUTPUT_PREFIX` を `"result_06_a"`、`"result_06_b"` と変えてください。

- `INPUT_PATH`: 入力画像の名前
- `SCALE`: 処理時の倍率。`0.5` は半分、`1.0` は元の大きさ
- `ITERATIONS`: GrabCutの繰り返し回数。初期値は5

元画像、縦長にした画像、板が横向きになるよう90度回転した縦長画像で実行確認しました。
これは画像サイズ・向きに合わせて範囲を指定できることの確認です。
個々の撮影画像では、初期範囲を調整してマスクを目視で確認してください。

## 9. よくあるつまずき

- `image is None` を忘れる: ファイル名が違うと `None` になり、次の `shape` で落ちます
- `resize` の `(w, h)` と `shape` の `(h, w)` を混同する: `resize` だけ幅が先です
- 白黒マスクに `INTER_AREA` を使う: 灰色が混ざって `findContours` が変になります。拡大には `INTER_NEAREST` を使います
- `findContours` の返り値を間違える: OpenCVの版によって返り値の個数が違います。今の版は2個です
- `contours` が空で `max()` が落ちる: 板が見つからなかった時に起きます。今回は起きない前提にしています
- `rect` に `None` を渡す: 動くことがありますが型チェックで怒られます。`(0, 0, 1, 1)` を入れます
- 色が `(255, 0, 0)` で赤にならない: OpenCVはBGRの順なので、これは青です。赤は `(0, 0, 255)` です

## 10. ローラー反射の誤検知を比較する

`ex07`〜`ex10` は、添付されたAI生成画像 `input_ai.png` で方式の違いを試す独立スクリプトです。
実際の撮影画像や正解マスクはまだないため、数値で実画像の精度を評価することはできません。
入力は各スクリプトと同じフォルダ、出力はその中の `results/` を基準に読み書きします。
画像の縮小は行いません。カーネルや窓の大きさは、入力画像上のpx単位です。

### 10-1. ex07: 元方式の初期指定

`ex03` と同じ横方向の割合で初期指定します。
幅の48〜56%の縦帯を、上端から下端まで確実な前景にします。
その帯に背景や深い裂け目が入る画像では、GrabCutが背景へ戻せません。
最大連結領域を残しますが、そこにつながったローラーの反射は残ります。

### 10-2. ex08: 小さな前景とローラー背景を指定

まず `LEFT`、`TOP`、`RIGHT`、`BOTTOM` で試料全体を含む探索範囲を指定します。
範囲内は前景候補、範囲外は確実な背景です。
さらに `BACKGROUND_RECTS` と `FOREGROUND_RECTS` で小さな確定領域を指定します。
矩形の値は全て **左、上、右、下** の順で、0〜1の割合です。

```python
FOREGROUND_RECTS = (
    (0.49, 0.12, 0.55, 0.20),
    (0.49, 0.58, 0.55, 0.66),
    (0.49, 0.88, 0.55, 0.94),
)
BACKGROUND_RECTS = (
    (0.34, 0.0, 0.365, 1.0),
    (0.675, 0.0, 0.71, 1.0),
)
```

前景には、試料内部の異なる明るさの場所を少数指定します。
背景には、試料の左右に露出したローラーを指定し、明るい反射も背景として与えます。
この画像では試料が上下端まで続くため `TOP = 0.0`、`BOTTOM = 1.0` です。
試料の上下に余白がある画像では、その余白を背景にできるよう範囲を合わせてください。

適用順は探索範囲、確実な背景、確実な前景です。重複すると最後の指定が優先されます。
`_initial.png` で、緑が試料内部、青が背景に乗っていることを確認してください。
ローラーの高さの行全体を背景にすると、同じ行の試料も消えるので避けます。

`ex08`〜`ex10` は同じ初期指定をそれぞれ持っています。
公平な比較をするには、共通の位置指定、`ITERATIONS`、`RANDOM_SEED` を全て同じ値にします。
`ex07` の初期指定は元方式との比較用なので異なります。

### 10-3. ex09: 縦オープニング

初回GrabCutの最大連結領域に、幅1px、高さ `VERTICAL_SIZE` pxの縦長カーネルで
オープニングをかけます。縦に長い試料を残し、横に伸びた薄い部分を落とす狙いです。
その後、最大連結領域を選びます。輪郭を塗りつぶして穴を埋める処理は行いません。

添付画像では残る反射の縦方向の厚みが約30pxあるため、初期値は `41` にしています。
`17`、`31`、`41` のように1以上の奇数を比較し、反射を落とせる最小の値を探します。
`1` ならオープニングによる変更はありません。

この方法は本物の薄い突起も削ります。`_changes.png` の紫色には、本物の形状の変化も含まれます。
輪郭の長さを計測する場合、見た目が滑らかになったことだけで採用を決めないでください。
試料が横向きの場合、この縦方向の設定は適しません。

### 10-4. ex10: 反射候補だけを局所再判定

同じ初期GrabCutを行ってから、次の条件が全て重なる画素を候補にします。

1. 縦オープニングで消える細い部分である。
2. 左右端が、前後の行の中央値より外側へ急に張り出している。
3. 試料の外にあるローラー参照範囲でも、その高さに明るい反射帯が見える。
4. 候補の画素自身も明るく、確実な前景として指定した場所ではない。

縦オープニングは候補を探すためだけに使い、その結果を最終マスクにはしません。
また、左右端の中央値も判定の基準に使うだけで、全ての輪郭をその曲線へ置き換えません。

ローラー参照範囲の行ごとの明るさを取り、周辺の行より明るい行を反射帯とします。
左右いずれかの参照範囲に反射があれば帯として扱い、上下へ `BAND_MARGIN` px広げます。
参照範囲には試料や装置の支柱を含めないよう調整してください。

候補を `GC_BGD` に固定してGrabCutを再実行します。
ただし、再実行結果は候補から `REFINE_MARGIN` px以内、かつ張り出し側の反射帯にだけ反映します。
`_review_region.png` の黒い場所は初回の最大連結領域と同じままです。
候補が0画素の場合は再実行を省き、初回の結果をそのまま保存します。
局所変更後の穴や分離した領域は保存し、輪郭全体の塗りつぶし・平滑化・最大領域の再選択は行いません。

| パラメータ | 初期値 | 調整する意味 |
| --- | --- | --- |
| `VERTICAL_SIZE` | 41 | 細い部分を探す高さ。大きいほど本物の突起も候補に入りやすい |
| `EDGE_WINDOW` | 101 | 左右端の中央値を取る行数。反射が続く行数の2倍より大きい値が目安 |
| `MIN_EXTENSION` | 10 | 中央値から何px外へ張り出した行を調べるか |
| `EDGE_MARGIN` | 3 | 中央値から外側へ残す保護幅。`MIN_EXTENSION` より小さくする |
| `ROLLER_LEFT` / `ROLLER_RIGHT` | `(0.25, 0.35)` / `(0.70, 0.84)` | 露出したローラーの左右の参照範囲。横位置の割合 |
| `PROFILE_WINDOW` | 81 | 反射帯の周辺の明るさを調べる行数 |
| `MIN_ROLLER_CONTRAST` | 14 | 周辺の行よりどれだけ明るければ反射帯とするか。明るさは0〜255 |
| `MIN_BRIGHTNESS` | 150 | 反射帯と候補画素に必要な最低の明るさ。0〜255 |
| `BAND_MARGIN` | 5 | 反射帯を上下へ広げるpx数 |
| `REFINE_MARGIN` | 7 | 候補の近傍で再判定結果を反映する最大の距離 |
| `REFINE_ITERATIONS` | 3 | 2回目のGrabCutの反復数 |

先に `_bands.png` で反射の高さが拾えているか、次に `_candidate_overlay.png` で
紫の候補がローラー上に乗っているか確認します。
最後に `_changes.png` の紫（除去）・緑（追加）と元画像を比較します。
本物の突起が反射帯に重なると、この方法でも誤除去することがあります。
短い本物の突起と反射が同じ形状・明るさなら、この1枚だけでは確実に識別できません。
