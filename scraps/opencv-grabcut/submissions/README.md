# 現行の実行順

2026-10-16、床置きの局所写真から左右側辺長を比較するPoCに使う6本へ整理しました。
同じ材料区間の追跡を必須にせず、実測長と100mmあたりの側辺長を比べます。
板作成・カメラ校正・補正・計測の4本と、比較GUIの2本があります。
比較は厚さなしの局所版か、実測厚さと累積圧下率も使う厚さ版を選びます。
`00_1`・`00_2` は初回準備、`01`～`03` は撮影後に使う番号です。同じ番号の比較GUIは用途に応じて選びます。
各ファイルに設定・入力・処理・保存を書き、校正とレンズ歪み補正にはOpenCV魚眼モデルを使います。
自作モジュールや一括実行スクリプトは使わず、画像とCSVで結果を渡します。

## コードと運用の共通方針

6本は引き続き単独で使います。共通モジュールは追加せず、同じ処理の名前と書き方を揃えています。
パスは `script_directory`・`input_path`・`output_path`、カメラ係数は `camera_matrix`・`dist_coeffs`、
長さの倍率は `mm_per_px`、表示の倍率は `display_scale` として区別します。
画像は `Path.read_bytes()` → `np.frombuffer()` → `cv.imdecode()` で読み、
PNGは `cv.imencode()` → `Path.write_bytes()` で保存します。日本語のパスも同じ方法で扱います。
全スクリプトは `main()` から実行します。

通常のステータスは「計測完了」「比較: N件」「保存: ファイル名」に揃えています。
計測後は赤い側辺と黄色の区間を確認し、比較ではCSVの追加順と区間長を確認します。
厚さが未入力の場合は、入力が必要な項目を表示します。

入力形式・数値・計測区間・抽出結果・補正の成立条件と、入力を上書きしないためのチェックは残します。
CLIは失敗したところで停止し、GUIは入力・計測・保存の操作で起きるエラーを表示します。
失敗した画像の自動除外、再試行、保存の巻き戻しは行いません。
撮影条件・板の寸法・倍率を揃えること、入力名の整理、実行前の出力の退避は運用で行います。
保存先フォルダは保存時に作ります。保存に失敗した場合はCSV・PNGの両方を確認し、原因を直して保存し直します。

## 00_1. 板を作る（初回準備）

ChArUco板は横7・縦5マス、1マス30mm、マーカー18mm、辞書 `DICT_4X4_50` です。
`output/charuco_board.png` を保存します。板本体210×150mm、余白込み230×170mmです。

印刷時は自動縮小を避け、実物の1マスが30mmであることを測って確認します。
寸法を変える場合は、板生成・カメラ校正・画像補正の3本の設定を同じ仕様へ手で揃えます。

## 00_2. カメラ係数を求めて貼る（初回準備）

同じ撮影モード・画角・解像度で、板の位置・傾き・距離を変えた写真を10枚以上用意します。
魚眼の歪みが残った画像を使います。中央だけでなく上下左右の周辺にも板を写し、ピントと角の読取りを確認します。
既定の保存場所は `submissions/input/camera_calibration/` です。
板の角を縦横に6点以上読める写真を使います。

処理した写真ごとに、元写真へ読取結果を重ねた確認PNGを `output/camera_detection/` へ保存します。
例えば `shot1.jpg` の確認画像は `shot1.jpg_detected.png` です。元の拡張子も名前に残すため、PNGとJPEGが混在しても区別できます。
緑の枠は読めたマーカー、赤い点と番号はChArUcoの角とID、左上は `OK` / `NG` と読取点数です。
`OK` は角が6点以上あり一直線に並んでいないという意味で、校正や実寸精度の合格表示ではありません。
点とIDが板の正しい位置に付いているか、画像を開いて確認します。
写真が10枚未満でも、読取確認PNGを保存してから枚数不足で止まります。

`00_2_calibrate_camera.py` の表示から、次の3設定を `01_rectify_images.py` の冒頭へコピペします。

```python
CALIBRATION_SIZE = ...
CAMERA_MATRIX = ...
DIST_COEFFS = ...
```

設定ファイルの保存・自動読込はありません。
校正にはOpenCV 5の `cv.fisheye.calibrate()` を使います。
`DIST_COEFFS` は魚眼モデルの `k1, k2, k3, k4` の4個です。
通常モデルの `k1, k2, p1, p2, k3` とは意味が異なり、以前の係数は使えません。写真から校正し直し、3設定をまとめて貼り直します。
固定したカメラ・撮影条件で係数を使い続け、モード・画角・解像度・電子補正などを変えたら校正し直す運用です。
現在の係数は `None`。本番カメラの写真で求めるまで補正は実行できません。

`CALIB_CHECK_COND - Ill-conditioned matrix for input array N` は、該当する写真で、校正に使う姿勢を安定して求められなかったという意味です。
`N` は今回読み込んだ順の0始まりの番号です。スクリプトがその値から、1始まりの通し番号・元のファイル名・確認PNGの場所を表示します。
特定の枚数やファイル名には固定しません。入力写真を移動・追加して再実行した場合も、その実行の読込順から写真を特定します。
確認PNGの `OK` は角の読取条件を満たした表示であり、この校正計算の成功を表してはいません。
停止した写真の確認PNGを開き、板が小さすぎないか、極端な傾きや誤った角の検出がないかを確認します。
その写真をいったん入力フォルダ外へ移すか撮り直し、残りが10枚以上ある状態で再実行します。板の位置・傾き・大きさに変化をつけ、点とIDが正しく付く写真を使います。
このエラーだけで写真そのものの欠陥と断定はできません。ほかの写真でも続く場合は、撮影モード・画角を揃え、板が十分大きく写る写真を撮り直します。
エラー時には係数を表示せず停止します。写真の除外と再実行は運用で行います。
番号と条件数確認の仕様は [OpenCVの実装](https://github.com/opencv/opencv/blob/5.0.0/modules/calib/src/fisheye.cpp) と [魚眼校正API](https://docs.opencv.org/5.0/main_modules/calib3d_fisheye.html) に基づきます。

## 01. フォルダの写真を一括補正する

板を試料の計測面と同じ高さ・同じ平面に置きます。
板の位置・写真内での向きは任意ですが、試料を隠さず、角を縦横に6点以上読めるようにします。
写真で見えていた向きを保つため、**試料の長手方向は撮影時に画像の縦方向へ揃えます**。計測GUIは開始y・終了yで区間を選びます。

`01_rectify_images.py` の冒頭でフォルダを指定して実行します。

```python
INPUT_DIRECTORY = "input"
OUTPUT_DIRECTORY = "output/rectified"
```

入力フォルダ直下のPNG・JPEG・BMP・TIFFを名前順に処理します。サブフォルダは読みません。
固定した魚眼係数でレンズ歪みを補正し、板から求める平面の遠近補正を行います。
`cv.fisheye.estimateNewCameraMatrixForUndistortRectify()` の `balance=1.0` で周辺をなるべく残す画角を求め、
`cv.fisheye.undistortImage()` で補正します。補正後も試料と板が写っていることを確認します。
入力の拡張子を `.png` へ変えた同じ名前で出力します。例えば `shot1.jpg` は `output/rectified/shot1.png` です。
同名・異なる拡張子の入力は出力名が重なるため、実行前に名前を変えます。

保存するのは計測用の補正PNGだけです。読取確認PNGや `detected/` フォルダは作りません。
以前に作った確認画像が残っている場合は、実行前の出力整理で退避・削除します。
向きの基準は、魚眼補正後の画像で板の中央の横軸が写る方向です。その方向を補正後も保ち、板の座標へ向きを揃える回転を防ぎます。
板が横向き・逆向きでも、その配置を理由に写真全体の向きを変えません。遠近補正による形状の変化や、余白・出力サイズの変化はあります。

板を読めない画像・破損画像・保存失敗では、その場でエラー終了します。後ろの画像には進みません。
補正側では失敗時も確認PNGを作りません。エラーと元写真を見て入力を撮り直すか入力フォルダから外し、再実行してください。
カメラ校正側の読取確認PNGと、画像を読めた場合にNG画像を保存して停止する動作は維持しています。
停止する前に保存した結果と、前回の出力は残ります。混同を避けるため、実行前に出力を退避するか空にします。
画像名・保存先・撮影条件を揃え、出力確認と失敗後のやり直しは運用で行います。
入力フォルダと出力フォルダは別にします。同名の正常な出力は再実行時に上書きする運用です。

補正画像は全撮影を `MM_PER_PX = 0.25`、つまり4px/mmへ揃えます。
計測GUIの冒頭にも**同じ `MM_PER_PX`** を置きます。倍率はGUIには表示しません。
換算係数CSVや別のCSV換算スクリプトは使いません。
補正画像と倍率の対応、写真ごとの保存先は運用で確認します。

この平面補正では、試料の反りや板との高さの違いは補正できません。
魚眼モデルに固定し、通常モデルへの切り替えは設けません。
Linearなどで既に歪み補正された画像や、撮影ごとに画角が変わる電子補正の画像は前提にしません。
撮影条件を固定して校正し、板に使わない既知寸法を中央・周辺で確認します。
補正後に黒い余白や周辺の欠けが出る場合があります。補正範囲が大きすぎる場合は安全のため保存を止めるので、撮影距離・角度・固定倍率を見直します。
魚眼モデルの仕様は [OpenCV公式ドキュメント](https://docs.opencv.org/5.0/main_modules/calib3d_fisheye.html) を参照してください。

## 02. 計測GUIで長さCSVを作る

`02_measure_edge_lengths_gui.py` で、上部から**補正済みPNG**を読み込み、左サイドバーと右の画像で操作します。
画像選択は `output/rectified` から始まります。
ファイル名とサイズだけを表示し、エラー・ステータスは読み込みボタンの右端へ表示します。

1. 前景候補の矩形で試料を囲む。板・床・黒い余白は候補の外へ置く。
2. 必要なら確実な背景・確実な前景を矩形で指定する。確実な前景には床を含めない。
3. 計測する区間の開始y・終了yを入力する。黄色い横線と「区間長」のmm表示で、測る範囲を確認する。両端の行を含む。
4. 「長さを計測」で抽出し、赤い左右側辺と黄色の区間を確認する。
5. 「CSV・確認PNGを保存」で、その計測のCSVと確認画像を一度に保存する。

左・右・左右合計は長さ(mm)の表に数値を右揃えで表示します。
保存ダイアログは `output` から始まり、既定の名前は `<画像名>_lengths.csv` と `<画像名>_lengths.png` です。
CSVの保存名を決めると、同じ名前のPNGも保存します。どちらかが既にある場合は、一度の確認で上書きするか選びます。
同じ画像で別の区間を測った場合は、`p01_a`・`p01_b` など別の保存名を付けます。
「確認画像を保存」では、従来どおり計測前の初期指定や計測後の画像だけを別途保存できます。

開始y・終了yの入力値を変えると、対応する黄色の横線と行番号がすぐにプレビューへ反映されます。
横線は計測前から表示し、元画像の表示やウィンドウサイズの変更にも追従します。
空欄・整数以外・画像範囲外の値は、その端の横線を表示しません。
開始・終了の組が有効なときだけ区間長をmmで表示し、不正な範囲では「—」に戻します。
目印を確認しづらい場合は、左下の「元画像」を選んで調整できます。

区間の全行に試料が必要です。試料がない行を指定した場合は、区間か初期指定を直します。
矩形・区間・画像を変えたら結果を無効にし、計測し直してからCSVを保存します。
確認画像は計測後なら側辺と区間、計測前なら初期指定を保存します。

GrabCut 5回・乱数シード0で抽出し、最大の外側輪郭を塗りつぶします。
各y行の最左・最右を隣接行へつないで長さを求め、上下辺は加えません。
側辺の凹凸と画素の段差も長さへ入るため、直線の区間長と同じ値になるとは限りません。

CSVはUTF-8 BOM付き、1回の計測につき1行です。列は従来と同じです。

```text
image_path,image_width,image_height,mm_per_px,start_y,end_y,
left_px,left_mm,right_px,right_mm,total_px,total_mm
```

実際のヘッダーは1行です。左右と合計のpx・mm値を保存し、比較側が読み込みます。
GUIで未補正画像や違う倍率の画像を判定する仕組みはありません。読み込む画像を確認してください。
局所画像でも左右両側辺を写します。片側が画面外へ切れた画像では、画像の切れ目を側辺として測る場合があります。

## 03. 局所区間の左右長さを比較する

```powershell
uv run submissions/03_compare_edge_lengths_gui.py
```

1. 「CSVを追加」で、計測GUIから保存した長さCSVを比較したい順に追加する。
2. 自動表示される表で、CSV名・区間長・左右側辺長を確認する。
3. 「実測長」「100mm換算」でグラフを切り替える。左右の長さと、灰色の破線「基準（直線の目安）」を表示する。表は実測値のまま表示する。
4. 不要なCSVは表で選び、「選択したCSVを削除」を押す。複数選択もできる。
5. 「グラフを保存」で、表示中のグラフをPNGに保存する。

初期長さ・厚さ・理想長は入力しません。既存CSVの開始・終了yと倍率を使います。

```text
区間長(mm) = (end_y − start_y) × mm_per_px
100mmあたりの側辺長(mm) = 側辺長(mm) ÷ 区間長(mm) × 100
```

区間長は両端の画素中心の間隔なので、行数の「+1」は加えません。
区間100mm・側辺104mmと、区間200mm・側辺208mmは、100mm換算ではどちらも104mmです。
換算は区間長に対して側辺がどれくらい長いかを見るもので、傾き・曲がり・抽出の揺れも含みます。
基準線は、実測長では各CSVの区間長、100mm換算では100mmの水平線です。
画面と保存PNGの両方へ表示します。厚さから予測した伸びの理想値とは別の目安です。

横軸はCSV名・追加順で、左右それぞれの点を線で結びます。追加した順をパス番号へ自動変換しません。
同じパスの複数箇所は `p01_a_lengths.csv`・`p01_b_lengths.csv` などで区別できます。
複数選択時の順序はダイアログの返す順です。順番を確実に指定する場合は1件ずつ追加します。
同じCSVの追加は重複させず、異なるCSVなら同じ画像の別区間も比較できます。

既定の保存名はグラフが `length_comparison_local.png`、
100mm換算のグラフが `length_comparison_local_100mm.png` です。
比較CSVは出力しません。計測元のCSVは引き続き入力に使います。

比較時には画像を読み直しません。確認PNGは別に開いてグラフと照合できます。
CSVの追加・削除で表とグラフを自動更新します。入力CSVを外部で直した場合は、そのCSVを外して追加し直します。
読込みに失敗したCSVは追加しません。比較全体の読込みに失敗した場合は古い結果を消し、保存を無効にします。
入力CSV・補正画像への上書きは止めます。計測CSVの形式を変える必要はありません。

uv run python -m unittest discover -s tests -p test_length_comparison_local_gui.py
uv run tests/verify_length_comparison_local_gui.py --out tests/results/local_comparison_new

## 03（厚さあり）. 厚さと累積圧下率を使って比較する

`03_compare_edge_lengths_with_thickness_gui.py` は、局所比較GUIと同じ計測CSVを使う独立した別スクリプトです。
初期厚さと各撮影の実測厚さを入力し、厚さの減少と左右側辺長の関係を確認します。

```powershell
uv run submissions/03_compare_edge_lengths_with_thickness_gui.py
```

1. 「CSVを追加」で、計測GUIから保存した長さCSVを比較したい順に追加する。
2. 「初期厚さ (mm)」と、各CSVの行の「厚さ (mm)」へ数値を入力する。
3. 入力が揃うと、各行の区間長・左右実測長・累積圧下率とグラフが自動表示される。
4. グラフの実測長／100mm換算、横軸の撮影順／累積圧下率を切り替える。
5. 「グラフを保存」で表示中のグラフをPNGに保存する。不要なCSVは行の「削除」で外す。

```text
累積圧下率(%) = (初期厚さ − 現在の厚さ) ÷ 初期厚さ × 100
```

初期厚さ10mmなら、厚さ10・8・6mmに対する累積圧下率は0・20・40%です。
初期長さや理想伸びは計算しません。区間長・左右長さ・100mm換算の定義は局所比較GUIと同じです。
同じパスの複数箇所に同じ代表厚さを入力しても比較できます。区間近くの実測値かパス代表値かは撮影記録へ残します。
現在の厚さが初期厚さを上回った場合は、計算結果を負の圧下率として表示します。

撮影順の横軸ではCSV名を、累積圧下率の横軸では数値の位置を使います。
どちらもCSV追加順に点を線で結びます。同じ圧下率の点は縦に結ばれ、圧下率が前後する追加順では線も折り返します。
線は採取した区間の違いを見比べる目安で、同じ材料区間を追跡した変化ではありません。撮影順に1件ずつ追加すると順番を確実に指定できます。
100mm換算の基準は100mmの灰色破線です。実測長の基準は各CSVの区間長を灰色の破線で結びます。
各行の区間長と左右側辺長は、グラフのモードにかかわらず実測値を表示します。

初期厚さ・各行の厚さ・CSVの追加や削除に合わせて自動で再計算します。
空欄・不正値・CSVの読込失敗時は古いグラフ・計算値を消し、入力を直すと再表示します。
入力CSVと補正画像は変更しません。厚さはこのGUIで入力するため、既存の計測CSV形式はそのまま使えます。
厚さの入力値は終了時に保存されません。撮影記録にも値を残してください。

比較CSVは出力せず、表示中の軸と長さモードのグラフをPNGにします。
既定名は `length_comparison_thickness.png` で、累積圧下率の横軸では `_reduction`、100mm換算では `_100mm` が付きます。
例えば両方を切り替えた場合は `length_comparison_thickness_reduction_100mm.png` です。
