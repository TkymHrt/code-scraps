# 提出用

段階ごとの成果を、短く読めるスクリプトで提出する場所です。
既存コードは参考として残し、提出版は必要な処理だけで1本ずつ作ります。
ここでは、再現性・設定調整・入力の選定を運用で扱う方針を優先します。
既存の工程表にある記録項目を、提出コードの必須機能にはしません。

## コードの形

- 1つの成果につき1スクリプト。設定・読み込み・処理・保存を上から読めるようにする。
- 入力・保存先・調整する数値は冒頭に置き、必要なときに人が編集する。
- 小さな関数と短い重複は許容し、自作の共通モジュールには依存させない。
- 実行条件JSON、設定管理、実行履歴、自動バックアップや復旧処理は足さない。
- 入力が読めない、計測が成立しない場合など、誤った数値を出さないためのチェックだけ残す。

結果画像と、定量評価そのものに必要なCSVを保存します。
撮影条件を揃える、設定を合わせる、出力を見て確認する、必要な結果を残すことは人が行います。
同じ保存先への上書きは、実行前に確認します。

## 最初に作るもの

| 順番 | その1本の成果 |
| --- | --- |
| 1 | GrabCut直後の2値マスク画像 |
| 2 | 左右端の重ね画像と座標CSV |
| 3 | 左右側辺の長さのCSV |
| 4 | 行ごとの幅のCSV |

完成した段階だけに番号を付けて追加します。未実装のスクリプトや空の段階フォルダは作りません。
各スクリプトは元画像から単独で動かし、前段階の実行を必須にしません。
人の指定あり・追加指定なしの比較は、それぞれ別の成果として必要なときに用意します。

## 提出と確認

提出は、スクリプト・成果画像またはCSV・何ができたかの短い説明で十分です。
既知の形状や元画像で結果を確認します。検証のための処理を提出コードへ組み込みません。
依存ライブラリは題材の既存環境を使い、必要ならスクリプト1本をコピーして実行できます。
入力画像と生成結果はGit管理対象外です。

現在は方針と置き場を用意した段階で、提出用の実行コードはまだありません。
