# 画像補正・側辺計測・比較の実行スクリプト

旧版の `sandbox/submissions/` の6本を元に、複数のスクリプトで使う処理と設定を共通化しました。
1目的1スクリプトと実行順、入力・計算・保存の機能を維持しています。
GUIは `02` を基準に「上部＝入力と状態、左＝操作、右＝画像・表・グラフ」へ揃えました。
実行スクリプトと共通設定は `src/` 直下、補助モジュールは `src/utils/` に置いています。
この版の計測GUIは、多角形による初期指定と、試料の長手軸に直角な断面を使う計測へ更新しています。
旧版の矩形・水平区間による計測は変更していません。
成果物はこの `src/` 一式です。[発表原稿とPython・Excelでのグラフ作成手順](../PRESENTATION.md) も参照してください。

## 共通化の判断

- **入出力先**：`workflow_settings.py` を変更すると全工程が同じ基準に従います。`01` の補正画像の出力先と、`02` の読込開始先は同じ `RECTIFIED_DIRECTORY` です。
- **画像の読込・保存**：日本語パスへの対応、PNG変換の成否確認、保存フォルダの作成を `utils/file_io.py` にまとめました。画像・CSV・グラフの保存先の拡張子と入力保護にも、同じ確認処理を使います。
- **CSVとグラフ**：CSVの書込と読込を `utils/measurement_csv.py` へ集め、列名・文字コード・数値の扱いを同じ場所で読めるようにしました。比較順とグラフは `utils/length_comparison.py` にあります。
- **GUIの枠とファイル操作**：画面の3領域、CSV選択・重複除外・事前検証、PNG保存先の選択、グラフの破棄・再配置を `utils/gui_parts.py` にまとめました。
- **個別の計算とGUI操作**：補正、GrabCut、側辺長、累積圧下率の計算は担当するスクリプトに残しました。ボタンと計算のつながりや、GUIごとの状態は同じファイルで追えます。

共通化は現在の重複を減らせる箇所に限りました。
板を作る数行の処理やGUIの短い重複は残し、継承クラス・一括実行・設定ファイルの自動読込は追加していません。
例えば `02` のGrabCutから長さ計算までを別モジュールへ分けても、現在は利用元が1本だけです。
今回は計算の順序を同じファイルで追えることを優先しました。

### 読み進める順序

1. 使う実行スクリプトの先頭で、入力・出力・importしている共通処理を確認する。
2. CLIは `main()`、GUIは `main()` 内のボタンの処理から、入力→計算→保存を追う。板生成も `main()` に揃え、読込時にはファイルを保存しない。
3. ファイル選択や画面構成は `utils/gui_parts.py`、画像操作は `utils/file_io.py`、CSVの受渡しは `utils/measurement_csv.py`、グラフは `utils/length_comparison.py` を読む。

例えば局所比較GUIでは、「CSVを追加」→ `choose_csv_paths()` で選択・事前確認 → `read_measurements()` で読込・換算 → `create_graph()` と `replace_graph()` で描画、という流れです。
厚さ版は `compare_lengths_with_thickness()` が同じ `read_measurements()` を使い、その結果へ厚さと累積圧下率を加えます。
自作モジュールを読む必要は増えますが、比較する2本に同じ検証コードを重ねて置かずに済みます。

処理の役割に合わせ、次の名前へ揃えています。

- 比較GUIの再計算・表の更新は両方とも `update_comparison()`。
- ファイルへ書く処理は `write_*`、ダイアログから保存するGUI操作は `save_*`。CSVとPNGを組で保存する操作は `save_measurement()`。
- 上部の操作領域は `header`、保存ボタンは `save_measurement_button`・`save_graph_button`。
- 厚さの文字入力は `initial_thickness_text`・`thickness_text`、数値は `initial_thickness_mm`・`thickness_mm`。

## GUIの配置と状態

| 領域 | 計測GUI | 局所比較GUI | 厚さ付き比較GUI |
| --- | --- | --- | --- |
| 上部 | 画像読込・ファイル情報・状態 | CSV追加・件数・状態 | CSV追加・件数・状態 |
| 左側 | 多角形・区間・軸・計測・結果・保存 | 表示切替・選択CSVの削除・保存 | 初期厚さ・表示切替・横軸・保存 |
| 右側 | 画像と計測区間・側辺 | CSV一覧とグラフ | 撮影ごとの厚さ入力・計測値とグラフ |

`02` は計測ボタンで計算し、比較GUIは入力の変更に合わせて自動更新します。
厚さ版の表は上下・左右にスクロールでき、狭い画面でも全列と各行の削除ボタンを操作できます。
最小サイズは計測が1000×760、比較が960×640で、各画面の用途に合わせて維持しています。

結果を消す処理は各GUI内の `clear_results()` に揃えました。状態管理全体を別モジュールには移していません。
選択ダイアログを取り消した場合や、新しいファイルを受け付けられない場合は、現在の有効な入力・結果を保ちます。
使用中の入力や条件を変えた場合は古い結果を無効にし、計算に成功してから保存を有効にします。
CSVの追加は選択した全件を確認してから行い、途中の1件で失敗した場合はその選択全体を追加しません。
比較時はCSVを読み直すため、追加後にCSVが変更・削除された場合の検出も維持しています。

比較が成功したときの説明文や件数の重複表示は出しません。件数は上部、追加順は表の見出しで確認できます。
ステータスは `計測中…`・`計測完了`・`保存: ファイル名`、必要な入力の不足、失敗の理由に絞っています。
空画像や読めないCSVは、OpenCVやOSの詳細文をそのままGUIへ表示せず、対象ファイル名を付けた短いエラーにします。

計測の「CSV・画像2枚を保存」でCSV名を選ぶと、計測CSV・初期指定PNG・計測結果PNGをまとめて保存します。
例えば `shot_lengths.csv` を選ぶと、多角形の色を重ねた `shot_lengths_initial.png` と、
側辺・長手軸・上下断面を重ねた `shot_lengths.png` を元の解像度で保存します。画面の表示切替には依存しません。
既存の3ファイルは確認なしで上書きします。2枚ともPNGへ変換できることを確認してからCSVを書きます。
書込途中で失敗した場合には `保存失敗: CSV・PNGを確認してください` と表示し、部分的に保存されている可能性を知らせます。

### 多角形・計測区間・長手軸を指定する

操作は **多角形 → 基準区間長（mm）と区間の中心 → 自動軸 → 必要なら手動軸 → 計測 → 保存** の順です。
画像上の指定は「多角形」「区間の中心」「手動軸2点」から選びます。
指定と確定・取消はマウスと画面のボタンで行い、基準区間長は入力欄へ数値を入力します。
操作説明はこのREADMEへまとめ、GUIは操作名・設定値・状態・計測値を表示します。

1. 補正画像を読み込み、前景候補・確実な前景・確実な背景の種類を選ぶ。
   「多角形」を選び、画像を順にクリックして頂点を置き、「多角形を確定」で確定する。
   「描画を取消」で未確定の頂点を取り消せる。各種類を複数追加でき、一覧から削除できる。
   前景候補は、測る試料の両側辺と上下断面を余裕をもって含める。
2. 「基準区間長（mm）」へ正の長さを入力し、「区間の中心」を選んで試料の中心付近をクリックする。
   基準区間長は起動直後は空欄なので、比較する全パスで確保できる長さを決めて入力する。
   区間の中心から軸方向へ長さの半分ずつ離れた位置に、上下断面を置く。上下2点を個別に指定する操作は使わない。
3. 「試料抽出・軸を自動推定」を押す。選んだ区間内の複数断面で、最もDR側と最もOP側の輪郭交点の中点を求め、
   その中点群へ直線を当てはめる。内部の凹凸で交点が増えた断面も、両外側の交点から中点を求める。
   最初は画像の縦方向を仮の軸とし、3回の当てはめのたびに、指定した中心と基準区間長を保って上下断面を配置し直す。
   撮影時は従来どおり試料の長手をおおむね画像の縦方向へ揃える。
   表示された軸と上下断面が試料に合っていることを確認する。
4. 自動軸が適切でない場合は、「手動軸2点」を選び、試料の長手方向に離れた2点を順にクリックして上書きする。
   この2点は方向を決めるために使い、区間の中心と基準区間長は保つ。上下断面も手動軸に直角な向きへ変わる。
5. 「長さを計測」を押す。確定した軸に直角な2本の断面でDR・OP側辺を切り出し、平滑化して側辺長と超過率を求める。
   基準区間長は、この2断面の**軸方向の距離**で、入力した長さになる。画面の縦方向の差や側辺の端点間距離は使わない。
6. 側辺・軸・断面を確認し、CSVと確認PNGを保存する。

「試料抽出・軸を自動推定」では輪郭と軸を求めます。DR・OPの最終的な側辺長と超過率は「長さを計測」で求めます。
抽出後に中心や基準区間長を変更すると、抽出済みの輪郭の区間内の中点から軸を自動で推定し直し、古い計測結果を消します。
多角形を変更した場合は、再び「試料抽出・軸を自動推定」を押します。
自動推定だけが失敗した場合も、抽出済みの試料に対して手動軸を指定できます。
別画像の読込では多角形・区間の中心・軸・結果をリセットし、入力した基準区間長を保持します。
同じ起動中に各パスを続けて測る場合も、次の画像で区間の中心と多角形を指定してください。
ホイールでカーソル位置を中心に拡大縮小し、右ドラッグで画像を移動できます。「全体表示」で画面内へ戻します。
拡大・移動・表示切替・画面サイズの変更では指定を保持します。描画は画面に見える範囲だけを作ります。

GrabCutは、前景候補と確実な前景の多角形を囲む範囲に、幅・高さの10%（最低10px）の余白を足した範囲だけで実行します。
範囲外の物体や背景は計測に使いません。前景候補は測りたい試料の両側辺と計測区間全体を含め、
確実な背景はその近くの床・ローラーなどへ指定します。余白は `02` 冒頭の `GRABCUT_MARGIN_RATIO` で変更できます。
試料が処理範囲の側端へ接した場合は、側辺が欠けたまま計測せず、前景候補を広げるよう表示します。
複数の多角形は同じ試料の初期指定です。従来どおり、抽出後の最大領域1つの側辺を測ります。
推論用に範囲を絞っても、画像座標・画素間隔・mm/pxは元の補正画像の値です。

画像の左側をDR、右側をOPとして、結果表・プレビューの両隅・保存PNG・比較GUIとグラフへ表示します。
CSVの列名は `left_*`（DR）・`right_*`（OP）を使います。
カメラが固定でも、圧延の往復で試料の進行方向は変わります。DR・OPは画像の左右に固定し、
パスごとに入れ替えたり、画像を反転・回転して左右を合わせ直したりしません。

### 側辺長の評価条件

`02_measure_edge_lengths_gui.py` 冒頭の次の変数を変更します。GUIは変更後に起動し直します。

| 変数 | 既定値 | 意味 |
| --- | ---: | --- |
| `EVALUATION_INTERVAL_MM` | `1.0` | 抽出した側辺に沿って評価点を配置する間隔（mm）。正の値を指定する |
| `SMOOTHING_WIDTH_MM` | `2.0` | 側辺に沿って局所直線を当てはめる窓の全幅（mm）。`0` で平滑化を止める |

上下断面と外周輪郭の交点を求め、その間の連続したDR・OP側辺を、輪郭の順番に沿って切り出します。
区間内部に張り出しや折り返す凹凸があっても、断面ごとに外側の点へ置き換えず、側辺の形をたどります。

切り出した側辺の生の輪郭に沿う距離（弧長）で評価点と平滑化窓を配置します。
各窓内で画像のx座標・y座標へそれぞれ局所直線を当てはめ、平滑化した評価点間の距離を足します。
評価間隔と平滑化幅は、この側辺に沿う距離のmm指定です。基準区間長に使う軸方向の距離とは別です。
窓は側辺の両端で切り詰めます。下側断面を必ず含めるため、最後の評価間隔は設定値より短くなる場合があります。
平滑化後の両端は対応する上下断面へ投影し、指定した2断面間の側辺として長さを求めます。
元の輪郭画素をそのまま足す場合に生じる、斜線の階段形状による長さの過大評価を抑えます。
倍率は補正画像と同じ `workflow_settings.py` の `MM_PER_PX`（mm/px）を使います。

同一の比較では、倍率・評価間隔・平滑化幅を全パスで揃え、設定済みコードを結果と一緒に保管します。
平滑化幅を大きくすると、本来の細かい凹凸まで短く評価されます。最初に既知形状や代表画像で条件を決め、
設定を変える場合は比較対象の全画像を測り直してください。既定値は実画像での精度保証値ではありません。
上下の切断面がそれぞれ抽出輪郭と2点で交わらない場合や、計測する側辺が画像・処理範囲の端へ接する場合は停止します。
指定した長さが画像や抽出した側辺に収まらない場合も、区間を自動で短くして計測することはありません。
上下断面の間の内部断面は2交点に限定しません。上下断面そのものが複数の張り出しを横切る場合は、
両側辺を一意に切り出せる位置へ区間の中心を変更してください。

### CSVの内容と超過率

1回の計測で1行のUTF-8 BOM付きCSVを保存します。読込時には、次のうち `image_name` を除く列がすべて必須です。

| 列 | 内容 |
| --- | --- |
| `image_path` | 元画像のパス。読込時の画像名は、このパスから取得する |
| `image_name` | 保存時に付ける便宜上の画像名。読込時には使わないため、列がなくても読み込める |
| `interval_length_mm` | 軸に直角な上下断面の軸方向の間隔（基準区間長、mm）。入力した長さと浮動小数点の計算誤差の範囲で一致する |
| `left_mm`, `right_mm` | 平滑化後のDR・OP側辺長（mm） |
| `left_excess_percent`, `right_excess_percent` | DR・OPの超過率（%） |
| `mm_per_px` | 補正画像の倍率（mm/px） |
| `evaluation_interval_mm` | 抽出した側辺に沿う評価間隔（mm） |
| `smoothing_width_mm` | 側辺に沿う平滑化窓の全幅（mm） |

超過率は、DR・OPそれぞれ **`(側辺長 / 基準区間長 - 1) * 100`** で求めます。
例えば基準区間長100mm、側辺長102mmなら超過率は2%です。軸に平行な直線側辺は0%が目安です。
軸を自動・手動のどちらで決めたかはCSVへ記録しません。
画像名は `image_name` 列の有無や値にかかわらず、常に `image_path` のファイル名から取得します。

比較GUIと作図スクリプトは、新版の `02_measure_edge_lengths_gui.py` で保存したCSVだけを対象にします。
基準区間長は `interval_length_mm` から読み、比較GUIでは実測長と100mm換算を表示します。
`start_y`・`end_y` を使う旧CSVには対応しません。必須列が不足する場合は値を補わず、新版の計測GUIで測定・保存し直してください。
この改修では比較GUIに超過率グラフは追加していません。

### スクリプト内の設定から3種類のグラフを一括作成する

`04_plot_pass_metrics.py` は、冒頭の `MEASUREMENTS` に指定した計測CSVを直接読み、3種類の図をPNGへ保存します。
別の対応表CSVや測定値の転記は不要です。既存の比較GUIとは別に使い、追加の依存関係はありません。

`opencv-grabcut` フォルダから、次の2段階で使います。

1. `src/04_plot_pass_metrics.py` 冒頭の `MEASUREMENTS` と出力先 `GRAPH_DIRECTORY` を編集する。
   1行を「実験回、パス数、区間ID、計測CSVのパス」の順に書く。パス数は整数、それ以外は引用符で囲んだ文字列にする。
   各CSVは新版の `02` の「CSV・画像2枚を保存」で保存した計測CSVを使う。

   ```python
   MEASUREMENTS = [
       ("run01", 0, "a", "output/run01_pass00_a.csv"),
       ("run01", 0, "b", "output/run01_pass00_b.csv"),
       ("run01", 2, "a", "output/run01_pass02_a.csv"),
       ("run01", 2, "b", "output/run01_pass02_b.csv"),
   ]
   GRAPH_DIRECTORY = OUTPUT_DIRECTORY / "pass_graphs"
   ```

2. 作図する。コマンドの引数は不要。

   ```powershell
   uv run src/04_plot_pass_metrics.py
   ```

コード内のパスは例です。対応する計測CSVを用意してから実行します。
計測CSVのパスは絶対パス、または**スクリプトがある `src/` を基準とする相対パス**です。
上の例の `output/run01_pass00_a.csv` は `src/output/run01_pass00_a.csv` を指します。実行したフォルダには依存しません。
別環境へコピーするときは、`04_plot_pass_metrics.py` と `workflow_settings.py`、`utils/` を同じ版で揃えます。
CSVの必須列が不足する場合は、読込先の絶対パスと不足列をエラーに表示します。旧CSVへの読み替えや不足値の補完は行いません。
実データのファイルや参照先を公開しないよう、スクリプトをcommitする前に `MEASUREMENTS` を公開用の例へ戻します。

| 出力名 | 集計する値 | 単位 |
| --- | --- | --- |
| `excess.png` | 各区間のDR・OP超過率 | % |
| `change_from_initial.png` | 各区間の超過率 − 同じ実験回・区間ID・側のパス0の超過率 | パーセントポイント |
| `dr_op_difference.png` | 各区間のDR超過率 − OP超過率 | パーセントポイント |

横軸には `MEASUREMENTS` の実際のパス数を使い、昇順に並べます。行の順序は問いません。
欠測を0で埋めず、線は観測した点を結ぶ補助として使います。未観測パスの値を推定する線ではありません。
各区間を点で残し、実験回・パスごとに平均の線と区間間の標本SDの誤差棒を重ねます。DR・OPは別々に集計し、実験回同士も混ぜません。
SDは区間が2つ以上あるときだけ求めます（分母は区間数−1）。1区間の場合はその値を平均として表示し、SDは表示しません。
初回差とDR−OP差は、各区間の差を計算してから平均・SDを求めます。元の超過率のSD同士を引いた値ではありません。
パス0の初回差とそのSDが0になるのは、自分自身を引いているためです。測定誤差が0という意味ではありません。

同じ画像の別区間は `02` で区間を指定し直し、それぞれ別名のCSVと確認PNGへ保存します。画像ファイルは共通で構いません。
測定前に区間の選び方を決め、同じ長さで、できるだけ重ならない区間を各パスで同じルールにより選びます。区間の自動選択は行いません。
後のパスで一部の区間が欠けた場合は、ある区間だけで集計します。区間数や構成の変化自体が平均の変化につながるため、できるだけ同じ区間IDと区間数を揃えます。
同じ区間IDは比較用の識別子であり、圧延後も同じ材料部分を追跡できていることは保証しません。
同一画像内の区間数 `n` と独立した実験回数は区別します。平均しても抽出の偏り・倍率の誤りを解消するものではなく、局所的に大きい値と確認PNGも残します。

入力時に次を確認し、不一致・不正があれば保存前に停止します。

- 実験回と区間IDは空の文字列にしない。パス数は0以上の偶数の整数にする。
- 各実験回・区間IDの組にパス0を含め、同じ組の同一パスを重複させない。
- 同じ計測CSVを複数行で使い回さない。計測CSVは新版の `02` で保存した1計測1行を使う。
- 全計測の基準区間長・倍率・評価間隔・平滑化幅を揃える。条件を変えたデータは別の実行に分け、出力先も変える。

出力フォルダは自動作成し、同名のPNG3枚は確認なしで上書きします。全出力先を保存前に確認し、入力ファイルへの上書きは拒否します。
再測定後は同じコマンドで作り直せます。色・軸範囲・文字サイズ・図の大きさ・DPIは、スクリプト冒頭の設定値で調整します。

図は白背景・四辺の枠・上下左右の内向き目盛りとし、水平・垂直の補助線と0の基準線を入れません。軸名と単位、枠なしの凡例を表示します。
縦軸範囲が自動の場合は0を含めます。手動の軸範囲は指定値を使います。
DR・OPを色と異なるマーカーで区別し、実験回ごとに線種を変えます。題目・計測条件・区間数は画像内へ入れません。
原稿にはPNGを挿入し、図の下へ図番号・題目・説明を記載します。点・平均・SDの意味、計測条件、区間数は、指定したCSVと `MEASUREMENTS` を確認して必要に応じて添えます。
区間数と独立した実験回数を区別し、区間選択・除外や実験条件の説明も原稿に合わせて記載します。

| 設定変数 | 変更するもの |
| --- | --- |
| `MEASUREMENTS` | 実験回・パス数・区間IDと、読む計測CSVの組合せ |
| `GRAPH_DIRECTORY` | PNG3枚の出力先。既定は `src/output/pass_graphs/` |
| `FIGURE_SIZE`、`SAVE_DPI` | 図の横・縦の大きさ（インチ）とPNGの保存解像度。既定は約90×70mm、600dpi |
| `FONT_FAMILY`、`FONT_SIZE` | フォント名と文字サイズ。既定はWindowsの `Meiryo`、9pt |
| `DR_COLOR`、`OP_COLOR`、`DIFFERENCE_COLOR` | DR・OP・左右差の色 |
| `LINE_STYLES`、`MARKERS` | 実験回ごとの線種と、実験回・側に割り当てるマーカー |
| `PASS_X_LIMITS` | 3図共通の横軸範囲 |
| `EXCESS_Y_LIMITS`、`CHANGE_Y_LIMITS`、`DIFFERENCE_Y_LIMITS` | 各図の縦軸範囲 |

軸範囲の `None` は自動設定です。例えば `EXCESS_Y_LIMITS = (0, 5)` で超過率図の縦軸を0～5%に固定できます。
実験回別に図を作るときは軸範囲を揃え、範囲外の測定点を見落とさないよう確認します。
図幅を85mmにする場合は `FIGURE_SIZE = (85 / 25.4, 70 / 25.4)` のように変更します。実験回が多く凡例が詰まる場合は図幅を広げるか、実験回ごとに出力します。
これは論文原稿用の初期体裁です。投稿先ごとの図幅・フォント・言語・ファイル形式に合わせて調整します。
例えば [「鉄と鋼」の執筆要領](https://tetsutohagane.net/submission/guide_to_authors/instructions_to_authors) は図番号・図注を画像へ含めず、通常85mm幅、図中文字は英文としています。
軸名は英語です。図の下へ記載する英文キャプションの例は [発表原稿](../PRESENTATION.md#英文キャプション例) にあります。実験回の凡例には `MEASUREMENTS` に記入した名前をそのまま使います。
Excelで自由に編集する場合は、下記の集計手順と [発表用の作図手順](../PRESENTATION.md#5-実験結果) を使います。

### 実験回・圧延パスごとのExcel集計

1. 実験回ごとにフォルダを分け、画像・計測CSV・確認PNGを同じ規則で名付ける。
   例えば `run01_pass00_a`、`run01_pass02_a`、`run01_pass04_a` とし、同じパスの別区間は `_b` などで区別する。
   1台の固定カメラへ戻ってくる記録は、初回を0、次を2、以後4、6、…と付ける。
   撮れなかったパスは欠測のまま残し、後続のパス番号を詰めない。
2. Excelに各CSVの行をまとめ、手入力の `experiment_id`・`pass_number`・`section_id` 列を加える。
   `pass_number` は0、2、4、…の数値、`section_id` は同じパスの別区間の識別子とする。
   区間長・倍率・評価間隔・平滑化幅も集計表に残し、同条件か確認できるようにする。
   CSVの超過率は2%なら数値の `2` なので、セルは数値表示にし、グラフの軸名へ `%` を付ける。
   Excelのパーセント表示を使う場合は、別列で100で割ってから表示する。
3. XY散布図の横軸を `pass_number`、縦軸を超過率（%）とする。
   実験回ごとにDR・OPを別系列にし、DR・OPの色と実験回の線種を揃えると比較しやすい。
   横軸へCSVの追加順やファイルの並び順を使わない。0%の基準線も置く。
4. 同じパスで複数区間を測る場合は、個々の点を残す。代表値を出すなら実験回・パス・側ごとに平均と
   区間数、ばらつき（範囲または標準偏差）を添える。反復実験と同一画像内の複数区間は区別する。
5. 数値だけで採否を判断せず、確認PNGで輪郭・断面・軸のずれを確認する。
   撮影条件・校正・設定を変えた場合や、抽出を修正して再測定した場合は集計表に記録する。

比較する全パスで確保できる基準区間長を測定前に決め、GUIへ同じ値を入力します。
区間の位置の選び方・倍率・評価間隔・平滑化幅も揃え、端部・傷・反射などの除外規則を測定前に決めます。
超過率で区間長を正規化しても、凹凸の分布が異なる局所区間を同じ形状として扱えるわけではありません。
基準区間長を固定しても、圧延で伸びる同じ材料部分を追跡したことにはなりません。
各パスで異なる材料部分を測る場合は「そのパスで見える局所側辺の指標」として解釈します。
厚さの変化、面外の反り、カメラの振動、動体ブレによる差は、この2次元の超過率だけでは分離できません。

### 補正画像を中央部分に絞る

`01_rectify_images.py` と `01_rectify_frames_from_reference.py` は、共通設定の `RECTIFY_ROI` を使います。
既定値は `(0.25, 0.0, 0.75, 1.0)` で、歪み補正後の画像の中央50%の幅・縦全体を出力対象にします。
値は左・上・右・下の比率です。縦方向も不要な場合は、例えば `(0.25, 0.1, 0.75, 0.9)` へ絞れます。
`(0.0, 0.0, 1.0, 1.0)` にすると従来どおり全体を出力します。

元の写真・基準画像・動画フレームは、カメラ校正と同じ元解像度のまま渡してください。
板の検出には画像全体を使い、その後に指定範囲の4隅から遠近補正の出力枠を求めます。
傾いた範囲を囲む長方形を保存するため、周辺が少し入る場合や、出力画素数が比率どおりにならない場合があります。
リサイズはせず `MM_PER_PX` を維持するので、GUIも同じ倍率で測れます。
固定カメラ版は基準画像と全フレームに同じ出力枠を使います。実行時に出力の縦横pxを表示します。
範囲を変えた場合は補正PNGを作り直し、試料の両側辺と測りたい区間が残っていることを確認します。

## 設定と実行

`opencv-grabcut` フォルダから実行します。依存関係は題材の `pyproject.toml`・`uv.lock` を共用します。

```powershell
uv sync
uv run src/00_1_generate_charuco_board.py
uv run src/00_2_calibrate_camera.py
uv run src/01_rectify_images.py
uv run src/02_measure_edge_lengths_gui.py
uv run src/03_compare_edge_lengths_gui.py
# 厚さとの関係も見る場合はこちらを選ぶ
uv run src/03_compare_edge_lengths_with_thickness_gui.py
```

初期準備は次の順序です。

1. `workflow_settings.py` の板の寸法を確認して印刷し、実寸を測る。
2. 校正写真を `src/input/camera_calibration/` に置く。
3. `00_2` を実行し、表示された `CALIBRATION_SIZE`・`CAMERA_MATRIX`・`DIST_COEFFS` を、この版の `01` の冒頭に貼る。現在は未設定なので、校正するまで補正は実行できない。
4. `workflow_settings.py` の `MM_PER_PX` を確認し、写真を補正してから計測する。既定値は `0.25`。

写真の枚数と撮り方は [撮影手順](../sandbox/CAPTURE.md) で管理し、この版では枚数の下限による停止や枚数不足の案内を行いません。
校正・補正とも `find_images()` で入力フォルダ直下の画像を取得し、フォルダがない場合や画像がない場合は同じ処理で停止します。
`00_2` は、次の写真を理由・ファイル名とともに表示してスキップし、残りで係数を求めます。

- 読み込めない画像。
- 板の角を縦横に6点以上検出できない写真。
- 最初に板を検出できた写真と解像度が違う写真。
- 魚眼校正で `Ill-conditioned matrix for input array ...` と特定された写真。この写真を除いて再計算し、別の写真が同じ理由で失敗した場合も繰り返します。

読めた写真には従来どおり確認PNGを保存し、検出・解像度の判定を `OK` / `NG` で示します。
`OK` でも後の校正計算で除外されることがあるため、最終的な採否は実行時のスキップ表示で確認します。
最後に使用枚数・スキップ枚数と、使用した写真だけの再投影誤差、コピペ用の3設定を表示します。
画像を読み込めなかった場合には、その画像の確認PNGは作成できません。

使える写真がなくなった場合、原因の写真を特定できない計算エラー、係数が不正な場合、確認PNGの保存失敗では停止します。
枚数による下限や、再投影誤差のしきい値による自動除外は追加していません。写真を除外して係数が出ても、校正結果の精度確認は必要です。

板の寸法を変えたら、板を印刷し直してカメラ校正もやり直します。
倍率を変えたら、変更後の設定で補正画像を作り直します。
設定は起動時に読み込むため、変更後は実行中のスクリプト・GUIを起動し直してください。
この設定は旧版の `sandbox/submissions/` には反映されません。

入出力先は `workflow_settings.py` の冒頭で変更します。既定では、この `src/` フォルダを基準にしています。
`OUTPUT_DIRECTORY` を変更すると、補正画像・校正の確認画像の保存先、計測・比較GUIの保存開始先も追従します。
`RECTIFIED_DIRECTORY` を個別に変更した場合も、補正の出力先と計測の読込開始先は揃います。
既定の場所は次のとおりです。元の提出版の入出力とは分かれています。

| 用途 | 題材フォルダからのパス |
| --- | --- |
| 校正写真 | `src/input/camera_calibration/` |
| 補正する写真 | `src/input/` 直下 |
| 板・読取確認画像・計測・比較結果 | `src/output/` |
| 補正画像 | `src/output/rectified/` |

既存の写真を使う場合は、`workflow_settings.py` の `INPUT_DIRECTORY`・`CALIBRATION_DIRECTORY` を変更するか、写真をコピーします。
補正PNGや新版の計測GUIで保存した長さCSVは、各GUIのファイル選択から直接読み込めます。
CSVの浮動小数点数の丸め方（有効数字12桁）とUTF-8 BOMは提出版と同じです。列は上記の長手軸方式へ更新しています。
確認PNG・比較PNGの表示名はDR・OPで、補正PNGの出力範囲は上記の共通設定に従います。
各GUIで任意の保存先を選ぶ場合は、元の出力を残せる名前を指定してください。
撮影条件・板と試料の高さは [撮影手順](../sandbox/CAPTURE.md)、GUI操作・エラー時の扱いは本書を参照してください。
提出版の手順にある入出力先・板・倍率の設定先は、この版では `workflow_settings.py` に読み替えます。

## 動画からフレームを保存する

`opencv-grabcut` フォルダから実行します。追加の依存関係はありません。

```powershell
uv run src/video_frame_gui.py
```

読込の取消や失敗では現在の動画を保持します。OpenCVで開けて、フレーム数とFPSを取得できる動画を使ってください。

## 固定カメラの動画フレームを補正する

`01_rectify_frames_from_reference.py` は、動作前のボード付き基準画像から補正を1回求め、
動作中の全フレームへ同じ歪み補正・遠近変換・出力範囲を適用します。
各フレームにはボードが不要です。毎画像のボードを使う従来の `01_rectify_images.py` と使い分けます。
上のGUIやFFmpegでフレームを切り出し、このスクリプトにはPNG・JPEGなどの画像を渡します。

### 設定と実行

1. 基準画像と測定フレームを、同じ動画条件・元解像度で書き出す。リサイズ・切り抜き・回転は加えない。
2. このスクリプトの冒頭へ、動画条件に適合する `CALIBRATION_SIZE`・`CAMERA_MATRIX`・`DIST_COEFFS` を貼る。
   既存の `01_rectify_images.py` の係数は自動では読み込まない。魚眼モデルの歪み係数4個を使う。
3. 同じ冒頭の `REFERENCE_IMAGE_PATH`・`FRAMES_DIRECTORY`・`RECTIFIED_FRAMES_DIRECTORY` を確認する。
   既定値は次のとおり。板の仕様と `MM_PER_PX` は既存GUIと同じ `workflow_settings.py` を使う。

| 用途 | `src/` を基準にした既定の場所 |
| --- | --- |
| ボード付き基準画像 | `input/video_reference/reference.png` |
| 補正するフレーム | `input/video_frames/` 直下 |
| 補正フレーム | `output/rectified_frames/` 直下 |
| 基準画像の補正結果 | `output/rectified_frames/reference/reference.png` |

入出力の既定値は共通の `INPUT_DIRECTORY`・`OUTPUT_DIRECTORY` から決まります。
撮影ごとに保存先を変える場合は、このスクリプトの `RECTIFIED_FRAMES_DIRECTORY` を変更してください。
基準画像の補正結果は `reference/` 内に基準画像の名前をPNGへ変えて保存します。
入出力のフォルダは混ぜず、結果を再現するため基準画像・設定済みスクリプト・共通設定を保管します。

`opencv-grabcut` フォルダから実行します。

```powershell
uv run src/01_rectify_frames_from_reference.py
uv run src/measure_point_distance_gui.py
uv run src/02_measure_edge_lengths_gui.py
```

### 撮影条件と結果の扱い

- 基準撮影から動作中までカメラの位置・高さ・向き・画角・ズームを固定する。
  手ぶれ補正・水平維持・自動クロップなど、画像の対応関係を変える処理は使わない。
  基準画像も同じ動画から切り出し、カメラ係数が動画の撮影モードに適合していることを確認する。
- ボードを測定予定の試料面に近い高さ・傾きで平らに置く。
  高さの差や反りによる誤差は補正しない。結果はボードの基準面に換算した長さとして扱う。
- 写真内の向きを保つため、試料の長手は画像の縦方向へ揃え、区間内の左右両側辺を写す。
  動体ブレ・反射・影で境界が読めないフレームは測定に使わない。
- カメラを動かしたら、新しい基準画像と別の出力先を使う。
  設備の動かない部分や終了後のボード画像で構図の変化を確認する。
  同じ画像サイズでも画角・カメラ姿勢の変化はコードでは検出できない。

基準画像で角を縦横に6点以上読めない、再投影誤差が2pxを超える、補正画像が大きすぎる場合は停止します。
表示する角数・再投影誤差は基準画像の値であり、動作中のフレームの寸法精度を表す値ではありません。
フレームは基準画像と同じ解像度であることを確認します。解像度不一致はファイル名を示して停止します。
既存の出力PNGは同名で上書きしますが、基準画像・入力フレームへの上書きと出力名の重複は実行前に拒否します。
途中で失敗した場合、基準画像の補正結果と処理済みフレームは残ります。
入力を直し、結果を退避するか同じ条件で上書きして再実行してください。
