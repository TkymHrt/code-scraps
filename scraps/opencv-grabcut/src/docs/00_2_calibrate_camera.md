## 1. 校正で求めたいもの

写真の上で測った画素数を、そのまま実物の長さにできるとは限りません。レンズを通すと直線が曲がって写ったり、場所によって写る倍率が変わったりします。まず、カメラの写り方を表す数値を求めます。この作業がカメラ校正です。

このプログラムは、実物の配置と寸法が分かっているChArUco板を写した複数の写真を使います。各写真について、次の対応を集めます。

```text
板の上で既知の角の位置             写真の上で検出した同じ角の位置
(X, Y, Z) : mm                    (u, v) : px
                同じIDで対応付ける
```

カメラに共通する「写り方」と、各写真で異なる「板の向き・位置」を合わせて推定します。板の向き・位置が異なっても、カメラのレンズ・撮影条件が同じであれば共通の係数を使える、という前提です。

求める主な値は次の3つです。

| 名前 | 内容 | 次の工程での用途 |
| --- | --- | --- |
| `CALIBRATION_SIZE` | 校正に使用した画像の幅・高さ、単位px | 補正対象が同じ解像度か確認する |
| `CAMERA_MATRIX` | 3×3のカメラ行列 | 焦点距離に相当する画素上の倍率と、投影の中心を表す |
| `DIST_COEFFS` | 魚眼モデル用の4係数 | レンズの写り方の補正に使う |

これらは最終的にターミナルへ表示します。設定ファイルへ自動保存したり、後続のコードへ自動で書き込んだりする実装ではありません。表示された3設定を、使う補正スクリプトの冒頭へコピーします。

## 3. 読む順序と、実際に実行する順序

ファイルには `calibrate()`、`parameter_text()`、`main()` の順に関数が定義されています。関数を定義することと、その関数を呼んで実行することは別です。

実行すると、入口の `main()` から次の順序で進みます。

```text
main()
  ├─ 入出力フォルダを絶対パスへ直す・同一なら停止
  ├─ find_images() : 入力画像を列挙する
  ├─ calibrate(paths, output_directory)
  │    ├─ 板・検出器・全ての角の物理座標を用意する
  │    ├─ 写真ごとに読む → 検出 → 確認PNG → 対応点を蓄積する
  │    ├─ 魚眼校正を試し、不安定と特定された写真を外して再計算する
  │    ├─ 係数が有限値で妥当か確認する
  │    └─ 使用した写真ごとの再投影誤差を計算して返す
  ├─ 全体RMSと写真ごとの誤差を表示する
  └─ parameter_text() : コピー用の3設定を文字列にして表示する
```

以下では、まず関数内の実装を上から読み、最後に `main()` からのつながりを再確認します。

## 4. 読み込む機能と、関数宣言の記法

最初に、標準ライブラリと外部ライブラリを読み込みます。

```python
import re
from pathlib import Path

import cv2 as cv
import numpy as np
```

- `re` は、文字列から特定の並びを探す正規表現の標準ライブラリです。後でOpenCVのエラーメッセージから写真番号を取り出します。
- `Path` は、ファイル・フォルダのパスを扱う標準ライブラリの型です。
- `cv` は、このファイルの中でOpenCVを呼ぶ短い名前です。
- `np` は、このファイルの中でNumPyを呼ぶ短い名前です。NumPyでは画像・点・行列を配列として扱います。

続いて、[共通の画像入出力](../utils/file_io.py)から `find_images`、`read_image`、`write_png`、[共通設定](../workflow_settings.py)から板の仕様と入出力先を取り込みます。

```text
def calibrate(paths: list[Path], output_directory: Path) -> tuple:
```

この宣言は、`calibrate` という関数を定義しています。

| 部分 | 意味 |
| --- | --- |
| `paths` | 入力画像のパス一覧を受け取る名前 |
| `: list[Path]` | `Path`を並べたリストを想定している、という型注釈 |
| `output_directory` | 確認PNGの保存先フォルダを受け取る名前 |
| `: Path` | パスのオブジェクトを想定している、という型注釈 |
| `-> tuple` | 複数の結果をタプルにまとめて返す、という型注釈 |

型注釈を書くだけで値の検査や自動変換が行われるわけではありません。関数の使い方を、人と解析ツールへ伝えるための情報です。戻り値の `tuple` は後で、画像サイズ・行列・歪み係数・RMS・写真ごとの誤差の5個だと分かります。

## 5. 検出に使う板と、物理座標の一覧

関数の初めで、生成時と同じ板を定義します。

```python
dictionary = cv.aruco.getPredefinedDictionary(cv.aruco.DICT_4X4_50)
board = cv.aruco.CharucoBoard(BOARD_SQUARES, SQUARE_MM, MARKER_MM, dictionary)
detector = cv.aruco.CharucoDetector(board)
all_board_points = np.array(board.getChessboardCorners(), dtype=np.float64)
```

`dictionary` はマーカーの種類、`board` は板の配置・寸法を保持するオブジェクト、`detector` はその板を画像から探す検出器です。板生成と同じ `(7, 5)`、30mm、18mm、同じ辞書を使います。実物の板と、この定義が一致している必要があります。

`board.getChessboardCorners()` は、板の全てのチェス盤内側の角の物理座標を返します。写真を読んだ結果ではありません。板の設計だけから決まる一覧です。`np.array(..., dtype=np.float64)` で、小数を扱う64ビットのNumPy配列に揃えます。

既定の板では内側の角が24個なので、`all_board_points.shape` は `(24, 3)` です。

```text
行番号 = ChArUcoの角ID            列 = X(mm), Y(mm), Z(mm)
0                               [ 30.0, 30.0, 0.0 ]
1                               [ 60.0, 30.0, 0.0 ]
2                               [ 90.0, 30.0, 0.0 ]
...
```

これは現行環境での既定板の値です。板は平面なので全点の `Z` は0です。ただし、写真の中で板が傾いていることまで0という意味ではありません。これは板自身を基準にした座標で、写真ごとの傾きや位置は校正中に別途推定します。

## 6. 蓄積する3つのリストと、画像サイズ

```python
object_points = []
image_points = []
used_indices = []
image_size = None
```

`[]` は空のリストです。読み進めながら、使える写真のデータを1枚分ずつ追加します。

| 変数 | 追加する内容 | 単位・意味 |
| --- | --- | --- |
| `object_points` | 各写真で見えた角の板上の3D座標 | mm |
| `image_points` | 同じ角を写真から検出した2D座標 | px |
| `used_indices` | その写真が元の `paths` の何番目だったか | 0始まりの整数 |
| `image_size` | 最初に採用した画像の `(幅, 高さ)` | px。未決定は `None` |

`None` は「まだ値がない」「該当しない」ことを表す特別な値です。数値の0でも空文字列でもありません。

3つのリストの同じ位置が、同じ写真に対応します。たとえば `object_points[2]`、`image_points[2]`、`used_indices[2]` は、校正候補の3枚目に関する情報です。この対応を最後まで保つことが、誤差を正しい写真名と結び付けるために必要です。

## 7. 写真を1枚ずつ読み、読めない写真を飛ばす

```text
for index, path in enumerate(paths):
```

`for` は繰返しです。`enumerate(paths)` は、パスだけでなく、その位置の番号も返します。`index` は0、1、2…、`path` はその位置の画像パスです。`index + 1` を表示する箇所では、人が数えやすい1始まりの番号にしています。

```python
try:
    image = read_image(path)
except ValueError as error:
    print(f"スキップ {index + 1}: {error}")
    continue
```

`try` の中を実行し、`ValueError` が発生したら `except` の中へ移ります。`as error` は、発生した例外の情報に `error` という名前を付ける部分です。`continue` は、この写真について残りの処理をせず、次の写真へ進む命令です。

`read_image()` の中では、まず `Path.read_bytes()` でファイルをバイト列として読みます。続いて `np.frombuffer(..., np.uint8)` でデータを配列として見て、`cv.imdecode(..., cv.IMREAD_COLOR)` でカラー画像へ復号します。この手順で日本語を含むパスを扱っています。ファイルを読めない、OpenCVが画像へ戻せない、といった失敗を `ValueError` にして呼出元へ返します。

ここで読み込めなかった写真は、確認PNGを作れません。書込失敗など、これ以降の全ての失敗をこの `except` が捕まえるわけではありません。`try` の字下げの範囲は `read_image(path)` の呼出だけです。

## 8. 画像のサイズと、検出結果を受け取る

```python
height, width = image.shape[:2]
corners, ids, markers, marker_ids = detector.detectBoard(image)
```

カラー画像の配列は、通常 `(高さ, 幅, 色成分数)` という形です。`image.shape[:2]` は、その形状の先頭2個だけを取り出します。960px × 720pxの画像なら、形状は `(720, 960, 3)`、`height = 720`、`width = 960` です。`height, width = ...` は、2個の値を2個の名前へ分けて受け取る代入です。

`detectBoard(image)` は、4個の結果を返します。

| 変数 | 内容 | 校正での扱い |
| --- | --- | --- |
| `corners` | 検出したChArUcoの角の画像座標 | 校正へ渡す2D点になる |
| `ids` | `corners` の各点に対応する角ID | 板上の物理座標を選ぶ |
| `markers` | 検出したArUcoマーカーの四隅 | 確認PNGへ描く |
| `marker_ids` | マーカーの識別番号 | 確認PNGへ描く |

ここで、`ids` と `marker_ids` を区別します。前者はチェス盤の角のID、後者は白黒マーカーのIDです。校正用の `all_board_points` の行を選ぶのは **`ids`** です。マーカーの四隅を、そのまま24個の角へ対応させてはいません。

検出点数を `N` とすると、文書作成時に確認したOpenCV 5.0.0では、角の配列は `(N, 2)`、IDは `(N,)` でした。`(N,)` は、N個の要素を持つ1次元配列を表します。OpenCVの別の版の例では `(N, 1, 2)`、`(N, 1)` のように1の軸が入る形も見かけます。このコードは受取直後の軸の置き方を固定的に使わず、描画や校正へ渡す前に `reshape()` で必要な形へ揃えます。検出がなければ `ids` などが `None` になるため、それを先に確認します。

## 9. 写真を使える候補にする条件

まず、点数を求めます。

```python
corner_count = 0
if ids is not None:
    corner_count = len(ids)
```

`len(ids)` はIDの個数です。`is not None` は「値が存在しないことを示す `None` ではない」を確認します。NumPy配列に対して単に `if ids:` とすると、複数要素をどう真偽判定するかが曖昧になるので、ここでは `None` と区別しています。

続いて、除外理由を決めます。

```python
skip_reason = None
if corner_count < 6 or board.checkCharucoCornersCollinear(ids):
    skip_reason = "板の角を縦横に6点以上読めません"
elif image_size is not None and image_size != (width, height):
    skip_reason = f"解像度が違います: {(width, height)} / 使用: {image_size}"
```

最初は `skip_reason = None`、つまり「除外理由はまだない」です。条件に当てはまれば理由の文字列を入れます。

- `corner_count < 6` は、検出点が6個未満かを調べます。
- `or` は、どちらかが成り立てば真です。左が真なら右を評価しない、短絡評価をします。そのため、点が0個のときに右側を無条件に呼ぶ構造ではありません。
- `checkCharucoCornersCollinear(ids)` は、選ばれた板上の角が一直線に並ぶ配置かを調べます。6個以上あっても、一直線にしか情報がなければ採用しません。
- 表示の「縦横に6点以上」は、縦6点かつ横6点という意味ではありません。コード上の条件は「合計6点以上で、全点が共線ではない」です。
- `elif` は、前の `if` が成り立たなかったときに、次の条件を調べます。
- `and` は、両方が成り立つ場合だけ真です。
- `!=` は、「等しくない」を調べます。

`image_size` は後で、採用した写真のサイズに設定します。したがってサイズ基準は「最初の入力ファイル」でも「最初に読めた画像」でもなく、**検出条件を満たして最初に採用した写真**です。後続候補はそのサイズと同じでなければ除外します。

この段階の合格は、校正の精度が十分という意味ではありません。後の校正計算で不安定と特定されれば、さらに除外されます。

## 10. 元画像をコピーして、読取確認PNGを作る

```python
check_image = image.copy()
```

配列の `copy()` は、画像データのコピーを作ります。続く描画関数は渡した画像へ直接描き足すので、元の `image` を確認用の線や文字で汚さないためです。

`marker_ids` がある場合は `drawDetectedMarkers()` でマーカーを、角が1個以上ある場合は `drawDetectedCornersCharuco()` でChArUcoの角を描きます。後者へ渡す `corners.reshape(-1, 1, 2)` は、点を描画APIが受け取る形へ並べ直すものです。

`reshape` は点の値を変えたり、別の座標へ変換したりする処理ではありません。`-1` は「全要素が収まる個数を自動で決める」、末尾の2は「1点が横・縦の2数値からなる」という指定です。

描画色 `(0, 0, 255)` は赤です。OpenCVで読み込んだカラー画像の色順序は **BGR**、すなわち青・緑・赤だからです。

```python
status = "OK" if skip_reason is None else "NG"
```

これは条件式です。「除外理由がなければ `"OK"`、あれば `"NG"`」を選び、`status` に代入します。通常の `if` 文を1行へまとめた、値を選ぶための構文です。

`cv.putText(...)` は画像の中へ状態と点数を描きます。

| 引数 | 内容 |
| --- | --- |
| `check_image` | 書き込むコピー画像 |
| `f"{status}: {corner_count} corners"` | たとえば `OK: 24 corners` |
| `(20, 40)` | 文字の基準位置。左から20px、上から40px |
| `cv.FONT_HERSHEY_SIMPLEX` | OpenCVの英数字用フォント |
| `1` | 文字サイズの倍率 |
| `(0, 255, 255)` | BGRで黄色 |
| `2` | 線の太さ、px |

保存先は `output_directory / f"{path.name}_detected.png"` です。`path.name` はパス全体ではなくファイル名部分、`/` は `Path` のパス連結、f文字列の `{...}` は値の埋込みです。

`write_png()` は、拡張子を確認し、PNGへ変換してから必要なフォルダを作って保存します。詳細は[板生成の保存処理](00_1_generate_charuco_board.md)と[画像入出力の実装](../utils/file_io.py)を参照してください。同名の確認PNGがある場合は置き換わります。

**読めた画像については、NGでもこの確認PNGを保存してからスキップします。** 板が検出できなかった画像にもNGと0点を描けます。保存に失敗したら、ここでは例外を捕まえていないため全体が停止します。

if skip_reason is not None:

ここでは、読取確認の結果を表示した後、除外された画像について理由と確認画像の場所を表示します。`continue` によって、これより後の対応点追加には進みません。

## 12. 検出IDを使い、物理点と画像点を同じ順序に揃える

採用候補では、まずサイズを保持します。

```python
image_size = (width, height)
board_points = all_board_points[ids.astype(np.int32).ravel()]
```

2行目はこの関数で特に重要です。短い1行ですが、次の3段階を行います。

1. `ids.astype(np.int32)`：角IDを32ビットの整数配列へ揃える。
2. `.ravel()`：IDを1次元の配列として扱える形へする。現行環境のように最初から1次元なら、並びはそのまま。たとえば1列の `[[2], [8], [9]]` で受け取る形でも、`[2, 8, 9]` へ揃えられる。
3. `all_board_points[...]`：その番号の行を、指定した順序で選ぶ。

たとえば `ids` が `[2, 8, 9]` なら、`board_points` は板の全点一覧の2行目、8行目、9行目を、この順序で取り出した配列です。行番号は0始まりなので、「2行目」は人が1から数えれば3番目の行に当たります。写真の検出順と、板の全点一覧の先頭からの順序が同じとは仮定していません。

```text
cornersの0番目 ── idsの0番目は2 ── 板のID2の物理座標
cornersの1番目 ── idsの1番目は8 ── 板のID8の物理座標
cornersの2番目 ── idsの2番目は9 ── 板のID9の物理座標
```

これは説明用の3点例です。実際には6点以上などの条件を通過した写真だけがこの箇所へ到達します。

写真に板の全体が写っていなくても、対応するIDの角が必要数検出できれば、その部分だけ使えます。一方で、角を単に左上から並べ直したり、マーカーIDと取り違えたりすると、違う位置どうしを対応付けることになり、校正の前提が崩れます。

## 13. 校正API向けに配列の形を揃え、リストへ追加する

```python
detected_points = np.array(corners, dtype=np.float64).reshape(1, -1, 2)
object_points.append(board_points.reshape(1, -1, 3))
image_points.append(detected_points)
used_indices.append(index)
```

角が `N` 個の写真では、次の形になります。

| 値 | 配列の形状 | 末尾の意味 | 単位 |
| --- | --- | --- | --- |
| `board_points` | `(N, 3)` | X、Y、Z | mm |
| `board_points.reshape(1, -1, 3)` | `(1, N, 3)` | X、Y、Z | mm |
| `detected_points` | `(1, N, 2)` | u、v | px |

たとえば24点なら `(1, 24, 3)` と `(1, 24, 2)` です。最初の1は、ここでOpenCV 5の校正へ渡す際の「1行に全点を持つ」配置です。3は空間の座標成分数、2は画像の座標成分数です。写真枚数を、この先頭の1へまとめて入れるのではありません。

写真ごとの配列を、`append(...)` で外側のPythonリストへ1個ずつ追加します。写真によって検出点数 `N` が違っていても構いませんが、同じ写真の物理点数と画像点数、点の対応順序は一致する必要があります。

`used_indices.append(index)` は、写真を飛ばしても元の入力番号を失わないための記録です。ここまでで、写真ごとの読込・検出ループが終わります。

## 14. 魚眼モデルで何を表しているのか

このプログラムが呼ぶのは `cv.fisheye.calibrate()` です。一般的な通常レンズ用の `cv.calibrateCamera()` と、モデルと係数の意味が異なります。数字が4個あるからといって、ほかのモデルの係数を同じ意味で使えるわけではありません。

概念としては、板上の点を、その写真の板の向き・位置によってカメラから見た座標へ移し、魚眼モデルで画像座標へ投影します。

```text
板上の3D点
   ↓ 写真ごとの回転・移動
カメラから見た3D点
   ↓ 魚眼レンズのモデル + カメラ行列
予測する画像上の2D点
```

魚眼モデルの4係数 `k1`〜`k4` は、レンズ中心からの角度 `θ` に対して、高い次数の項で写り方を調整する係数です。

```text
θd = θ × (1 + k1×θ² + k2×θ⁴ + k3×θ⁶ + k4×θ⁸)
```

`θd` は補正された角度に相当する量で、画素数そのものではありません。式を実装しているのはOpenCVで、このスクリプトが自分でその計算を書いているわけではありません。式とモデルの定義は[OpenCV公式の魚眼カメラモデル](https://docs.opencv.org/4.x/db/d58/group__calib3d__fisheye.html)を参照してください。このリンクはモデルを読む補助資料で、手元のOpenCV 5のコードを旧版APIへ書き換える指示ではありません。

主なカメラ行列は、次の形で理解できます。この実装はスキューを0へ固定します。

```text
           [ fx   0  cx ]
matrix =   [  0  fy  cy ]
           [  0   0   1 ]
```

`fx`、`fy` は画素単位の焦点距離に相当する倍率、`cx`、`cy` は画像上の主点の座標、単位はpxです。実際のレンズに印字された「焦点距離mm」と、そのまま同じ数ではありません。魚眼の4係数は角度についての多項式の係数で、mm単位の距離やpx単位の誤差ではありません。

## 15. 校正フラグと、反復計算を止める条件

```python
flags = cv.CALIB_RECOMPUTE_EXTRINSIC | cv.CALIB_CHECK_COND | cv.CALIB_FIX_SKEW
```

フラグは、ライブラリの動作を選ぶための印です。ここでは現在のコードにある `cv.CALIB_...` 定数を、`|` というビットORで組み合わせています。条件分岐で使う `or` とは異なる演算子です。

| フラグ | この計算で意図する動作 |
| --- | --- |
| `CALIB_RECOMPUTE_EXTRINSIC` | 内部パラメーターの更新に伴い、写真ごとの板の位置・姿勢も再計算する |
| `CALIB_CHECK_COND` | 計算が不安定になる条件を確認する |
| `CALIB_FIX_SKEW` | 画像軸の斜交を表すスキューを0へ固定する |

校正呼出の `criteria` は次のタプルです。

```python
criteria=(cv.TERM_CRITERIA_EPS + cv.TERM_CRITERIA_MAX_ITER, 100, 1e-8)
```

これは、「値の変化が十分小さくなったか」と「反復回数の上限」を使う終了条件です。`100` は最大100回、`1e-8` は `0.00000001` の科学技術表記です。後者は最適化を止めるための小さな許容値であって、「実寸誤差がこのmm以内」という精度指定ではありません。ここでの `+` は終了条件の種類のフラグを組み合わせるために使っています。

## 16. `while True` で、必要なら写真を除いて再計算する

```python
while True:
    if not object_points or image_size is None:
        raise ValueError(
            "校正に使える写真がありません。スキップ理由と確認画像を確認してください"
        )
```

`while` は条件を満たす間繰り返す文です。`True` は常に真なので、内部で `break` して抜けるか、例外で停止するまで繰り返します。

`not object_points` は、ここではPythonのリストが空かどうかの判定です。写真が1枚も残っていないか、画像サイズが未確定なら、`raise ValueError(...)` で処理を止めます。`raise` は自分で例外を発生させる命令です。

このコードには「最低何枚以上必要」という独自の枚数判定はありません。1枚でも候補があれば校正APIへ渡します。これは1枚で十分な精度の校正ができると推奨しているのではなく、枚数だけで停止させる条件を実装していないという事実です。

毎回、次の行列を新しく用意します。

```python
matrix = np.zeros((3, 3), dtype=np.float64)
distortion = np.zeros((4, 1), dtype=np.float64)
```

`np.zeros` は、指定した形の全要素を0にした配列を作ります。`matrix` は3×3、`distortion` は4行1列です。

これは最終的な係数を0だと決めているのではありません。この呼出では既知の内部係数を初期値として固定的に使う指定をしておらず、OpenCVが係数を推定します。また、前回の校正がエラーで途中終了すると、渡した配列が途中の値に書き換わっている可能性があります。ループの中で作り直すことで、その途中の値を次の計算へ持ち込みません。

## 17. 校正の5個の戻り値を受け取る

`cv.fisheye.calibrate()` へは、対応点のリスト、画像サイズ、行列と歪み係数の配列、フラグ、終了条件を渡します。戻り値を次の5個の名前へ受け取ります。

```python
rms, matrix, distortion, rotations, translations = cv.fisheye.calibrate(
    object_points,
    image_points,
    image_size,
    matrix,
    distortion,
    flags=flags,
    criteria=(cv.TERM_CRITERIA_EPS + cv.TERM_CRITERIA_MAX_ITER, 100, 1e-8),
)
```

| 戻り値 | 内容 |
| --- | --- |
| `rms` | 全体の再投影誤差のRMS。単位px |
| `matrix` | 推定した3×3カメラ行列 |
| `distortion` | 推定した4個の魚眼歪み係数 |
| `rotations` | 使用した写真ごとの回転ベクトル |
| `translations` | 使用した写真ごとの移動ベクトル |

`rotations` は3Dの向きを表す回転ベクトルで、単純に「画像を何度回すか」の角度1個ではありません。`translations` の距離の単位は入力した物理点と揃うので、この題材ではmmになります。

`matrix` と `distortion` は複数写真に共通、回転・移動は写真ごとに異なります。成功すると直後の `break` で `while True` を抜けます。

## 18. 不安定な写真を、エラーメッセージから特定する

校正の呼出は `try` の中にあり、OpenCVが `cv.error` を発生させた場合は `except cv.error as error` に移ります。何でも削除してやり直すのではなく、特定のメッセージだけから、除く写真を判断します。

```python
match = re.search(
    r"Ill-conditioned matrix for input array (\d+)", str(error)
)
```

`str(error)` は例外を文字列へ変換します。`re.search(...)` は、その中に指定の並びがあるかを探します。

| 正規表現の部分 | 意味 |
| --- | --- |
| `r"..."` | バックスラッシュをそのまま扱いやすいraw文字列 |
| `Ill-conditioned matrix for input array ` | この固定した英文を探す |
| `\d` | 数字1文字 |
| `+` | 直前のものが1文字以上続く |
| `(\d+)` | 見つけた数字のまとまりを後で取り出せるように囲む |

`match` が `None` なら、想定する理由のエラーではありません。その場合は `ValueError("カメラ校正に失敗しました") from error` で停止します。`from error` は、元のOpenCVの例外を原因としてつなぎ、調査できるようにする記法です。

数字を取り出せた場合は、次を実行します。

```python
photo_index = int(match.group(1))
```

`group(1)` は最初の括弧に一致した文字列です。たとえば `"3"` を `int` で整数3に変えます。この番号は元の全入力の番号ではなく、**現在校正へ渡している候補リスト内の位置**です。

`photo_index >= len(used_indices)` の場合も対応が取れないため停止します。この実装は、OpenCVのこのメッセージ形式と番号の意味に依存しています。メッセージが変わったり、別のエラーが出たりした場合は、原因を決めつけて写真を除去せず停止する形です。

## 19. 3つのリストを同じ位置で削除し、再試行する

```python
input_index = used_indices.pop(photo_index)
photo_path = paths[input_index]
```

`pop(photo_index)` は、その位置の要素を取り除き、取り除いた値を返します。ここで返るのは元の入力番号です。`paths[input_index]` から、正しい元ファイル名を取り出せます。

たとえば次の状態を考えます。

```text
元のpathsの位置     0      1      2      3      4
入力の例           A      B      C      D      E
事前の除外                       ↑Cを除外済み

used_indices = [0, 1, 3, 4]
現在の候補       A  B  D  E
候補内の番号     0  1  2  3
```

校正が「候補内の2番」と報告した場合、`used_indices.pop(2)` が返すのは3です。削除する元入力はDになります。番号を元入力へそのまま使うとCを指してしまうので、この対応表が必要です。

理由と元のファイル名、確認画像の場所を表示した後、次を実行します。

```python
del object_points[photo_index]
del image_points[photo_index]
```

`del` は、指定したリスト要素を削除します。`used_indices` はすでに `pop()` で削除済みなので、3つのリストは同じ位置で1枚分ずつ短くなります。板の点だけ、あるいは画像の点だけを削除すると対応が崩れるため、必ず一緒に扱います。

ここまで来ると `except` の処理が終わり、`while True` の先頭へ戻ります。残りの写真で、行列・歪み係数を0から作り直して再計算します。次の写真で同じ理由が出れば、再び除いて試します。

確認PNGの `OK` は検出時に描いた状態なので、この段階の除外後にNGへ描き直してはいません。**最終的な採否はターミナルのスキップ表示と使用枚数で確認します。** 係数が出たこと自体も、除外後の写真が十分な情報を持つ保証にはなりません。

## 20. 計算が成功しても、無効な数値なら止める

校正APIが例外を出さずに戻った後、RMS、行列、歪み係数を検査します。

```python
not np.isfinite(rms)
not np.isfinite(matrix).all()
not np.isfinite(distortion).all()
matrix[0, 0] <= 0
matrix[1, 1] <= 0
```

実際にはこれらを `or` で結んだ `if` 文です。どれか1つでも問題があれば、`ValueError("校正係数が不正です。写真を確認してください")` で停止します。

- `np.isfinite(...)` は、値が有限の数値かを調べます。計算不能を表す `NaN` や、無限大 `inf` を除きます。
- 配列に対する `.all()` は、全ての要素が条件を満たすかを1個の真偽値にまとめます。
- `matrix[0, 0]` は0行0列、つまり `fx` です。
- `matrix[1, 1]` は1行1列、つまり `fy` です。
- `<= 0` は0以下かを調べ、正の焦点倍率が得られていない結果を拒否します。

これは明らかに扱えない数値を防ぐチェックです。有限で正の値でも、実カメラに適合しているか、寸法測定に十分かは別の確認が必要です。

## 21. 写真ごとの再投影誤差を計算する

全体のRMSだけでは、1枚だけ読取が悪いことを見落とす可能性があるため、使用した写真ごとの誤差も計算します。

```python
errors: list[float | None] = [None] * len(paths)
```

`list[float | None]` は「小数または `None` を要素に持つリスト」という型注釈です。この `|` は型の選択肢を示す記法で、先ほどのフラグのビットORとは文脈が違います。

`[None] * len(paths)` は、元の入力枚数分だけ `None` が並ぶリストを作ります。除外した写真の位置は最後まで `None` のままにし、使用した写真だけ誤差へ置き換えます。

```python
projected, _ = cv.fisheye.projectPoints(
    points, rotations[index], translations[index], matrix, distortion
)
```

`projectPoints()` は、板上の既知の点を、推定した姿勢とカメラ係数で「画像のどこに写るはずか」へ投影します。この予測位置が `projected` です。戻り値のもう1つはこの処理では使わないため、慣習的に `_` という名前で受け取っています。特別に「受け取らない」命令ではなく、不要な値に付けた変数名です。

続く2行で、予測と実測のずれを求めます。

```python
difference = projected.reshape(-1, 2) - image_points[index].reshape(-1, 2)
error_px = float(np.sqrt(np.mean(np.sum(difference**2, axis=1))))
```

1行目は両方を `(N, 2)` に揃え、同じ点どうしの座標を引きます。`difference[i]` は、その点の `[横方向のずれ, 縦方向のずれ]`、単位pxです。

2行目は、次の順序で内側から計算します。

| 式 | 内容 | 形状・単位 |
| --- | --- | --- |
| `difference**2` | 横ずれ・縦ずれをそれぞれ2乗する | `(N, 2)`、px² |
| `np.sum(..., axis=1)` | 点ごとに横と縦の2乗を足す | `(N,)`、px² |
| `np.mean(...)` | 全ての検出点について平均する | 1個の値、px² |
| `np.sqrt(...)` | 平方根を取る | 1個の値、px |
| `float(...)` | Pythonの小数にする | 1個の `float` |

`**` はべき乗です。`axis=1` は行ごとに列方向を合計する指定です。点を全部ひとまとめに足すのではなく、まず各点の横・縦を組にしています。

数式なら、写真の点数を `N` として次の意味です。

```text
各点の2乗ずれ = (予測u − 検出u)² + (予測v − 検出v)²
写真の誤差px = sqrt(各点の2乗ずれの合計 / N)
```

たとえば、全ての点でずれが横3px・縦4pxなら、1点ごとの2乗ずれは25px²です。その平均の平方根は5pxになります。横ずれと縦ずれを符号付きのまま平均して相殺する計算ではありません。

最後に `input_index = used_indices[index]` で元の入力位置を求め、`errors[input_index] = error_px` に入れます。候補から途中で写真を削除しても、元の写真名に正しい誤差を表示できます。

## 22. RMSの単位と、解釈してはいけないこと

RMSはRoot Mean Square、二乗平均平方根です。この文脈では、予測した画像位置と検出した画像位置のずれをpxで表しています。全体RMSはOpenCVが返し、写真ごとのRMSは前節の式でこのコードが計算しています。

表示されるRMSが `0.3px` だったとしても、「実物の長さが0.3mm以内で正しい」という意味ではありません。実物の寸法誤差には、印刷した板の寸法、板の平面性、検出の偏り、画角の網羅、カメラモデルとの適合、補正先の平面、撮影条件なども関わります。

このRMSは、係数を求めるのに使用した点へ、同じモデルを当てはめた際の誤差です。別の撮影データによる独立した検証結果ではありません。小さい値だけで校正が適切と断定せず、写真ごとの読取確認と、既知寸法の対象による補正後の確認も行います。

また、コードにはRMSのしきい値による自動除外はありません。「この値以上の写真は除く」という数値判定は実装されていません。写真ごとのRMSを単純平均した値が、必ず全体RMSに一致するわけでもありません。写真によって点数が違い、全体では点ごとの二乗ずれを集計するためです。

## 23. `calibrate()` の最後に返す5個の値

使用枚数・スキップ枚数を表示した後、次の値を返します。

```python
return image_size, matrix, distortion, float(rms), errors
```

カンマで並べた5個が、1つのタプルとして呼出元へ戻ります。

| 位置 | 値の例・形 |
| --- | --- |
| 0 | `image_size = (960, 720)`。幅・高さ、px |
| 1 | `matrix`。`(3, 3)` のNumPy配列 |
| 2 | `distortion`。`(4, 1)` のNumPy配列 |
| 3 | `rms`。小数1個、px |
| 4 | `errors`。元入力の枚数と同じ長さ。小数pxまたは `None` |

上のサイズは説明用の例で、使う実カメラの推奨サイズではありません。

## 24. `parameter_text()` は、設定を文字列にする

この関数は、画像サイズ、カメラ行列、歪み係数を受け取り、3行の文字列にします。

```text
def parameter_text(
    image_size: tuple, matrix: np.ndarray, distortion: np.ndarray
) -> str:
```

引数の `tuple` は幅・高さをまとめたタプル、`np.ndarray` はNumPy配列の型名です。末尾の `-> str` は、返す値が文字列であるという型注釈です。計算済みの係数を文字列へ変える関数なので、この中で写真を読み直したり校正をやり直したりはしません。

```python
f"CALIBRATION_SIZE = {image_size!r}\n"
f"CAMERA_MATRIX = {matrix.tolist()!r}\n"
f"DIST_COEFFS = {distortion.ravel().tolist()!r}"
```

ここにある書き方を分けて読みます。

- `f"..."`：変数や式の値を埋め込むf文字列。
- `!r`：値を、Pythonの表現に向いた `repr` 形式で文字列化する指定。
- `\n`：改行を表すエスケープ表記。画面には通常、バックスラッシュとnの2文字ではなく改行として現れる。
- `matrix.tolist()`：NumPy配列を、通常のPythonの入れ子リストへ変える。
- `distortion.ravel()`：4行1列を4要素の1次元配列にする。
- `.tolist()`：その配列を通常のリストへ変える。

`return (...)` の括弧の中に文字列を隣接して並べると、Pythonはそれらをつないで1個の文字列にします。ここでは文字列どうしの間にカンマがないため、3個の要素のタプルではありません。

結果は、次の形になります。数値は形の説明のための仮の例であり、実カメラへコピーする係数ではありません。

```python
CALIBRATION_SIZE = (960, 720)
CAMERA_MATRIX = [[600.0, 0.0, 480.0], [0.0, 610.0, 360.0], [0.0, 0.0, 1.0]]
DIST_COEFFS = [-0.04, 0.005, -0.001, 0.0001]
```

関数はこの文字列を返すだけです。自身ではファイルへ保存せず、表示も呼出元の `print()` が行います。

## 25. `main()` の事前確認と、画像一覧の作成

```python
input_directory = CALIBRATION_DIRECTORY.resolve()
output_directory = DETECTION_DIRECTORY.resolve()
if input_directory == output_directory:
    raise ValueError("入力と出力は別のフォルダにしてください")
```

`resolve()` はパスを絶対パスへ揃えます。`..` などの表現の違いを整理し、同じフォルダを違う書き方で指定していても比較しやすくします。フォルダを作る処理ではありません。

同じ入力・出力フォルダだと、作った確認画像が次の入力へ混ざるなどの問題が起こるため、同じなら停止します。この判定はフォルダが同一かを確認するもので、出力名の重複を全て避ける仕組みではありません。

```python
paths = find_images(input_directory)
```

`find_images()` は共通の画像入出力ファイルにあります。

1. `directory.is_dir()` で入力フォルダが存在するか確認する。
2. `directory.iterdir()` で直下の項目を取り出し、`sorted(...)` で名前順にする。
3. `path.is_file()` と拡張子の条件に合うものをリストへ追加する。
4. 0件なら `ValueError("画像がありません: ...")` で止める。

拡張子を調べる前に `.lower()` するので、`.JPG` のような大文字の拡張子も対象になります。名前順は「文字列としての名前の順序」で、撮影時刻順や数値の自然順とは限りません。番号を名前へ付けるなら `01`、`02` のように桁を揃えると、意図を確認しやすくなります。

## 26. 戻り値を表示し、次の工程へ渡す

```python
image_size, matrix, distortion, rms, errors = calibrate(paths, output_directory)
```

先ほどの5個の戻り値を、左側の5個の変数へ順番に受け取ります。関数の中の変数と、呼出元の変数は、それぞれの有効範囲にある名前です。同じ名前だから自動で伝わったのではなく、戻り値を代入して受け渡しています。

続いて、全体RMSを表示します。`{rms:.4f}` の `:.4f` は、小数点以下4桁の固定小数点表示です。内部の係数や計算済みのRMSの値を4桁へ切り詰めて置き換えているわけではありません。

```python
for path, error in zip(paths, errors):
    if error is not None:
        print(f"  {path.name}: {error:.4f}px")
```

`zip(paths, errors)` は、同じ位置のパスと誤差を組にして取り出します。元入力と同じ長さの `errors` を用意していたため、スキップがあっても対応が保たれます。除外した写真の誤差は `None` なので、この一覧には表示しません。0pxという誤差と `None` は区別されます。

最後に案内と `parameter_text(image_size, matrix, distortion)` の文字列を表示します。使用する[画像ごとの補正スクリプト](../01_rectify_images.py)または[固定カメラの基準画像による補正スクリプト](../01_rectify_frames_from_reference.py)の冒頭へ、3設定をまとめて反映します。

ファイル末尾の次の条件で、直接実行したときだけ `main()` を呼びます。

```python
if __name__ == "__main__":
    main()
```

`__name__` が `"__main__"` かを `==` で比較する条件分岐です。別コードから部品として読み込んだだけで、校正や確認PNGの作成を開始しない構成です。詳しい記法は[Pythonの基礎](python_basics.md)を参照してください。

## 27. スキップして続く失敗と、全体が止まる失敗

| 状況 | この実装の対応 | 確認PNG |
| --- | --- | --- |
| 入力フォルダがない | 全体を停止 | 作らない |
| 対応拡張子の画像がない | 全体を停止 | 作らない |
| 入力・出力が同じフォルダ | 全体を停止 | 作らない |
| 画像を読み込めない | その写真をスキップ | 作れない |
| 角が6点未満、または共線 | その写真をスキップ | NGで保存 |
| 最初の採用写真と解像度が異なる | その写真をスキップ | NGで保存 |
| 校正が所定の英文で不安定な写真番号を報告 | その写真を除いて再計算 | 検出時のOKが残る場合がある |
| 写真が全て除外された | 全体を停止 | それまでの確認PNGは残る |
| 想定外の校正エラー、番号の対応が取れない | 原因の例外をつないで全体を停止 | それまでの確認PNGは残る |
| NaN・無限大・0以下の焦点倍率 | 全体を停止 | それまでの確認PNGは残る |
| 確認PNGの変換・書込に失敗 | 全体を停止 | それ以前の出力は残り得る |

処理全体を一括で取り消す仕組みはありません。後半で停止しても、先に作成した確認PNGは残ります。再実行時は同名の確認PNGを置き換えますが、入力から削除した写真の古い確認PNGを掃除する処理はありません。フォルダ内の画像だけで今回の採否を推測せず、今回のターミナル表示と対応させて確認します。

## 28. 安全に変更しやすい場所と、慎重に扱う場所

| 変更対象 | 変更場所・影響 |
| --- | --- |
| 校正写真を置くフォルダ | `workflow_settings.py` の `CALIBRATION_DIRECTORY`。入力と出力を別にする |
| 確認PNGの保存先 | 同ファイルの `DETECTION_DIRECTORY`。既存の確認結果を残したい場合は別の保存先を使う |
| 板のマス数・寸法 | 同ファイルの `BOARD_SQUARES`、`SQUARE_MM`、`MARKER_MM`。実物の印刷を一致させ、生成・校正・補正で揃える |
| マーカー辞書 | 生成側と検出する側の両方。実物の模様を変える変更になる |
| 反復回数・終了許容値 | 校正呼出の `criteria`。大きく・小さくすれば実寸精度が保証される設定ではない |
| 校正の点数条件・フラグ・配列の形 | 点対応とAPIの要件に関わる。エラーを消すためだけに条件を外したり形を変えたりしない |

写真ごとのRMSが大きい場合は、まず確認PNGで角が期待する位置へ重なっているかを確かめ、ブレ、反射、板の反り、印刷寸法、写真の撮影条件を確認します。現在のコードにないRMS基準の自動除外や、通常レンズモデルへの切替が必要になれば、それは別の実装変更になります。
