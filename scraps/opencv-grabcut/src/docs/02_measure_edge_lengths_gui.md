この章は、補正済み画像から試料を取り出し、試料の左右の側辺を一定の区間で測るプログラムを説明します。「画面を操作すると何が起こるか」と「画像や数値をどのように計算するか」の両方を扱います。長いプログラムなので、最初から全行を覚える必要はありません。まず処理全体を読み、実際の関数を開きながら、対応する節へ戻ってください。

ここで説明するのは、現行の `src/02_measure_edge_lengths_gui.py` です。区間は **基準区間長の mm 入力と中心の 1 点指定**で決まり、多角形は **「多角形を確定」ボタン**で確定します。以前の矩形指定や上下 2 点の直接指定とは操作が異なります。

## 1. このプログラムが測るもの

入力は、前の工程でレンズ歪みと遠近を補正し、1 px が何 mm に当たるかを揃えた画像です。`MM_PER_PX` は現在 `0.25` なので、補正画像の 4 px が 1 mm に相当します。このプログラム自身がカメラの校正や画像の遠近補正をやり直すわけではありません。

画面の左側に現れる試料の側辺を DR、右側を OP と表示します。CSV の列名では、それぞれ `left_*`、`right_*` と呼びます。これは画像上で決めた呼び方です。圧延の進行方向を読み取って毎回左右を交換する処理はありません。

測定の考え方は次のとおりです。

1. 人が多角形を描き、試料らしい場所と背景らしい場所を教える。
2. GrabCut が画素の色などを使って試料と背景を分ける。
3. 試料の外周を取り出す。
4. 指定した区間内の形から、試料の長手方向を推定する。
5. 長手方向に直角な 2 本の断面で、左右の側辺を切り出す。
6. 切り出した側辺の細かな画素の階段をならし、点と点の距離を足す。
7. px を mm に換算し、基準区間長からの超過率を出す。
8. 数値を CSV、指定と測定線を PNG へ保存する。

```text
補正済み画像 + 確定した多角形
                │
                ▼
        extract_specimen()
         試料の外周と処理範囲
                │
  中心 + 区間長 ├── estimate_axis() / manual_axis()
                │           長手軸
                ▼
          side_chains()
      2 断面間の連続した左右側辺
                │
                ▼
         smoothed_sides()
      弧長に沿う再配置と局所平滑化
                │
                ▼
         measure_contour()
        長さ・超過率の辞書
                │
                ▼
        write_measurement()
         CSV + 確認 PNG 2 枚
```

測っているのは、画像から抽出した **外周側辺の長さ**です。個々のクラックの位置、本数、深さ、開口幅を直接検出・計測する処理はありません。側辺に写る凹凸とクラックとの関係を検討するときも、この区別が必要です。

### 3.2 計算に使う設定

```python
ITERATIONS = 5
RANDOM_SEED = 0
EVALUATION_INTERVAL_MM = 1.0
SMOOTHING_WIDTH_MM = 2.0
GRABCUT_MARGIN_RATIO = 0.1
```

| 名前 | 単位・役割 |
| --- | --- |
| `ITERATIONS` | GrabCut の繰り返し回数。現在 5 回 |
| `RANDOM_SEED` | GrabCut が使う乱数の出発点。比較しやすいように毎回 0 へ設定 |
| `EVALUATION_INTERVAL_MM` | 生の側辺に沿って評価点を置く間隔。現在 1 mm |

| `GRABCUT_MARGIN_RATIO` | 前景を囲む範囲に加える余白の割合。現在は幅・高さの 10% |

大文字で書かれた名前は、「通常は実行中に変更しない設定」という意図を表します。Python が大文字の変数への代入を禁止するわけではありません。変更したら GUI を起動し直します。

`MM_PER_PX` を変更した場合は、同じ倍率の補正画像を作り直す必要があります。数値だけ変えて元の画像を使い続けると、px から mm への換算が合わなくなります。

### 3.3 `type` で作る名前

```python
type PolygonRatios = list[tuple[float, float]]
type Axis = tuple[np.ndarray, np.ndarray]
```

`PolygonRatios` は、「小数の組 `(x の比率, y の比率)` を並べたリスト」という型の説明に付けた名前です。例えば次の値です。

```python
[(0.2, 0.1), (0.8, 0.1), (0.8, 0.9), (0.2, 0.9)]
```

`Axis` は、NumPy 配列を 2 つ組にしたものです。1 つ目が軸上の基準点 `origin`、2 つ目が軸の向きを示す `direction` です。この型名を作ることで、すべての関数に長い型の説明を繰り返さずに済みます。新しい画像データや独自のクラスを作っているわけではありません。

関数名の後の `-> np.ndarray` は「NumPy 配列を返す想定」、`-> None` は「返り値として結果を渡す用途ではない」という説明です。型注釈だけですべての不正な値を自動で防げるわけではないため、計算に必要な確認は関数内にも書かれています。

## 4. NumPy 配列と座標を先に理解する

### 4.1 画像配列の添字は `y, x`

OpenCV で読んだカラー画像 `image` は、概ね次の形の配列です。

```text
image.shape == (高さ, 幅, 色の数)
例: (800, 1600, 3)
```

`image[100, 200]` は `y=100, x=200` の画素を表します。一方、点の座標としては `(x, y)` を使います。この順番の違いに注意してください。

```python
height, width = image.shape[:2]
```

`[:2]` は先頭から 2 つの値を取り出すスライスです。`(800, 1600, 3)` から `(800, 1600)` を取り、その順に `height` と `width` へ代入します。

画像は左上が `(0, 0)` です。右へ進むほど `x` が増え、下へ進むほど `y` が増えます。幅 1600 の画像の最後の x 座標は 1599 です。これが、比率から座標へ戻すときに `width - 1` を使う理由です。

### 4.2 点を並べた配列は `N × 2`

輪郭 `contour` は次のような形です。

```text
[[x0, y0],
 [x1, y1],
 [x2, y2],
 ...]
```

`contour[:, 0]` は全点の x 座標、`contour[:, 1]` は全点の y 座標です。`:` は「その方向の全部」を意味します。`contour[-1]` は最後の点、`contour[[0, -1]]` は先頭と末尾の 2 点です。

`np.asarray(value, dtype=np.float64)` は、リストなどを計算用の配列として扱い、数値を倍精度の小数に揃えます。元の値が条件に合った配列なら、必ず別のコピーを作るとは限りません。画像を変更せず別の作業用配列にしたいところでは、明示的に `.copy()` が使われています。

### 4.3 `True` / `False` を並べたマスク

```python
initial_foreground = (labels == cv.GC_FGD) | (labels == cv.GC_PR_FGD)
```

`labels` は画素ごとに「背景」「前景」などの番号を持つ配列です。`labels == cv.GC_FGD` は、それぞれの画素で条件を調べ、同じ大きさの `True` / `False` 配列を返します。

ここで `|` は、配列の各要素についての「または」です。`&` は各要素についての「かつ」です。普通の `if` で使う `or` / `and` と、配列用の `|` / `&` は使い分けます。比較を括弧で囲んでいるのも、計算の順番を明確にするためです。

```python
raw_mask = np.zeros(labels.shape, np.uint8)
raw_mask[extracted_foreground] = 255
```

最初はすべて 0 の配列を作り、`extracted_foreground` が `True` の場所だけ 255 にします。これは「試料の場所が白、残りが黒」の 1 チャンネル画像です。`np.uint8` は 0〜255 を表せる整数型です。

`.any()` は「1 つでも `True` があるか」、`.all()` は「すべて `True` か」です。`any(axis=1)` は各行について横方向に調べ、`any(axis=0)` は各列について縦方向に調べます。同じ `axis` という単語でも、この NumPy の引数は「配列のどの方向をまとめるか」であり、試料の長手軸とは別です。

## 5. 多角形から初期指定画像を作る関数

### 5.1 `polygon_pixels()`：比率を画像の整数座標へ戻す

多角形の頂点は `0.0`〜`1.0` の比率で保存します。画面で拡大しても、画像そのものの位置を保つためです。

```python
pixels = np.rint(points * (width - 1, height - 1)).astype(np.int32)
```

例えば幅 101、高さ 201 なら、`(0.25, 0.5)` は `(25, 100)` になります。NumPy は各行の x へ 100、y へ 200 を掛けます。このように、形の合う小さな配列を各行へ適用する動作をブロードキャストと呼びます。

`np.rint()` は近い整数へ丸め、`.astype(np.int32)` は OpenCV に渡す整数の座標配列へ変換します。丸める前は小数の座標でも、マスクを塗るときは画素位置が必要です。

その前に次を確認します。

- 2 次元配列で、各点が x・y の 2 個の値を持つか。
- 頂点が 3 個以上あるか。
- `nan` や `inf` など、普通の有限な数でない値がないか。
- 比率が 0〜1 に入っているか。
- 整数座標へ変換した後の面積が 1 px² 以上あるか。

面積が不足すれば、同じ点ばかりを置いた場合や一直線に並べた場合などを拒否できます。ただし、この関数が多角形の自己交差や全頂点の重複を個別に検査しているわけではありません。試料を一周する順に、形の分かる多角形を指定します。

### 5.2 `initial_mask()`：画素ごとに GrabCut の分類番号を入れる

最初に全画素を `cv.GC_PR_BGD`、つまり「背景候補」にします。

```python
labels = np.full((height, width), cv.GC_PR_BGD, np.uint8)
```

その後、確定済みの多角形を `cv.fillPoly()` で塗ります。

| ラベル | 現行の数値 | 意味 | 初期指定画面の色 |
| --- | ---: | --- | --- |
| `cv.GC_BGD` | 0 | 確実な背景 | 青 |
| `cv.GC_FGD` | 1 | 確実な前景 | 緑 |
| `cv.GC_PR_BGD` | 2 | 背景候補 | 灰色 |
| `cv.GC_PR_FGD` | 3 | 前景候補 | 橙 |

処理する順番は「前景候補 → 確実な背景 → 確実な前景」です。同じ画素へ多角形が重なれば、後の種類が上書きします。これはクリックした時刻順ではなく、コードに書かれたラベル順です。

`regions` は次のような辞書です。

```text
ラベル番号 → その種類の多角形のリスト
```

各種類の多角形は複数持てます。ただし、複数の試料をそれぞれ測る仕組みではありません。同じ試料を抽出するための初期指定を複数置ける仕組みです。

### 5.3 `initial_overlay()`：元画像へ色を薄く重ねる

```python
color_mask = PALETTE[labels]
overlay = cv.addWeighted(image, 0.65, color_mask, 0.35, 0)
```

`PALETTE` は「ラベル番号 → 色」の対応表です。`PALETTE[labels]` はラベル番号が書かれた各画素を、その番号に対応した 3 色の値へ置き換えます。

重ね合わせは、おおよそ「元画像の色 × 0.65 + 指定色 × 0.35」です。画像の内容を見ながら指定範囲も確認できます。これは表示・保存用の色付けです。GrabCut の入力へこの着色画像を渡すわけではありません。

OpenCV の色順は BGR、すなわち青・緑・赤です。例えば `(0, 0, 255)` は赤になります。Tkinter の `#rrggbb` 表示とは順番が違うため、色見本を作る部分では `blue, green, red` と受け取って並べ直します。

### 5.4 `draw_edge_names()`：DR・OP の文字を直接画像に描く

左右に黒い四角と白い文字を描きます。この関数は受け取った画像配列をその場で変更し、別の画像を返しません。そのため返り値の型が `None` です。

同じ「描く」でも、後述の `canvas.create_text()` は GUI 部品へ文字を置き、ここでの `cv.putText()` は保存できる画像の画素を書き換えます。

## 6. `extract_specimen()`：試料を抽出し、最大の外周を選ぶ

この関数は `(contour, bounds)` の 2 つを返します。`contour` は元画像座標の輪郭点列、`bounds` は処理範囲の `(left, top, right, bottom)` です。

### 6.1 前景の候補があるか確認する

`initial_mask()` でラベルを作り、「確実な前景または前景候補」を `True` にします。前景が 1 画素もなければ試料の手がかりがありません。逆に全部が前景なら、その外の背景を判断する手がかりがありません。この 2 条件は `ValueError` で停止します。

### 6.2 処理する範囲を前景の周辺へ絞る

```python
foreground_y = np.flatnonzero(initial_foreground.any(axis=1))
foreground_x = np.flatnonzero(initial_foreground.any(axis=0))
```

前景がある行番号と列番号を取り出します。`np.flatnonzero()` は「0 ではない、つまりこの場合 `True` の位置の番号」を返します。最小・最大から、前景を囲む長方形を求めます。

`right` と `bottom` は最大座標へ 1 を足します。Python の `image[top:bottom, left:right]` は、終わりの番号を含めないためです。例えば x=20〜29 を含める切り出しは `20:30` です。

余白は次で決まります。

```python
margin_x = max(10, math.ceil((right - left) * GRABCUT_MARGIN_RATIO))
```

前景の幅が 200 px なら、10% は 20 px なので左右に 20 px ずつ加えます。幅が 50 px なら 10% は 5 px ですが、最低値の 10 px を使います。y 方向も同様です。`ceil()` は小数があれば切り上げます。加えた範囲が画像をはみ出さないよう、0、幅、高さで制限します。

```python
working_image = image[top:bottom, left:right].copy()
labels = labels[top:bottom, left:right].copy()
```

GrabCut はこの範囲だけで実行します。画像を縮小したのではなく、元の画素の一部を切り出しています。したがって 1 px の物理的な大きさは変わりません。範囲の外に指定した確実な背景などは、この GrabCut には入りません。

### 6.3 GrabCut を実行する

```python
background_model = np.zeros((1, 65), np.float64)
foreground_model = np.zeros((1, 65), np.float64)
cv.setRNGSeed(RANDOM_SEED)
labels, _, _ = cv.grabCut(
    working_image,
    labels,
    (0, 0, 0, 0),
    background_model,
    foreground_model,
    ITERATIONS,
    cv.GC_INIT_WITH_MASK,
)
```

GrabCut は「前景・背景の色の傾向」と「隣り合う画素の関係」を使って分類を更新する手法です。人の指定が出発点になり、前景候補・背景候補の分類を計算します。モデル配列は OpenCV がこの計算で使う作業領域です。`65` は OpenCV の API が求める形で、画像の幅や試料の寸法ではありません。

`cv.GC_INIT_WITH_MASK` は、長方形から初期化する代わりに、すでに作ったラベル画像から初期化する指定です。したがって長方形引数の `(0, 0, 0, 0)` で試料の位置を教えているわけではありません。

返り値は複数ありますが、このコードが後で使うのは更新後の `labels` です。`_` は「この値は使わない」という意図で使う慣習的な変数名です。

### 6.4 白黒マスクから外周を取り出す

更新後のラベルから、確実な前景と前景候補を白にします。その白い領域の輪郭を求めます。

```python
contours, _ = cv.findContours(raw_mask, cv.RETR_EXTERNAL, cv.CHAIN_APPROX_NONE)
```

`RETR_EXTERNAL` は最も外側の輪郭を対象にします。試料の内側に完全に囲まれた穴の輪郭を、側辺として測る設定ではありません。`CHAIN_APPROX_NONE` は輪郭点を大きく間引かずに保持する指定です。

輪郭が複数ある場合は、`cv.contourArea()` で面積を比べ、最大のものを 1 つ選びます。「最も長い線」や「画面中央に最も近いもの」を選んでいるわけではありません。前景に別の大きな物体が混ざれば、そちらを選ぶ可能性があります。多角形の指定と結果画像の確認が必要なのはこのためです。

### 6.5 元画像の座標へ戻す

```python
points = contour.reshape(-1, 2).astype(np.float64)
points += (left, top)
```

OpenCV の輪郭配列の形を、以後使いやすい `N × 2` にします。`-1` は「もう一方の大きさに合うよう自動で決める」という指定です。

切り出し画像で `(30, 40)` の点でも、切り出し位置が元画像の `(500, 100)` なら、元画像では `(530, 140)` です。`points += (left, top)` で全点にこの補正を加えます。以後の中心指定、軸、側辺、確認 PNG は元画像座標で統一できます。

現行コードでは、GrabCut と輪郭抽出の間に膨張・収縮・opening・closing といったモルフォロジー処理は入っていません。後で行う「側辺の平滑化」は、抽出済みの点列を対象にする別の処理です。

## 7. 長手軸、直角方向、固定長区間

### 7.1 `manual_axis()`：2 点を軸の表現へ変える

入力は `[[x1, y1], [x2, y2]]` の 2 点です。関数名は手動軸ですが、自動推定の途中でも軸の表現を揃えるために使います。

```python
direction = points[1] - points[0]
length = float(np.linalg.norm(direction))
direction /= length
```

例えば 2 点が `(100, 100)` と `(130, 140)` なら、差は `(30, 40)`、長さは `sqrt(30² + 40²) = 50`、割った後の方向は `(0.6, 0.8)` です。長さが 1 の方向ベクトルを、単位ベクトルと呼びます。これに 100 を掛けると、その方向へ 100 px 進む量になります。

`direction /= length` は `direction = direction / length` に似た意味の複合代入です。この NumPy 配列の要素を長さで割ります。

2 点が同じか 1 px 未満しか離れていれば、安定した方向を決められないため拒否します。値が有限か、配列の形が `(2, 2)` かも確認します。

方向には符号の問題があります。同じ直線でも、上から下へ向くベクトルと、下から上へ向くベクトルは逆符号です。そのままだとクリック順で左右の定義まで逆になります。

```python
if direction[1] < 0 or (direction[1] == 0 and direction[0] < 0):
    direction = -direction
```

画像の下向き、すなわち y 成分が正になるよう揃えます。完全に横向きなら x 成分が正になる方を使います。返す `origin` は 2 点の平均、つまり中点です。

```python
return points.mean(axis=0), direction
```

### 7.2 `@` は、ここでは内積を計算する

軸上の基準点を `origin`、長さ 1 の方向を `direction` とします。

```python
positions = (points - origin) @ direction
```

`@` は NumPy 配列の行列積に使う演算子です。この形では、各点から基準点への差と方向ベクトルの内積になります。

```text
位置 = (点の x - 基準の x) × 方向の x
     + (点の y - 基準の y) × 方向の y
```

先ほどの方向 `(0.6, 0.8)` に対し、基準点からの差が `(30, 40)` なら `30×0.6 + 40×0.8 = 50` です。その点は軸方向に 50 px 先にあります。

方向が `(0, 1)` なら、結果は y 座標の差です。斜めの軸にも同じ式を使えるので、「上下の y 差」で測る実装にする必要がありません。

### 7.3 `interval_positions()`：区間の両端を軸上の位置へ変える

区間を表す 2 点を軸へ投影し、`sorted()` で小さい順の `start, end` にします。これは画像の y 座標を並べ替えているのではありません。

軸方向の距離が 1 px 未満なら拒否します。例えば 2 点が画像上では離れていても、その差がすべて軸と直角の方向なら、軸方向の距離は 0 です。

### 7.4 `fixed_interval_points()`：中心と mm から区間を作る

```python
length_px = length_mm / MM_PER_PX
half_interval = axis[1] * length_px / 2
return np.array([center - half_interval, center + half_interval])
```

中心が `(600, 500)`、基準区間長が 100 mm、倍率が 0.25 mm/px、軸方向が `(0, 1)` なら、全長は 400 px、半分は 200 px です。返る点は `(600, 300)` と `(600, 700)` です。

軸方向が `(0.6, 0.8)` なら、半分の移動量は `(120, 160)` なので、返る点は `(480, 340)` と `(720, 660)` です。y 差は 320 px ですが、軸方向の距離は 400 px で、100 mm を保ちます。

中心の形と有限性、倍率が正、区間長が正、px 換算後に 1 px 以上あることを確認します。画像・試料に収まるかは、この関数単独では判定しません。後の輪郭との交点・側辺の切り出しで判定し、収まらない長さを勝手に短くしません。

### 7.5 直角方向 `normal`

```python
normal = np.array([direction[1], -direction[0]])
```

方向 `(a, b)` に対して `(b, -a)` は直角です。内積は `a×b + b×(-a) = 0` になります。もとの方向の長さが 1 なら、この方向も長さ 1 です。

軸が下向き `(0, 1)` なら `normal` は右向き `(1, 0)` です。この方向の座標が小さい側を DR、大きい側を OP として揃えます。軸の符号を固定する理由も、この左右の順番を維持することにあります。

点は、軸に沿う量 `along` と軸を横切る量 `across` に分けて扱えます。

```python
relative = contour - origin
along = relative @ direction
across = relative @ normal
```

これにより、画像が斜めでも、軸に直角な断面は「`along` が一定の線」として計算できます。

## 8. `section_edges()`：断面と輪郭の交点を求める

この関数は、指定した軸方向の各位置で、DR 側と OP 側の輪郭位置を求めます。返り値は、断面数が N なら `N × 2` の配列です。値は画像の x 座標ではなく、`normal` 方向の座標です。

### 8.1 隣り合う輪郭点を線分として扱う

`contour` は一周する順番に並んでいます。先頭と末尾もつながった閉じた輪郭です。

```python
next_along = np.roll(along, -1)
next_across = np.roll(across, -1)
```

`np.roll(..., -1)` は値を 1 つずらし、最後に元の先頭を回します。

```text
along      = [10, 20, 30, 40]
next_along = [20, 30, 40, 10]
```

同じ番号の `along` と `next_along` が、1 本の輪郭線分の両端です。

### 8.2 断面をまたぐ線分を選ぶ

```python
crosses = ((along <= position) & (position < next_along)) | (
    (next_along <= position) & (position < along)
)
```

線分が上から下へ進む場合も、その逆も拾います。片端は `<=`、もう片端は `<` の半開区間にしてあります。断面がちょうど輪郭の頂点を通ったとき、同じ交点を隣の線分と二重に数えにくくするためです。

ここで `crosses` は線分ごとの `True` / `False` 配列です。`along[crosses]` は、断面をまたぐ線分の始点の値だけを選びます。

### 8.3 交点を線形補間する

```python
fraction = (position - along[crosses]) / (next_along[crosses] - along[crosses])
intersections = across[crosses] + fraction * (
    next_across[crosses] - across[crosses]
)
```

軸方向の位置が 10 から 20 へ変わる線分と、位置 15 の断面なら、割合 `fraction` は 0.5 です。横方向が 30 から 34 なら、交点は 32 です。輪郭点が整数画素でも、交点は小数で持ちます。

### 8.4 交点を左右に並べ、試料が存在する幅を調べる

交点を小さい順に並べ、2 個ずつ組にします。

```python
intersections.sort()
spans = intersections.reshape(-1, 2)
spans = spans[spans[:, 1] - spans[:, 0] > 1e-7]
```

例えば `[-40, 50]` なら、試料がある区間は 1 つです。`[-40, -10, 10, 50]` なら、`[-40, -10]` と `[10, 50]` の 2 区間です。頂点に接するだけで幅がほぼ 0 の組は除きます。`1e-7` は `0.0000001` で、計算誤差程度の微小な値を判断するためのしきい値です。

`outermost=False` が通常の厳しい判定です。試料の幅がちょうど 1 区間にならなければ、「左右 1 本ずつの側辺」を一意に取れないとして止めます。測定区間の上下の断面で使います。

`outermost=True` は自動軸推定用です。複数区間があっても最も左と最も右の交点を使います。軸を決める途中の内部断面に張り出しや凹凸があっても、外側の幅の中点を使うためです。ただし試料がまったくない断面は許可しません。

### 8.5 切り出し範囲の端に接していないか確認する

交点を画像の x・y 座標へ戻し、`bounds` の端に接していないか調べます。端を切り落とした輪郭を本来の側辺と誤認しないためです。右・下の範囲はスライスの終端なので、`right - 1`、`bottom - 1` が最後の画素に当たることも考慮した判定です。

この失敗が出た場合は、前景候補を広げる、適切な画像範囲を撮る、区間の中心を変える、といった修正が必要です。

## 9. `estimate_axis()`：区間内の断面中点へ直線を当てはめる

試料全体の外周へ一度だけ直線を当てる処理ではありません。指定した区間内の複数断面から中点を取り、その中点群へ直線を当てはめます。区間外の曲がりの影響を減らす意図です。

### 9.1 最初の方向と、3 回の繰り返し

最初に `manual_axis(interval_points)` で仮の軸を作ります。GUI から呼ぶときは、指定中心を通る縦向き `(0, 1)` の区間が出発点です。

```text
for _ in range(3):
```

3 回、次の処理を繰り返します。`_` は回数の番号自体を使わないことを示します。収束するまで無制限に繰り返す処理ではありません。

`fixed_length_mm` が与えられていれば、各回の冒頭で `fixed_interval_points()` を呼びます。軸が傾くたびに、最初の画像上の上下点をそのまま投影すると区間が短くなってしまうので、指定中心と指定 mm を保って点を置き直します。

### 9.2 断面を 3〜101 個置く

```python
count = min(101, max(3, math.ceil(end - start) + 1))
positions = np.linspace(start, end, count)
```

`linspace()` は両端を含む等間隔の値を `count` 個作ります。区間が長くても最大 101 個、短くても最低 3 個です。これらは軸推定用の断面であり、後の `EVALUATION_INTERVAL_MM` による側辺の評価点とは別です。

### 9.3 外側交点の中点を画像座標へ戻す

```python
edges = section_edges(contour, bounds, axis, positions, outermost=True)
midpoints = (
    origin
    + positions[:, None] * direction
    + edges.mean(axis=1)[:, None] * normal
)
```

`edges.mean(axis=1)` は各断面の DR・OP 位置の平均です。例えば左右が -40 と 50 なら中点は 5 です。

`positions[:, None]` の `None` は配列の軸を 1 つ追加し、形 `(N,)` を `(N, 1)` にします。これに形 `(2,)` の `direction` を掛けると `(N, 2)` になり、各断面の画像上の座標をまとめて作れます。

### 9.4 `cv.fitLine()` で中点群の長手方向を求める

```python
vx, vy, x, y = cv.fitLine(
    midpoints.astype(np.float32), cv.DIST_L2, 0, 0.01, 0.01
).ravel()
```

`cv.fitLine()` は点群へ直線を当てはめる関数です。`DIST_L2` は点と直線の距離を二乗した量に基づく当てはめです。x を入力して y だけの誤差を最小化する単純な `y=ax+b` とは異なり、縦向きの直線も方向ベクトルとして扱えます。

返る `(vx, vy)` が向き、`(x, y)` が直線上の点です。`.ravel()` は並びを 1 次元にして 4 つの変数へ受け取りやすくします。

次に `(x, y)` と、そこから方向へ 100 px 進んだ点を作り、再び `manual_axis()` に渡します。100 は方向を表すための仮の距離で、100 mm の測定区間を指定しているわけではありません。`manual_axis()` により、向きの長さと符号が共通の規則へ揃います。

このコードは `np.linalg` などで PCA を直接計算している実装ではありません。ここで実際に呼ぶのは `cv.fitLine()` です。

推定が失敗しても、輪郭の抽出だけは成功している場合があります。その場合、GUI では手動 2 点で軸を指定し直せます。極端な曲がりや、おおむね縦向きという初期条件に合わない試料に対し、自動推定が必ず成功するとは限りません。

## 10. `side_chains()`：輪郭に沿う連続した左右側辺を切り出す

ここは「断面ごとの外側の点をつないで長さを測る」処理ではありません。外周の並びをたどり、上下の断面に挟まれた **連続する輪郭線**を切り出します。内部に折り返す凹凸があっても、輪郭の経路を保持するためです。

### 10.1 まず上下断面を検査する

```python
section_edges(contour, bounds, axis, np.array([start, end]))
```

`outermost` を指定していないので既定値の `False` です。上下それぞれで試料の幅が 1 区間になることを確認します。内部の全断面へこの厳しい条件を課しているわけではありません。

### 10.2 各輪郭線分を区間で切る

```python
next_index = (index + 1) % len(contour)
```

`%` は割った余りです。最後の番号の次は 0 となり、末尾から先頭への閉じる線分も扱えます。

線分は、割合 `t` を使って次で表せます。

```text
点(t) = 始点 + t × (終点 - 始点)   0 ≤ t ≤ 1
```

軸方向の位置も同じ割合で変わります。そこで、上下断面に達する割合を計算します。

```python
first_cut = (start - first) / (last - first)
last_cut = (end - first) / (last - first)
enter = max(0.0, min(first_cut, last_cut))
leave = min(1.0, max(first_cut, last_cut))
```

例えば軸方向に 0→10 と進む線分を、区間 3〜8 で切るなら `enter=0.3`、`leave=0.8` です。10→0 の逆向きでも、`min` / `max` で線分の進む順に揃えます。0〜1 の外は線分の外なので制限します。`leave <= enter` なら残る長さがないので `continue` で次へ進みます。

`last - first` がほぼ 0、つまり線分が断面と平行な場合は、割り算の代わりに、その線分全体が区間内かを判定します。

### 10.3 つながる線分を 1 本の chain にまとめる

切り出した線分の始点が、現在の点列の末尾と一致していれば追加します。一致しなければ、別の連続部分として新しい点列を始めます。

```python
np.allclose(current_chain[-1], clipped_start, atol=1e-7, rtol=0)
```

小数計算では同じ点でも微小な誤差が出るため、完全な `==` ではなく許容差付きで比べます。`atol` が絶対誤差、`rtol=0` は値の大きさに比例する誤差を加えない指定です。

輪郭の最初の点が測定区間内にあると、同じ側辺が配列の末尾側と先頭側に分かれる場合があります。最後の chain の末尾と最初の chain の先頭が一致すれば、`np.concatenate()` で結合します。結合点が重複しないよう `chains[0][1:]` として先頭点を 1 つ除きます。

最終的な chain が 2 本でなければ、左右の側辺として扱えないので止めます。

### 10.4 上から下、DR から OP の順へ揃える

まず各 chain の進む方向を調べ、軸に対して逆向きなら `chain[::-1]` で点の順序を逆にします。`[::-1]` は「末尾から 1 つずつ逆順に取る」スライスです。

両端を軸方向へ投影し、確かに `start` と `end` に達していることを確認します。さらに両端だけでなく chain 全体について処理範囲の端への接触を検査します。

最後に `normal` 方向の位置を比べ、先頭が DR、次が OP になるよう `chains.reverse()` で 2 本の順番を揃えます。点列の向きを逆にする `chain[::-1]` と、左右 2 本の順番を逆にする `chains.reverse()` は別の操作です。

## 11. `smoothed_sides()`：弧長で評価点を置き、局所直線で平滑化する

画素の輪郭をそのまま足すと、斜めの直線が横・縦・斜めの細かな段差として表れ、長さを大きく評価することがあります。そこで、輪郭に沿う距離で評価点を置き、必要に応じて近くの点から位置をならします。

この処理は側辺を必ず真っすぐに直すものではありません。窓より大きな凹凸は残り、細かい凹凸は短くなる場合があります。そのため評価間隔と平滑化幅は、比較する画像で揃える必要があります。

### 11.1 設定を px へ換算する

倍率と評価間隔は有限な正の値、平滑化幅は有限な 0 以上の値であることを確認します。

```python
step = EVALUATION_INTERVAL_MM / MM_PER_PX
half_window = SMOOTHING_WIDTH_MM / MM_PER_PX / 2
```

現在の設定では `step=4 px`、窓の半幅 `half_window=4 px` です。窓の全幅は 8 px、すなわち 2 mm です。

ここでいう px は、画像の x 差や y 差ではなく、**生の側辺をたどった距離**です。基準区間長の「軸方向の距離」と混同しないでください。

### 11.2 生の輪郭の累積距離を作る

```python
raw_steps = np.linalg.norm(np.diff(chain, axis=0), axis=1)
distances = np.concatenate(([0.0], np.cumsum(raw_steps)))
```

`np.diff(chain, axis=0)` は隣り合う点の差です。`np.linalg.norm(..., axis=1)` は各差の長さを求めます。`np.cumsum()` は前から順に足した累積和です。

例えば点が `(0, 0)`、`(3, 4)`、`(6, 4)` なら、各距離は 5 と 3、先頭からの累積距離は `[0, 5, 8]` です。このように曲線・折れ線に沿って測った距離を弧長と呼びます。

### 11.3 評価位置を置き、最後の端点も含める

```python
positions = np.append(np.arange(0, distances[-1], step), distances[-1])
```

側辺の長さが 10 px、`step=4` なら `[0, 4, 8, 10]` です。`np.arange()` は通常、終わりの値を含めないので、最後に側辺の終端を必ず加えます。最後の評価間隔だけ設定値より短くなることがあります。

評価点が 3 点未満なら停止します。例えば非常に短い区間に対して評価間隔を大きくしすぎると、この条件に達します。入力した基準区間長が 1 px 以上という条件だけでは、測定まで成功するとは限らない理由です。

### 11.4 平滑化用にほぼ等間隔の点列を作る

元の輪郭では水平・垂直の 1 歩と斜めの 1 歩の距離が違います。そこで、累積距離を横軸として、均等な弧長位置へ x と y をそれぞれ補間します。

```python
dense_points = np.column_stack(
    (
        np.interp(dense_positions, distances, chain[:, 0]),
        np.interp(dense_positions, distances, chain[:, 1]),
    )
)
```

`np.interp()` は隣り合う既知点の間を直線で補います。先ほどの例で累積距離 2.5 の点なら、最初の 5 px の半分なので `(1.5, 2)` です。

`np.column_stack()` は x の列と y の列を横に並べ、再び `N × 2` の点列を作ります。密な点列の間隔は `min(1.0, step)` px 以下になるよう個数を決めています。

### 11.5 各評価点の前後を選ぶ

```python
nearby = np.abs(dense_positions - position) <= half_window + 1e-8
```

評価したい弧長位置から、窓の半幅以内にある点を選びます。`np.abs()` は絶対値です。例えば位置 20 px、半幅 4 px なら、16〜24 px の範囲です。

端点の近くでは側辺の外へ点を作らず、存在する側だけを使います。平滑化幅が 0 の場合、または窓内の点が 3 点未満の場合は、局所直線の計算をせず、生の側辺を直接補間した点を使います。後者では、平滑化幅が正でもその評価点だけ補間になります。

### 11.6 最小二乗で局所直線を当てる

```python
offsets = dense_positions[nearby] - position
matrix = np.column_stack((np.ones(len(offsets)), offsets))
coefficients, _, _, _ = np.linalg.lstsq(
    matrix, dense_points[nearby], rcond=None
)
points[index] = coefficients[0]
```

注目位置からの弧長差を `offset` として、次の 2 本の式を近傍の点へ当てはめます。

```text
x = a_x + b_x × offset
y = a_y + b_y × offset
```

`matrix` の各行は `[1, offset]` です。`np.linalg.lstsq()` は、これらの式と点の位置とのずれが小さくなる係数を求めます。`dense_points[nearby]` の x・y の 2 列を同時に渡しているので、返る係数も x・y について得られます。

注目位置は `offset=0` なので、必要な位置は傾きの項ではなく切片 `a_x, a_y` です。これが `coefficients[0]` です。

単純に窓内の点を平均するだけだと、端点では片側の点しかなく、点が区間内へ引き寄せられやすくなります。局所直線なら、直線上の点列の向きを保ちながら端の位置を推定できます。ただし、凹凸に対する形の変化そのものがなくなるわけではありません。

### 11.7 平滑化後の端点を元の断面へ戻す

```python
correction = position - np.dot(points[index] - origin, direction)
points[index] += correction * direction
```

平滑化後の先頭と末尾だけについて、軸方向の位置が `start` / `end` に戻るよう移動します。`normal` 方向（軸に直角な方向）の成分を保ち、軸方向だけ補正します。斜め軸では画像の x・y の両方が変わります。

例えば本来の下側断面が軸方向位置 200 px なのに、平滑化で 199.8 px に来たなら、軸方向へ 0.2 px 進めます。このため、平滑化後も指定した 2 断面の間の側辺として扱えます。

## 12. `measure_contour()`：長さと超過率を辞書へまとめる

まず `smoothed_sides()` で左右の点列を得ます。基準区間長は、軸方向の位置の差を mm へ換算して求めます。

```python
interval_mm = (end - start) * MM_PER_PX
```

続いて左右の点列ごとに、隣り合う点の距離を足します。

```python
steps = np.diff(sides[side], axis=0)
length_px = float(np.linalg.norm(steps, axis=1).sum())
row[f"{name}_mm"] = length_px * MM_PER_PX
```

これは直線で始点と終点を結んだ距離ではなく、評価点を順に結ぶ折れ線の全長です。

`for side, name in ((0, "left"), (1, "right")):` は、最初に番号 0 と文字列 `left`、次に番号 1 と文字列 `right` を取り出します。`f"{name}_mm"` は f 文字列で、`name="left"` なら `"left_mm"` になります。同じ計算を左右へ適用するために使っています。

超過率は次の式です。

```python
(length_px * MM_PER_PX / interval_mm - 1) * 100
```

基準 100 mm に対して側辺が 102 mm なら `(102/100 - 1)×100 = 2%` です。DR が 102 mm、OP が 103 mm なら、`total_mm` は 205 mm です。`total_mm` は左右の合計で、試料の幅や上下端を含む全周長ではありません。合計についての超過率は作りません。

返る `row` は辞書で、列名をキー、数値を値として持ちます。画像の計算が終わった後も、`row["left_mm"]` のように名前で結果を取り出せます。最初に倍率・区間長・評価条件を入れ、左右の値、最後に合計を足しています。

## 13. 確認画像を作る 3 つの関数

### 13.1 `draw_axis_and_sections()`

2 本の断面を黄色、長手軸の区間をシアンで画像へ描きます。OpenCV の BGR では黄色が `(0, 255, 255)`、シアンが `(255, 255, 0)` です。

断面の線を画像全体まで延ばすため、`math.hypot(*image.shape[:2])` で画像の対角線の長さを使います。ここで `*` は `(高さ, 幅)` を 2 つの引数へ展開しています。掛け算ではありません。

実際に描く座標は `np.rint(...).astype(int)` で整数にします。長さ計算の点列まで丸めているわけではありません。

軸の `origin` は自動当てはめの直線上の点、または手動 2 点の中点です。利用者が指定した `interval_center` と常に同じ座標とは限りません。区間を表す 2 点は指定中心を挟んで作り、断面はそれらの軸方向位置に置きます。したがって、中心や基準区間長を保つことと、シアンの軸線が必ずクリックした中心点を通ることは区別します。

### 13.2 `measurement_overlay()`

元画像のコピーへ、平滑化後の左右の側辺を赤い折れ線で描きます。`cv.polylines()` の `False` は「先頭と末尾を閉じてつながない」という指定です。上下の端を赤線で結んでしまわないようにしています。

次に軸・断面と DR・OP 名を追加して返します。計算済みの数値を書き込む処理ではなく、線の位置を見直すための画像です。`smoothed_sides()` は数値計測側でも呼ばれ、この関数でも描画のために呼び直されます。

### 13.3 `measure_lengths()`

この関数は「抽出 → 測定 → 画像サイズを結果へ追加 → 確認画像作成」をまとめ、`(row, overlay)` を返します。

GUI の通常の操作では、「試料抽出・軸を自動推定」で得た輪郭を保持し、「長さを計測」で `measure_contour()` などへ直接渡します。毎回この `measure_lengths()` を呼んでいるわけではありません。この関数は、テストなどから画像と指定を一括で処理する入口としても使われています。

## 14. `write_measurement()` と保存される内容

### 14.1 CSV 名から PNG 名を決める

例えば保存先を `shot_lengths.csv` にすると、次の 3 ファイルを作ります。

| ファイル | 内容 |
| --- | --- |
| `shot_lengths.csv` | 1 回の計測の数値 1 行と見出し |
| `shot_lengths_initial.png` | 初期多角形の色、軸、上下断面、DR・OP 名 |
| `shot_lengths.png` | 赤い測定側辺、軸、上下断面、DR・OP 名 |

```python
initial_path = path.with_name(f"{path.stem}_initial.png")
result_path = path.with_suffix(".png")
```

`path.stem` は最後の拡張子を除いた名前です。`with_name()` は同じフォルダの別名、`with_suffix()` は拡張子を変えた場所を表す、新しい `Path` を返します。この時点でファイルの作成や名前変更をしているわけではありません。

### 14.2 入力を上書きしないための確認

`check_output_path()` は、出力の拡張子が合うか、入力画像と同じパスでないかを調べます。CSV だけでなく、2 枚の PNG も確認します。

その後、まず `encode_png()` で **両方の PNG をメモリ上のバイト列へ変換**します。PNG 化できないのに CSV だけ先に保存する失敗を避けるためです。変換に成功したら親フォルダを作り、CSV → 初期 PNG → 結果 PNG の順で書きます。

ただし、これは 3 ファイルの保存が必ず一体で成功する仕組みではありません。例えば CSV を書いた後にディスクへの PNG 書込みが失敗すると、一部だけ残る可能性があります。失敗時の GUI 表示も、それを踏まえてファイルを確認するようになっています。既存の同名 3 ファイルは、現行コードでは確認なしで上書きします。

### 14.3 実際に保存する CSV の全列

`calculate()` 経由で保存する場合の列は次のとおりです。`image_path` と `image_name` は `write_csv()` が加え、画像サイズは `calculate()` が加えます。

| 列名 | 内容 | 単位 |
| --- | --- | --- |
| `image_path` | 入力画像の絶対パス | 文字列 |
| `image_name` | 入力画像のファイル名 | 文字列 |
| `mm_per_px` | 1 px に相当する長さ | mm/px |
| `interval_length_mm` | 2 断面の軸方向距離 | mm |
| `evaluation_interval_mm` | 生の側辺の弧長上の評価間隔 | mm |
| `smoothing_width_mm` | 生の側辺の弧長上の窓の全幅 | mm |
| `left_px` | 平滑化後の DR 側辺長 | px |
| `left_mm` | 平滑化後の DR 側辺長 | mm |
| `left_excess_percent` | DR の超過率 | % |
| `right_px` | 平滑化後の OP 側辺長 | px |
| `right_mm` | 平滑化後の OP 側辺長 | mm |
| `right_excess_percent` | OP の超過率 | % |
| `total_px` | DR と OP の合計 | px |
| `total_mm` | DR と OP の合計 | mm |
| `image_height` | 入力画像の高さ | 画素数 |
| `image_width` | 入力画像の幅 | 画素数 |

CSV には多角形の頂点、区間中心の座標、軸の座標、自動／手動の区別は保存していません。初期 PNG と結果 PNG で位置を確認します。CSV を読み込んで GUI の指定を完全復元する機能もありません。

`write_csv()` は文字コードに `utf-8-sig` を使います。UTF-8 の先頭に BOM を付ける形式です。`newline=""` と `csv.DictWriter` によって、CSV の区切り・改行・必要な引用符を扱います。小数値は `f"{value:.12g}"` で有効数字 12 桁の文字列にします。GUI の表示は小数点以下 3 桁ですが、その表示文字列を CSV へ転記しているわけではありません。

後工程の `read_lengths()` が必要とするのは、このうち画像パス、倍率、区間長、左右 mm、左右超過率、評価間隔、平滑化幅です。`image_name` は読込時には画像パスから導きます。旧版の `start_y` / `end_y` を持つ CSV を、新形式として読み替える処理はありません。

GUI は、1 回計算して終わるプログラムと違い、「画像を読む」「多角形を足す」「中心を変える」「保存する」が繰り返されます。その間に必要な値を `main()` 内の変数として持ち続けます。

| 変数 | 中身 | 未設定のとき |

| `image` | 元画像配列 | `None` |
| `height`, `width` | 画像の大きさ | 初期値は 1 |
| `regions` | 確定した多角形を種類別に持つ辞書 | 各種類の値が空リスト |
| `region_rows` | 一覧の行番号と `(ラベル, 多角形番号)` の対応 | 空リスト |
| `pending_polygon` | 描画中で未確定の頂点 | 空リスト |
| `interval_center` | 人が指定した区間中心、画像座標 | `None` |
| `interval_points` | 固定区間の両端を表す 2 点 | `None` |
| `manual_points` | 入力中の手動軸の点 | 空リスト |
| `contour`, `bounds` | 抽出済み輪郭、処理範囲 | `None` |
| `axis` | `(origin, direction)` | `None` |
| `measurement` | 測定値の辞書 | `None` |
| `result_image` | 保存できる結果画像 | `None` |
| `photo` | 画面表示用の `PhotoImage` | `None` |
| `scale` | 画像から画面への倍率 | 1.0 |

| `pan_start` | 前回の右ドラッグ位置、画面座標 | `None` |

現行コードには、これらを全部 `state` という 1 個の辞書へ入れる構成はありません。`regions` や `measurement` は辞書ですが、GUI 全体の状態は上表の個別変数で保持します。

### 15.1 `None` は「まだない」ことを表す

`axis is None` は「軸の値がまだ設定されていない」という確認です。軸の数値が 0 かどうかとは異なります。空リストは `if pending_polygon:` のように書くと偽として扱われ、頂点が 1 つでも入ると真になります。

```python
axis = interval_points = None
```

これは両変数へ `None` を入れる連鎖代入です。「区間条件が変わったので、古い軸と区間を使えなくする」と読めます。

### 15.2 `tk.StringVar` / `tk.IntVar`

通常の Python 変数とは別に、Tkinter の部品と結び付く値があります。

| 変数 | 値の例 | 用途 |
| --- | --- | --- |
| `mode` | `cv.GC_PR_FGD` | 多角形の種類 |
| `selection_target` | `"region"`, `"center"`, `"axis"` | 左クリックが何を指定するか |
| `view` | `"initial"`, `"original"`, `"result"` | 表示する画像 |
| `status` | `"計測中…"` など | 上部の状態表示 |
| `file_text` | ファイル名と画像サイズ | 入力表示 |
| `length_text` | `"100"` など | 基準区間長の入力欄 |
| `axis_text` | `"軸：自動"` など | 軸の状態表示 |

`.get()` で現在値を読み、`.set(value)` で変更します。入力欄の値は文字列なので、`positive_value()` で小数へ変換してから計算します。`length_text = tk.StringVar()` には初期値を書いていないため、起動直後の入力欄は空です。

## 16. ネストした関数、`nonlocal`、コールバック

`main()` の中にさらに `def load_image()` などが入っています。これをネストした関数と呼びます。内側の関数から、外側の `main()` が持つ `image`、`canvas` などを参照できます。

ただし、外側の変数へ新しい値を代入したい場合は、意図を明示します。

```python
def load_image() -> None:
    nonlocal image, input_path, height, width, interval_center
```

`nonlocal` は「この名前は、この内側の関数だけの新しい変数ではなく、外側の関数にある変数を使う」と宣言します。`global` のようにファイル全体の変数を対象にするものではありません。

一方、`pending_polygon.clear()` のように既存のリストの中身を変更するだけなら、その変数へ新しいリストを代入していないので `nonlocal` は不要です。`measurement = measured` のように変数の指す先を変える場合との違いです。

```python
ttk.Button(..., command=calculate)
```

`command` に渡すのは関数そのものです。`calculate()` と括弧を付けると、その場で実行した返り値を渡してしまいます。ここではボタンが押された後に Tkinter が呼べるように `calculate` を登録します。こうして、後で呼び出してもらう関数をコールバックと呼びます。

```python
canvas.bind("<ButtonPress-1>", click_image)
```

こちらは左ボタンを押すイベントに `click_image` を登録します。イベントのコールバックには、位置などを持つ `event` が渡ります。`event.x` / `event.y` はキャンバス上の座標です。

`render(_event=None)` は、ボタンなどから引数なしでも、イベントから引数ありでも呼べる形です。`_event` の先頭の `_` は「引数は受け取るが使わない」という意図です。`on_interval_changed(*_args)` の `*` は、Tkinter が渡す個数の違う引数をまとめて受け取るためで、この関数ではその内容を使いません。

## 17. 画像を読む・多角形を変更するコールバック

### 17.1 `load_image()`

ファイル選択画面の開始位置は `RECTIFIED_DIRECTORY` です。選択を取り消せば空の文字列になるので `return` し、現在の画像や結果は変更しません。

読込に失敗した場合も、読み込んだものを一度 `loaded` へ受け、成功してから `image = loaded` とするため、現在の画像は維持されます。成功時はファイル名とサイズを更新し、中心を `None` に戻し、多角形と軸と結果を消して全体表示にします。

入力した基準区間長の文字列は消しません。同じ起動中に次のパスの画像へ移っても、中心と多角形は指定し直し、区間長は保持できます。

`read_image()` はファイルをバイト列として読み、`np.frombuffer()` と `cv.imdecode()` で画像にする処理です。日本語を含むパスでも扱える構成です。読み込めなければ `ValueError` を返し、GUI はその内容を `status` に表示します。

### 17.2 `on_regions_changed()`

確定した多角形が変わると、それを基にした抽出輪郭はもう有効とはいえません。そこで輪郭・処理範囲・軸・区間点を `None` に戻し、入力途中の点と古い結果も消します。

その後、左の一覧を作り直します。`region_rows` を用意するのは、画面で選んだ行が `regions` のどの種類・何番目なのかを調べるためです。

### 17.3 `clear_regions()` と `show_initial()`

`clear_regions()` はすべての種類の確定多角形を空にしてから `on_regions_changed()` を呼びます。区間中心そのものを消す処理はここにはありません。新画像の読込では、その前に `interval_center = None` としています。

`show_initial()` は領域一覧や種類を選んだときに、未確定の多角形と手動軸入力点を消し、初期指定表示・多角形入力へ戻します。確定済みの領域自体を変更する処理ではありません。

### 17.4 `finish_polygon()`

画像がない、または描画途中の点が 0 個なら何もしません。`polygon_pixels()` で点数・面積などを確認してから、次で確定します。

```python
regions[mode.get()].append(list(pending_polygon))
on_regions_changed()
```

`list(pending_polygon)` で頂点リストの別の入れ物を作ります。同じリストをそのまま保存すると、その後に `pending_polygon.clear()` を呼んだ際、確定した多角形まで空になるためです。各頂点は変更しない座標の組なので、ここでは外側のリストのコピーで足ります。

現在の確定操作はこのボタンです。右クリックは画像の移動に使い、多角形の確定には使いません。

### 17.5 `cancel_drawing()`、`select_target()`、`delete_region()`

`cancel_drawing()` は未確定の多角形と入力途中の手動軸点を消します。確定済みの多角形を消す処理ではありません。手動軸の 1 点目を置いた時点では軸が `None` になっているため、取消だけで以前の自動軸が復活するわけではありません。必要なら自動推定を押し直します。

`select_target()` は「多角形／区間の中心／手動軸 2 点」の切替時に呼ばれ、途中の描画を取り消します。多角形へ切り替えた場合は初期指定表示にします。

`delete_region()` は一覧で選択した 1 行に対応する多角形を `del regions[label][index]` で削除し、`on_regions_changed()` を呼びます。選択がなければ何もしません。

## 18. `click_image()`：同じ左クリックを 3 種類に分ける

まず画像があるか、クリックが画像の表示範囲内かを確認します。画像の外の余白をクリックしても点を置きません。

### 18.1 画面座標から元画像座標へ戻す

表示変換は次の式です。

```text
画面 x = offset_x + 画像 x × scale
画面 y = offset_y + 画像 y × scale
```

逆に解くと、コードの次の式になります。

```python
point = ((event.x - offset_x) / scale, (event.y - offset_y) / scale)
```

例えば `scale=0.5`、画像左上の画面位置が `(100, 50)`、クリックが画面の `(400, 250)` なら、元画像では `(600, 400)` です。さらに右端・下端は画像の最後の画素座標を超えないよう制限します。

### 18.2 中心を選んでいる場合

`selection_target.get() == "center"` なら、その点を `interval_center` に入れ、`on_interval_changed()` を呼んで区間と軸を更新します。中心を置いた瞬間に、抽出済みの輪郭があれば自動軸を推定し直します。まだ輪郭がなければ中心を記録するだけです。

### 18.3 手動軸を選んでいる場合

先に輪郭・処理範囲・中心が必要です。揃っていなければ、先に抽出・自動推定を行うよう表示します。自動推定の軸だけが失敗し、輪郭が残っている状態なら手動軸へ進めます。

1 点目をクリックすると古い測定値を消し、軸と区間点を `None` にします。「手動軸：1点」と表示し、まだ測定できない状態にします。

2 点目をクリックすると `manual_axis()` を呼びます。その向きに対して、既存の区間中心と基準区間長から `fixed_interval_points()` を作り直します。2 点間の距離を基準区間長に採用しているわけではありません。成功すれば「軸：手動2点」、失敗すれば「軸：未設定」と表示し、入力途中の点は消します。

手動軸が確定しても、試料の中を正しく切れるかの最終確認は測定時です。方向だけ指定できたことと、有効な側辺を測定できることは分けて考えます。

### 18.4 多角形を選んでいる場合

初期指定表示のときだけ頂点を追加します。

```python
pending_polygon.append((point[0] / (width - 1), point[1] / (height - 1)))
```

画像座標を画像サイズで割って比率に変換し、未確定リストに追加します。まだ `regions` には入りません。頂点を置くたびに古い測定結果は消えます。確定または取消をするまで、計測操作は未確定入力として拒否されます。

## 19. 条件変更・抽出・計測・保存のコールバック

### 19.1 `clear_results()`：古い数値を保存させない

```python
measurement = None
result_image = None
...
save_measurement_button.state(["disabled"])
```

内部の結果を消し、表の数値を `—` に戻し、保存ボタンを無効にします。表だけを消して古い辞書を残す実装にはしていません。

### 19.2 `on_interval_changed()`：中心・長さが変わったとき

区間中心か入力欄の文字が変わると、軸・区間点・手動入力中の点・結果を消します。すでに輪郭があり中心もあれば `fit_axis()` を呼びます。GrabCut はやり直さず、保持している輪郭の新しい区間で自動推定し直します。

手動軸を使っていた場合でも、中心や長さの変更後は自動軸へ戻ります。手動の方向をそのまま保持する動作ではありません。

```python
length_text.trace_add("write", on_interval_changed)
```

この登録により、入力欄が書き換わるたびに呼ばれます。確定ボタンを押したときだけではありません。例えば `100` をいったん空欄へ消して入力し直す途中には、正の数でないという表示になる場合があります。

### 19.3 `fit_axis()`：GUI の値から自動推定を呼ぶ

入力欄を `positive_value()` で数値へ変換し、指定中心と縦方向 `(0, 1)` から仮区間を作ります。`estimate_axis(..., fixed_length_mm=length_mm)` を呼び、最後に推定方向で区間点を作り直します。

成功するまでは `axis` を有効にしません。失敗すれば「軸：自動推定失敗」と理由を表示します。この関数は抽出済み輪郭を消さないので、手動軸による修正が可能です。

### 19.4 `extract_and_estimate()`：抽出ボタン

以前の輪郭と軸と結果を最初に消します。画像、確定した指定、中心、正の区間長が揃っているか確認します。未確定多角形が残っていれば抽出しません。

「試料抽出中…」を表示し、`root.update_idletasks()` を呼んで、長い計算に入る前に表示更新を進めます。別スレッドを作ってバックグラウンド実行しているわけではないため、GrabCut の計算中は通常の GUI 操作を自由に続けられる仕組みではありません。

`extract_specimen()` に成功すれば `fit_axis()` を呼びます。`ValueError` なら具体的な理由、OpenCV のエラー `cv.error` なら「試料を抽出できません。多角形を調整してください」と表示します。

### 19.5 `calculate()`：計測ボタン

まず古い結果を消します。次のいずれかがあれば計算を始めません。

- 未確定の多角形がある。
- 手動軸が入力途中である。
- 輪郭、処理範囲、軸、区間点が未設定である。

準備が揃えば `measure_contour()` と `measurement_overlay()` を呼びます。両方が成功した後に `measurement` と `result_image` へ採用します。途中で失敗した結果は保存対象にしません。

表には DR、OP、合計の mm を小数点以下 3 桁で表示します。超過率は DR と OP のみ表示します。表示を計測結果へ変え、`state(["!disabled"])` で保存を有効にします。`!disabled` は「disabled 状態を外す」という Tkinter の状態指定です。

計測ボタン自体は、準備不足のすべての状態で無効になるよう実装されているわけではありません。押した後の条件確認でも誤計測を防いでいます。

### 19.6 `save_measurement()`：保存ボタン

結果と入力画像が揃っているか改めて調べ、保存先を選びます。選択を取り消せば保存せず戻ります。

初期 PNG は、いま画面に何を表示しているかに関係なく、元画像と確定多角形から `initial_overlay()` で作り、軸・断面を加えます。結果 PNG は計測成功時の `result_image` を使います。画面を縮小表示していても、保存されるのは元画像の解像度です。

`ValueError` なら拡張子や入力上書きなどの理由を表示します。`OSError` または `cv.error` なら「保存失敗: CSV・PNGを確認してください」と表示します。コードの `except OSError, cv.error:` は、このプロジェクトで使う Python の複数例外指定の書き方です。エラーを無視して成功扱いにする構造ではありません。

## 20. 表示・拡大・移動の処理

### 20.1 `render()`：現在の状態から画面を描き直す

最初に `canvas.delete("all")` でキャンバス上の前回の描画を消します。これは画面の絵を消すだけで、元画像、確定多角形、計測値を削除する操作ではありません。

表示モードが結果で、有効な `result_image` があればそれを選び、それ以外では元画像を使います。初期指定モードなら、その表示画像へ多角形の色を重ねます。

大きな画像を拡大したとき、画面の外まで巨大な表示画像を作るとメモリを使います。そこで画面に重なる範囲だけを調べ、`cv.warpAffine()` でその部分の表示用画像 `small` を作ります。

```python
transform = np.array(
    [
        [scale, 0, offset_x - display_left],
        [0, scale, offset_y - display_top],
    ],
    dtype=np.float64,
)
```

これは拡大率と平行移動を表す 2 行 3 列の変換行列です。元画像の座標から、画面に見える小画像内の座標へ変換します。`INTER_NEAREST` は近い画素を使って表示する指定です。測定用の輪郭データをこの拡大画像から再計算するわけではありません。

表示する多角形も、元画像座標を `scale` と `offset` で変換してから、表示範囲のラベル画像へ塗ります。最後に PNG 化して `tk.PhotoImage` を作り、`canvas.create_image()` で置きます。

`photo` を外側の変数に保持しているのは、Python 側で表示画像への参照を保つためです。関数内だけの変数にして参照を失うと、Tkinter で画像が消える原因になります。

さらに次をキャンバスへ描きます。

- 一覧で選ばれた確定多角形の黄色い枠。
- 未確定多角形の白い頂点と破線。
- 指定中心の黄色い印と「中心」の文字。
- 軸が有効なら、上下断面の黄色い線と軸のシアン破線。
- 入力途中の手動軸点のシアンの印。
- 画面の左右上隅の DR・OP 表示。

キャンバス上の DR・OP 表示は画面の隅に置かれます。画像に直接描く `draw_edge_names()` の位置とは別です。

### 20.2 `canvas_polygon()`：頂点リストをキャンバス用へ変える

比率を元画像座標へ戻し、画面座標へ変換します。返す形式は `[(x1,y1), ...]` ではなく、キャンバスへ渡すための `[x1, y1, x2, y2, ...]` です。

```python
canvas.create_polygon(*points, ...)
```

`*points` は、平たいリストを複数の引数へ展開します。`ends.ravel()` に `*` を付けて線を描く部分も同じ考えです。

未確定頂点を描く `zip(points[::2], points[1::2])` は、偶数番目の x 群と奇数番目の y 群を 1 個ずつ組に戻しています。`[::2]` は 2 個おき、`[1::2]` は 1 番目から 2 個おきです。

### 20.3 `fit_image()`：全体表示

```python
scale = min(canvas.winfo_width() / width, canvas.winfo_height() / height, 1)
```

横も縦も収まる倍率を選び、最大を 1 倍にします。画像が小さければ、全体表示だけでは元より大きくしません。余った幅・高さの半分をオフセットにして中央へ置きます。指定座標や結果は変更しません。

### 20.4 `zoom()`：カーソル位置を保って拡大縮小する

最初に、カーソルの下にある元画像座標を逆変換で求めます。その後倍率を変えます。

```python
factor = 1.2 ** (event.delta / 120)
scale = min(16.0, max(0.01, scale * factor))
offset_x = event.x - image_x * scale
offset_y = event.y - image_y * scale
```

`**` はべき乗です。ホイール量が 120 なら 1.2 倍、240 なら 1.44 倍、-120 なら 1/1.2 倍になります。倍率は 0.01〜16 に制限します。

新しいオフセットは、「倍率を変えた後も、同じ画像座標が同じカーソル位置へ来る」よう逆算しています。`return "break"` は Tkinter に、このイベントの以後の標準処理を止める意図を伝える返り値です。

### 20.5 `start_pan()`、`pan()`、`end_pan()`：右ドラッグ

`start_pan()` は右ボタンを押した画面位置を保存し、カーソルを移動用へ変えます。`pan()` は前回からのマウス移動量をオフセットへ加え、前回位置を更新して描き直します。`end_pan()` は移動中の位置を `None` にして通常の十字カーソルへ戻します。

これらが変更するのは表示のオフセットです。中心や多角形を一緒に書き換える必要はありません。次の `render()` が同じ画像座標から新しい画面位置を計算するため、画像と指定が一緒に動きます。

## 21. 画面部品の作り方と、イベントの対応

`create_layout(root)` は上部の `header`、左の `sidebar`、右の `content` を返します。共通の配置だけを補助モジュールへ任せ、各ボタンの動作はこのファイルに置いています。

`ttk.Button(...).pack(...)` は「ボタンを作り、その配置を指示する」を続けて書いたものです。`fill="x"` は横幅を埋める、`fill="both"` は両方向、`expand=True` は余った領域を利用する指定です。

ラジオボタンは複数の選択肢で同じ `variable` を共有します。例えば `selection_target` に `"center"` が入るボタンを選ぶと、次の左クリックが中心指定へ切り替わります。多角形の種類、クリック対象、表示モードは、それぞれ別の変数を共有する別グループです。

結果の表は `ttk.Treeview` です。内部の行 ID は `left` / `right` / `total`、見える名前は DR / OP / 合計です。例えば `result_table.set("left", "length", "102.000")` は、DR 行の長さのセルを更新します。

色見本の `PhotoImage` も `swatches` のリストへ保持し、参照が失われないようにしています。

| 操作・イベント | 登録先の関数 | 主な結果 |
| --- | --- | --- |
| 補正画像を読み込む | `load_image` | 新画像を読込み、指定・結果をリセット |
| 多角形／中心／手動軸の選択 | `select_target` | 未確定入力を取消し、クリック対象を変更 |
| 前景候補・背景・前景の種類選択 | `show_initial` | 初期指定の多角形入力へ移る |
| 左クリック `<ButtonPress-1>` | `click_image` | 対象に応じて頂点・中心・手動軸点を追加 |
| 多角形を確定 | `finish_polygon` | 描画中の頂点を確定領域へ追加 |
| 描画を取消 | `cancel_drawing` | 未確定の頂点・手動軸点を消す |
| 選択した多角形を削除 | `delete_region` | 1 個削除し抽出・結果を無効化 |
| 多角形をすべて削除 | `clear_regions` | 全領域を削除し抽出・結果を無効化 |
| 基準区間長の文字列変更 | `on_interval_changed` | 結果を消し、可能なら自動軸を再推定 |
| 試料抽出・軸を自動推定 | `extract_and_estimate` | GrabCut と自動軸推定 |
| 長さを計測 | `calculate` | 側辺長・超過率・確認画像を作成 |
| CSV・画像 2 枚を保存 | `save_measurement` | 3 ファイルを書込み |
| 表示モード切替 | `render` | 現在のデータを別の表示で描画 |
| 全体表示 | `fit_image` | 全体が収まる表示へ戻す |
| ウィンドウ内の描画領域変更 `<Configure>` | `render` | 新しい画面サイズで描画 |
| ホイール `<MouseWheel>` | `zoom` | カーソル位置を中心に拡大縮小 |
| 右ボタン押下 `<ButtonPress-3>` | `start_pan` | 移動を開始 |
| 右ボタンを押して移動 `<B3-Motion>` | `pan` | 表示位置を更新 |
| 右ボタンを離す `<ButtonRelease-3>` | `end_pan` | 移動を終了 |
| 一覧の選択 `<<ListboxSelect>>` | `show_initial` | 選択領域を確認できる表示へ |

最後に出力フォルダを作り、`on_regions_changed()` で初期状態を反映し、`root.mainloop()` に入ります。`mainloop()` はイベントを待ち、操作が来れば該当するコールバックを呼ぶ役割です。ウィンドウを閉じるまで、この待受けが続きます。

## 22. 操作の一例を、変数の変化で追う

仮に、幅 1600 px、高さ 1200 px、倍率 0.25 mm/px の補正画像で、100 mm の区間を測るとします。

1. **起動**：`image=None`、`interval_center=None`、`axis=None`、`measurement=None`。基準区間長は空欄。保存は無効です。
2. **読込**：`image` に画像配列、`input_path` にそのパスが入り、`width=1600`、`height=1200` になります。
3. **多角形の頂点を 4 回クリック**：`pending_polygon` に比率の点が 4 個入ります。まだ `regions` は空です。
4. **多角形を確定**：前景候補を選んでいれば `regions[cv.GC_PR_FGD]` に 1 個の多角形が入り、`pending_polygon` は空になります。
5. **長さを入力**：`length_text.get()` は文字列 `"100"`。まだ輪郭がないので軸は未設定です。
6. **中心をクリック**：例えば元画像座標 `(800, 600)` が `interval_center` に入ります。
7. **抽出・自動軸**：`contour` と `bounds` が決まり、最初は `(800, 400)` と `(800, 800)` の仮区間から推定します。試料がほぼ縦なら `direction` は `(0, 1)` に近くなります。
8. **計測**：上下断面の間の左右側辺を切り出し、評価点を生の側辺に沿って約 4 px ごとに置き、全幅 8 px の窓で平滑化します。
9. **結果**：仮に DR=102 mm、OP=103 mm なら、超過率は 2% と 3%、合計 205 mm です。保存が有効になります。
10. **中心を移動**：`measurement=None` になり保存が無効になります。輪郭を保持したまま、新しい区間の自動軸を求めます。数値は再度計測するまで空欄です。

この例の 102 mm と 103 mm は計算を説明するための仮の値です。特定の実画像でその値が得られることを示すものではありません。

## 23. 失敗したとき、どこを見直すか

| 表示・状態 | コードで問題にしていること | 見直す点 |
| --- | --- | --- |
| 正の数値にしてください | 空欄、文字列、0、負数、`nan`、`inf` など | 基準区間長と設定値 |
| 多角形の面積が不足 | 点数はあっても面積がほぼない | 頂点の配置と確定 |
| 前景候補と、その外の背景を指定 | 前景がない、または全体が前景 | 初期多角形の範囲 |
| 試料を抽出できません | 有効な輪郭が得られない、または GrabCut が失敗 | 色・反射・背景、指定多角形 |
| 軸：自動推定失敗 | 推定に使う断面や直線が求まらない | 中心・長さ・抽出結果、必要なら手動軸 |
| 左右 1 本ずつの側辺を取れない | 上下断面で試料区間がない、または分かれる | 区間中心、軸、長さ |
| 上下断面を結ぶ側辺を 2 本取れない | 切り出した連続輪郭が左右 2 本にならない | 試料形状と区間 |
| 処理範囲の端に接している | 抽出に使う範囲で側辺が切れている恐れ | 前景候補の余裕、撮影範囲 |
| 評価点が 3 点以上入るように | 側辺に対して評価間隔が大きすぎる | 評価間隔と区間長 |
| 保存失敗 | 3 ファイルの書込みが完了しなかった可能性 | 保存先、CSV と両 PNG の実物 |

範囲不足の場合に区間を自動で短縮したり、片側だけを測って成功扱いにしたりはしません。何を修正すべきかが分かる状態で停止することも、計測の大切な動作です。

表示倍率、右ドラッグ、全体表示、表示モードだけの変更では、計測条件を変えないため結果は保持します。多角形、区間中心、区間長、手動軸の入力を変えた場合は、結果の根拠が変わるため保存を無効にします。
