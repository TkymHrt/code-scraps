# 赤い6桁7セグをカメラから読む

ハーフミラーで反射した赤色7セグを、OpenCVによる色抽出と点灯パターンの照合で読みます。学習モデルは使いません。
左から3桁目と4桁目の間に小数点があるものとし、整数側の不要な先頭桁は消灯していても位置を保ちます。

読み取りは `read_meter.py`、位置の校正は `calibrate_meter.py`、動画シミュレーションは `sandbox/simulate_meter.py` です。
いずれも先頭の設定を変更して実行します。コマンド引数や設定JSONは使いません。自動検証は `tests/` に置きます。
実機画像がまだないため、撮影位置と赤色のしきい値は現場で校正する前提です。

## 方式と対象

```text
カメラ / 動画
  → 鏡像を戻す
  → 赤い画素を抽出し、各選択領域内で赤につながる白飛びを補う
  → 手動指定した6桁×7領域で点灯状態を調べる
  → 数字へ変換し、3桁目と4桁目の間に小数点を補う
  → 同じ値が連続したら確定し、JSONLとCSVへ出力
```

桁の位置を固定するので、`"  1234"` は `1.234`、`" 12345"` は `12.345`、`"123456"` は `123.456` になります。`"  0000"` は `0.000` です。整数部の先頭消灯だけを許し、整数の1の位や小数部の消灯、途中の空白、全消灯は無効にします。

対象は **0.000〜999.999の非負数、赤色、固定された6桁の通常の7セグ** です。負号、単位表示、桁数や小数点位置の変更は扱いません。学習データ、Tesseract、GPU、ネット接続は認識時に不要です。カメラと計器の位置は固定してください。

数字全体の輪郭を自動検出すると、消灯桁や幅の狭い `1` で位置がずれます。そのため、最初に人が撮影画像上で各桁7か所の読み取り領域を指定します。鏡像を戻した画像をそのまま使い、四隅の選択や透視補正は行いません。

## まずシミュレーションで試す

Python 3.10以降を使います。PowerShellでリポジトリのルートから実行します。

```powershell
Set-Location scraps/seven-segment-ocr
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt

.\.venv\Scripts\python.exe sandbox/simulate_meter.py
.\.venv\Scripts\python.exe read_meter.py
```

上段に鏡像を戻した撮影画像と読み取り領域、下段に赤色と補完した白飛びの抽出結果が出ます。小枠は緑が点灯、灰色が消灯、黄色が判定不能です。`Q` または `Esc` で停止します。動画はおおむね元のfpsで表示しますが、処理時間が加わるので厳密な再生時計にはなりません。

シミュレーターは、透視、鏡像、ぼけ、雑音、輝度低下、弱い白い反射、読み取り範囲外の赤い物体を加えます。正常値のほか、全消灯・途中消灯・数字にない点灯・正常値への復帰を含む14条件、168フレーム、30fpsの動画です。以下が生成されます。

| ファイル                         | 内容                       |
| -------------------------------- | -------------------------- |
| `outputs/simulation/meter.avi`   | 合成したカメラ動画         |
| `outputs/simulation/truth.csv`   | フレームごとの正解と条件名 |
| `outputs/simulation/preview.png` | 鏡像のサンプル画像         |
| `outputs/readings_001.csv`       | 読み取りプログラムの出力例 |

読み取り側の初期設定は、この合成動画の位置に合わせてあります。すでに動画があれば生成は省略できます。
変更する場所は `read_meter.py` の先頭です。

| 設定              | 意味                                                                                   |
| ----------------- | -------------------------------------------------------------------------------------- |
| `SOURCE`          | カメラは整数の `0` など。動画は `BASE_DIR / "outputs/simulation/meter.avi"` などのパス |
| `CSV_DIR`         | CSVの保存フォルダ。ファイル名は自動で連番を付ける                                      |
| `SHOW_PREVIEW`    | `True` は確認画面を表示、`False` は画面なしで処理                                      |
| `FRAME_SIZE`      | 校正時の撮影解像度 `[幅, 高さ]`                                                        |
| `REFLECTION`      | 鏡像の補正方向                                                                         |
| `SEGMENT_BOXES`   | 鏡像を戻した撮影画像上の各桁7か所、計42個の読み取り枠                                   |

画面なしで処理する場合は `SHOW_PREVIEW = False` にします。JSONLもファイルに残せます。

```powershell
.\.venv\Scripts\python.exe read_meter.py > outputs/readings.jsonl
```

CSVは実行ごとに `CSV_DIR` 内で `readings_001.csv`、`readings_002.csv` のように、001から順に探した未使用の番号で保存します。既存ファイルは上書きしません。保存先は標準エラー出力に表示するので、標準出力のJSONLには混ざりません。

シミュレーションの生成先も上書きしません。動画を作り直すときは `OUTPUT_DIR` を変更してください。生成物、実測データ、仮想環境はGitの対象外です。上のJSONLへのリダイレクトは別の保存操作なので、再実行時はファイル名を変更します。

シミュレーターも先頭の `OUTPUT_DIR`、`FRAMES_PER_VALUE`、`FPS`、`REFLECTION` を変更して使います。反射方向を変えた場合は、読み取り側の `REFLECTION` も合わせます。

## 実機を校正する

1. ハーフミラーとカメラを固定し、6桁が十分な大きさで写るようにします。映り込みを遮る黒い覆いを使い、ピント、露光、ゲイン、ホワイトバランスをカメラ側で調整します。赤い縁が残る白飛びは補完できますが、赤が完全に失われた部分は判定不能になります。調整後は自動変更を止めます。
2. 可能なら全桁が `8` になる表示テスト、または消灯部も含め全セグメントの位置が分かる画像を使います。**各桁の7本をそれぞれ別の矩形で選ぶ**ため、消灯部の位置が見えない画像は避けてください。
3. `calibrate_meter.py` 先頭の `SOURCE = 0` をカメラ番号に合わせ、`REFLECTION` を選んで実行します。録画なら `SOURCE = r"C:\measurement\recorded.avi"` のように動画パスを指定します。

```powershell
.\.venv\Scripts\python.exe calibrate_meter.py
```

反射補正は設置方向に合わせて選びます。「カメラが上にある」ことだけでは補正方向は決まりません。既知の数字、例えば `123.456` が正しい順序・上下で見える設定を選んでください。

| `REFLECTION` | 補正                   |
| ------------ | ---------------------- |
| `horizontal` | 左右反転（既定）       |
| `vertical`   | 上下反転               |
| `both`       | 上下・左右の両方を反転 |
| `none`       | 反転しない             |

4. プレビューで `Space` を押して画像を止めます。中止は `Q` または `Esc` です。
5. 鏡像を戻した撮影画像で、左の桁から順に、各桁の **上→右上→右下→下→左下→左上→中央** をドラッグし、各回 `Enter` で確定します。合計42回です。ウィンドウ名に桁番号・選択番号・部位が出ます。各枠はセグメント内の小領域にし、余分な背景や隣のセグメントを入れません。傾いたセグメントも、その内側に収まる小さな矩形を選びます。白飛びがある場合は、白い中心だけでなく残っている赤い縁も含めてください。消灯した桁も7か所すべて選びます。選択済みの枠は黄色で表示され、中止は `C` です。中止すると設定は出力しません。
6. 校正が終わると、`FRAME_SIZE`、`REFLECTION`、`SEGMENT_BOXES` の3項目がPythonの代入文で表示されます。`read_meter.py` 先頭の同名設定をその内容に置き換え、`SOURCE` と必要に応じて `CSV_DIR` も実機用に変更します。以前の透視補正後の座標は使えないので、旧設定を使っていた場合は再校正してください。

```python
SOURCE = 0
CSV_DIR = BASE_DIR / "outputs"
```

7. 読み取りスクリプトを実行します。

```powershell
.\.venv\Scripts\python.exe read_meter.py
```

動画の校正プレビューでは `N` で次のフレームへ進み、`Space` で選択に入ります。校正スクリプトは読み取り側のコードを書き換えず、設定値を表示するだけです。

撮影解像度が校正時と違えば停止します。カメラ読み取りでは校正時の解像度を要求しますが、カメラが対応しない場合は自動的に合わせられません。カメラやミラーを動かしたときも再校正してください。遠近による変形が大きい場合や、各セグメント内に十分な矩形を取れないほど小さく写る場合は、撮影位置や解像度を調整します。

## 出力の読み方

標準出力は1フレーム1行のJSONL、自動採番したCSVには同じ項目を保存します。`Ctrl+C` でもCSVを閉じてカメラを解放します。カメラの途中切断はエラー終了します。

```jsonl
{"frame_index":2,"captured_at":"2026-11-02T00:00:00.067+00:00","source_time_seconds":0.066667,"status":"ok","display":"  1234","raw_value":"1.234","value":"1.234","reason":""}
```

| 項目                  | 意味                                                                                              |
| --------------------- | ------------------------------------------------------------------------------------------------- |
| `frame_index`         | 0から始まるフレーム番号                                                                           |
| `captured_at`         | PCで処理を始めた時刻。UTC。センサーの撮影時刻ではない                                             |
| `source_time_seconds` | 動画は番号÷fps、カメラは収集開始からの経過秒                                                      |
| `display`             | 6文字の読取結果。消灯は空白、読めない桁は `?`                                                     |
| `raw_value`           | そのフレームだけの読取値。確定前の値も含む                                                        |
| `value`               | 連続判定を通った値だけ。後段で使う列                                                              |
| `status`              | `warming_up` は連続判定待ち、`ok` は確定、`invalid` は読取不能                                    |
| `reason`              | `all_blank` は全消灯、`misplaced_blank` は不正位置の消灯、`uncertain_segments` は曖昧・不正な点灯 |

`value` と `raw_value` は、`0.001` や末尾のゼロを保持するため文字列です。数値計算では `decimal.Decimal` などへ変換します。`invalid` と `warming_up` の `value` はJSONでは `null`、CSVでは空欄です。直前の確定値を埋め直すことはしません。後段は `status == "ok"` の値を使ってください。

初期設定では同じ有効値が3フレーム続くと確定し、その後もフレームごとに出力します。値の変更や無効フレームで連続判定はリセットされます。30fpsでは最初の観測から確定まで約67msですが、撮影・転送・処理の遅延が別に加わります。変化が速く3フレーム続かない値は確定しません。

## 赤抽出・白飛び補完と点灯判定の調整

`read_meter.py` 先頭の次の値を現場に合わせます。

| 設定            | 初期値 | 意味                                         |
| --------------- | ------ | -------------------------------------------- |
| `RED_MIN`       | 70     | 赤成分Rの下限（0〜255の画像）                |
| `RED_MARGIN`    | 40     | `R - max(G, B)` の下限。白い反射を除く       |
| `WHITE_MIN`     | 200    | B・G・Rがすべてこの値以上なら白飛び候補      |
| `RED_SEED_FRACTION` | 0.05 | 白飛びを補う連結領域に必要な赤色面積／選択枠面積 |
| `OFF_FRACTION`  | 0.15   | 補完後の点灯画素率がこれ以下なら消灯。ただし補完できない白色が多ければ判定不能 |
| `ON_FRACTION`   | 0.65   | 補完後の点灯画素率がこれ以上なら点灯         |
| `STABLE_FRAMES` | 3      | 確定に必要な同じ有効値の連続フレーム数       |

各枠の中で、赤色と白飛び候補がつながった領域を調べます。その領域に、枠面積の5%以上の赤色が残っていれば、つながる白い部分も点灯画素に加えます。枠の外や別のセグメントの赤色は根拠にしません。赤色がわずかな雑音だけの場合や、赤から離れた白い映り込みは補完しません。ただし、赤と接している白い外乱は画像だけでは区別できません。

例えば補完後の点灯画素率が0.40なら、そのフレームを無効にします。補完できなかった白色が枠面積の15%を超え、点灯にも確定できない場合も無効です。白飛びした点灯を消灯とみなすと、`8` が `0` など別の正常な数字に変わるためです。下段の抽出画像と上段の黄色い枠を見て、ピント・露光・選択範囲を確認してください。完全に白くなり赤色が残っていないセグメントの復元は扱いません。

各領域は `SEGMENT_BOXES` に、左の桁から6組、各組7個の `[左, 上, 右, 下]` で保存します。鏡像を戻した撮影画像上の整数座標で、右・下は含みません。枠は `FRAME_SIZE` の範囲内に指定します。初期設定は960×360の合成動画に合わせてあります。位置や大きさは枠ごとに独立しており、桁枠に対する比率は使いません。設定・反射補正・認識・保存の処理は実行用スクリプト1本で追えます。

## 実機で残る確認

- LEDのPWMや時分割点灯と露光が合わないと、一部のセグメントだけが欠けます。露光時間や撮影fpsを調整し、表示更新の途中を含む録画と目視値で照合してください。単純な複数フレームの画像合成は、値の切替中に架空の数字を作るため採用していません。
- 欠けた点灯が別の正しい数字になる場合（例：`8` の中央が欠けて `0`）、連続判定だけでは検知できません。先頭の点灯欠落と正規の先頭消灯も画像だけでは区別できません。
- ハーフミラーの二重像、強い映り込み、赤い外乱が桁枠に重なる条件、振動・ピント変化、実際の字体、カメラの遅延は未確認です。まず撮影・遮光・固定で改善し、既知値を使って確認してください。
- 固定fpsの動画を前提に時刻を算出します。可変fps動画の厳密な撮影時刻や、計器の真の更新周期を記録するものではありません。
