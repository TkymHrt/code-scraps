# ロガーの電圧とOCR値のリアルタイム照合

同じWindows PCでNR-600の電圧とカメラの圧下表示を読みます。1つの入力ユニットの8CHをそれぞれの単位に換算し、時刻の近いOCR値と一緒に表示します。出力テストとして、仮の係数によるゲージメータ板厚の試算も表示します。

| スクリプト | 役割 |
| --- | --- |
| `collect_logger.py` | NR-600から指定CHの現在電圧を `GetCurrentData()` で読む |
| `calibrate_meter.py` | 各桁7点をクリックし、OCRの校正設定を表示する |
| `read_meter.py` | 赤い6桁の7セグを読み、同じ値が続いたら確定する |
| `calculate_readings.py` | 取得2本を起動し、電圧の換算・OCRとの時刻照合・テスト用の板厚試算を行う |

## 設定と実行

Python 3.10以降と製品版WAVE LOGGER PROを用意します。このフォルダを開き、校正・取得・計算に同じPythonを使います。

```powershell
python -m pip install pywin32 'opencv-python>=4.10,<6' 'numpy>=2,<3'
```

1. ユニット1の電圧CH1～8を有効にし、入力レンジをすべて±10Vにして、連続収集用の `.ucf` を作ります。WAVE LOGGER PROを終了し、`collect_logger.py` の `SETTINGS_FILE` にそのパスを、`DEVICE_ID` に本体IDを設定します。[NR-600の準備手順](../rolling-gauge-meter/README.md#準備)
2. OCRを校正し、得られた `FRAME_SIZE`、`REFLECTION`、`SAMPLE_RADIUS`、`SEGMENT_POINTS` をこのフォルダの `read_meter.py` に貼り付け、`SOURCE` にカメラ番号を指定します。入力の確認には動画ファイルも使えます。初期の点は既存の合成動画用です。対象は `0.000`〜`999.999` の赤い6桁7セグで、点灯時に白飛びしない赤い箇所を手動選択します。[OCRの校正手順](#ocrを校正する)
3. `calculate_readings.py` の `CHANNELS` にある8CH分の設定を埋めます。初期の割当は下表のとおりです。実配線に合わせて名称と対応を確認し、各CHの `unit` と、`low_point`・`high_point` の `None` を現場の値に置き換えます。未設定のままでは取得を開始しません。計算側がCH名を取得側に渡すため、取得側でCHを重ねて設定する必要はありません。

| CH | 初期の名称 | 信号 |
| --- | --- | --- |
| `U1_CH1` | `rolling_speed` | 圧延速度 |
| `U1_CH2` | `load_OP` | 圧延荷重OP |
| `U1_CH3` | `load_DR` | 圧延荷重DR |
| `U1_CH4` | `tension_in` | 入側張力 |
| `U1_CH5` | `tension_out` | 出側張力 |
| `U1_CH6` | `bender_Inc` | ベンダーInc |
| `U1_CH7` | `bender_Dec` | ベンダーDec |
| `U1_CH8` | `exit_thickness` | 出側板厚 |

`U1_CH1` はユニット1の電圧CH1です。例えばCH2が1～3Vで0～100tonを表す場合、その設定欄は次のようになります。説明用の仮値なので、実際の単位・対応値に置き換えます。

```python
"U1_CH2": {
    "name": "load_OP",
    "unit": "ton",
    "low_point": (1.0, 0.0),
    "high_point": (3.0, 100.0),
},
```

`low_point` と `high_point` はそれぞれ `(電圧, 換算後の値)` です。電圧は−10～10V内で、低い点から順に指定します。換算後の値は増加・減少のどちらでも構いません。基準2点の電圧範囲をそのまま有効範囲にし、端点を含めて換算します。範囲外は外挿せず、換算値を欠測にします。以前の `valid_voltage` は不要です。

ロガーの測定レンジ±10Vと、信号ごとの換算範囲は別です。0～8V、1～3VなどをCHごとに設定できます。例えば `(0.0, 0.0)` と `(8.0, 80.0)` なら4Vは40になります。`unit` は換算後の数値に付ける表記で、mpm・ton・kgなどをCHごとに指定できます。単位同士の自動変換は行いません。板厚試算に使うCH2・CH3の荷重単位は揃えます。±10Vの実際の入力レンジは `.ucf` 側で設定します。

```powershell
python calculate_readings.py
```

`Ctrl+C` または片方の取得終了で両方の取得を停止します。終了後はWAVE LOGGER PROの画面で収集停止を確認してください。

## ゲージメータ板厚の出力テスト

`calculate_readings.py` は、換算した `U1_CH2`（荷重OP）と `U1_CH3`（荷重DR）を合算し、OCRの圧下表示と次の式で試算します。OP・DRが独立した片側荷重である前提です。[式とゼロ基準の考え方](../rolling-gauge-meter/ANALYSIS.md#6-圧下ocrとゲージメータ式)

```text
P = load_OP + load_DR
h_test = h0 + a × (ocr_value − r0) + P/Mw − P0/M0
```

スクリプト先頭の次の6項目は、計算・出力を確かめるための仮値です。実機で校正した係数ではありません。

| 設定 | 初期値 | 意味 |
| --- | --- | --- |
| `GAUGE_BASE_THICKNESS_MM` | 0.0 | h0: ゼロ合わせ時の基準板厚・ギャップ（mm） |
| `GAUGE_ZERO_READING` | 0.0 | r0: ゼロ合わせ時のOCR表示 |
| `GAUGE_DISPLAY_TO_MM` | 1.0 | a: 表示差をmmへ換算する係数。開く方向を正にする |
| `GAUGE_ZERO_LOAD` | 200.0 | P0: ゼロ合わせ時の荷重。OP・DRと同じ単位 |
| `GAUGE_MILL_STIFFNESS` | 10000.0 | Mw: 圧延時の剛性。荷重単位/mm |
| `GAUGE_ZERO_STIFFNESS` | 10000.0 | M0: ゼロ合わせ時の剛性。荷重単位/mm |

例えばOP・DRをそれぞれ500kNに換算し、OCR表示が0.800なら、上の仮値で板厚は `0.800 + 1000/10000 − 200/10000 = 0.880 mm` です。結果はロガーの行ごとに標準エラー出力へ `print` します。

```text
[gauge test] 2026-11-06T00:00:00.150+00:00 h_test_mm=0.880000
```

OP・DRのどちらかが欠測・換算範囲外、OCRが未確定・受信待ち・時刻差超過の場合は `h_test_mm=missing` と表示します。直前の計算値は再利用しません。他のCHが欠測でも、必要なOP・DRとOCRが揃えば試算します。CH2・CH3の単位不一致、有限でない係数、0以下の剛性は起動前にエラーにします。

標準出力のCSVは従来の22列のままです。`> readings.csv` で記録しても試算の表示はCSVに混ざらず、コンソールに残ります。

## 単体で確認する

ロガー取得とOCR取得はそれぞれ単体で動きます。以下は `scraps/logger-ocr-live` を開いた状態で実行します。単体起動では `--managed` を付けません。終了は `Ctrl+C` です。

### OCRを校正する

このフォルダの `calibrate_meter.py` を使います。先頭の `SOURCE`、`REFLECTION`、`SAMPLE_RADIUS` を設定します。`SOURCE` はカメラ番号の整数 `0` など、録画なら `r"C:\measurement\recorded.avi"` のような動画パスです。`REFLECTION` は `none`（補正なし）、`horizontal`（左右反転）、`vertical`（上下反転）、`both`（両方）から選び、既知の数字が正しく見えることを確認します。半径は元の撮影画像上の画素数で、初期値の `1` は各点の周囲3×3画素を読みます。

カメラと計器を固定し、ピントや露光を調整します。全桁が `8` の表示テストなど、消灯部を含む全セグメントの位置が分かる画像を使ってください。

```powershell
python calibrate_meter.py
```

`Space` で画像を止め、左の桁から、各桁の上→右上→右下→下→左下→左上→中央の順に、点灯時に白飛びしない赤い箇所を左クリックします。計42クリックです。中心でなくても構いませんが、周囲の小領域も同じセグメント内に収めます。`B` で直前の点を取り消せます。42点が揃ったら `Enter` で確定し、出力した `FRAME_SIZE`、`REFLECTION`、`SAMPLE_RADIUS`、`SEGMENT_POINTS` を同じフォルダの `read_meter.py` に貼り付けます。旧設定の `SEGMENT_BOXES` は使わないので再校正してください。

動画では停止前に `N` で次のフレームへ進めます。中止は `Q`、`Esc`、画面の×です。中止した場合は設定を出力しません。画像端から読み取り範囲がはみ出す点は受け付けず、同じ部位を選び直します。縮小表示でも点と半径は元の撮影画像の座標です。カメラを動かしたときや解像度を変えたときも再校正します。校正スクリプトは単独で動き、設定値を表示するだけで読み取り側のファイルは書き換えません。

読み取りは小領域内の赤い画素率で判定します。白飛びの補完は行わず、白い画素率が `OFF_FRACTION`（初期値0.15）を超えれば、そのフレームの値を `null` にして連続確定をリセットします。点灯・消灯の間の曖昧な赤色率も `null` です。

### OCRだけ取得する

OCRだけを動かす場合は、校正した設定と `SOURCE` を指定して次を実行します。ロガーや換算の設定は不要です。

```powershell
python read_meter.py
```

標準出力に `received_at` と `value` のJSONLが出ます。未確定・読取不能は `null` です。このフォルダのOCR取得はプレビュー画面やCSVファイルを作らず、コンソールにJSONLを出力します。撮影画像や点灯判定を画面で確認するときは、同じ校正設定を貼り付けた `../seven-segment-ocr/read_meter.py` を使います。同じカメラを使う取得処理は終了してから起動してください。

### ロガーだけ取得する

ロガーだけを動かす場合は、`collect_logger.py` の `SETTINGS_FILE` と `DEVICE_ID` を設定し、取得するCHを引数で指定します。

```powershell
python collect_logger.py U1_CH1 U1_CH2
```

標準出力に `received_at` と指定CHの `voltages` のJSONLが出ます。出力は換算前の電圧で、OCRや `calculate_readings.py` の設定は不要です。8CHを読む場合は `U1_CH1`〜`U1_CH8` をすべて引数に並べます。終了後はWAVE LOGGER PROの画面で収集停止を確認します。

`calculate_readings.py` は両方の取得を起動して、電圧の換算とOCR値の時刻照合を行います。片方だけで換算・照合する起動方法はありません。

## 出力と時刻の照合

- ロガーは `received_at` と、CH名ごとの `voltages` を出力します。ロガーの無効値は `null` です。
- OCRは `received_at` と `value` を出力します。未確定の `value` は `null` です。
- 照合結果は標準出力のCSVに出ます。ロガーの新しい行ごとに、生電圧、換算値、最新のOCR値、時刻差、`voltage_status`、`ocr_status` を表示します。範囲外の生電圧はCSVに残り、対応する換算欄は空欄になります。他の有効なCHはそのまま換算します。記録する場合は標準出力を新しいCSVファイルにリダイレクトします。

`voltage_status` は `valid`（設定した全CHを換算できた）または `invalid`（いずれかのCHが欠測・範囲外）です。`ocr_status` は `ready`（OCR値が確定し、時刻差が上限以内）、`waiting`（OCR待ち、または受信停止）、`unreadable`（OCR未確定）、`time_gap`（時刻差が上限を超過）のいずれかです。電圧とOCRの状態は独立しており、照合に使えるのは `valid` かつ `ready` の行です。以前の `status` 列はこの2列に置き換えました。片側の受信が途切れたときは、`INPUT_TIMEOUT` 秒後にコンソールへ欠測を通知します。

時刻差は両方の `received_at` の絶対差です。ロガーは指定CHを読み終えたPC時刻、OCRはPCがフレームを読み込んだ時刻です。`MAX_TIME_GAP` の初期値は0.15秒で、実機で両方に現れる変化を見ながら調整します。動画の `received_at` は再生中にPCが読み込んだ時刻です。

ロガーは `READ_INTERVAL`（初期値0.2秒）の待ち時間を挟み、CHごとに `GetCurrentData()` で各ユニットの現在値を読みます。PCに転送済みの波形の最新位置とは別の値です。値が前回と同じでも毎回出力し、保存番号やサンプル位置での重複判定は行いません（Automationマニュアル p.44）。

NR-600の計測ユニット間同期は±1μs以下であり、今回の速報値の照合には現在値を使う方針です（NR-600マニュアル 10-2～10-3）。この仕様はCHを順に読むCOM呼出しの時間差や、カメラとの同期を保証するものではありません。多チャンネルリンクモードではサンプリング周期のずれが40ms以下、NR-CA04と他種ユニットの組み合わせでは設定に応じて最大40msまたは1サンプリング周期になる注記があります。現場の構成とOCRとの実際の時刻差を確認します。
