# NR-600の電圧データ取得PoC

[collect_logger.py](collect_logger.py) はWAVE LOGGER PROでUSB収集を開始し、8チャンネルの生データをコンソールとグラフに表示します。

## 準備

1. NR-600をWindows PCにUSBで接続し、製品版WAVE LOGGER PROとTkinterを使えるPythonを用意します。
2. WAVE LOGGER PROでユニット1の電圧CH1～8を有効にし、入力レンジをすべて±10Vにして、収集周期を設定します。ノーマルモードの「収集設定 → サンプリング」で「連続収集」を選び、リピートとExcel転送を使わない設定で `.ucf` に保存します（NR-600マニュアル 6-39～6-40）。
3. 収集を止めて必要な保存を済ませ、前回の試行で開いた画面も含めてWAVE LOGGER PROをすべて終了します。

このフォルダで依存パッケージをインストールします。

```powershell
python -m pip install -r requirements.txt
```

## 設定と実行

`collect_logger.py` の先頭で現場の設定を指定します。

| 設定 | 意味 |
|---|---|
| `SETTINGS_FILE` | 保存した `.ucf` の絶対パス |
| `DEVICE_ID` | NR-600本体のIDスイッチの値（0～3） |
| `CHANNELS` | `(入力ユニット番号, APIのCH番号)` の一覧。ユニットは1始まり、CHは0始まり |
| `READ_INTERVAL` | 現在値を読み終えた後の待ち時間（初期値は0.2秒） |
| `WINDOW_SECONDS` | グラフに残す時間幅（初期値は60秒） |

初期設定は1ユニット8CH、ユニット1の電圧CH1～8（APIのCH番号0～7）です。実行前に `.ucf` のパス、本体ID、有効チャンネルを確認し、更新間隔と時間幅には正の値を指定します。このスクリプトは電圧の表示までを行います。各CHの単位換算とOCRとの照合は [logger-ocr-live](../logger-ocr-live/README.md) を使います。

WAVE LOGGER PROを手動で開き直さず、次を実行します。

```powershell
python collect_logger.py
```

## 取得と表示

8チャンネルの現在値を、CHごとに `GetCurrentData()` で読みます。これはPCに転送済みの波形の最新位置とは別で、計測中の各ユニットで更新される値です。値が前回と同じでも、読出しのたびにコンソールに1行表示してグラフに追加します。保存番号・サンプル位置の管理は行いません（Automationマニュアル p.44）。

NR-600の計測ユニット間同期は±1μs以下であり、このPoCは現在値を使う方針です（NR-600マニュアル 10-2～10-3）。CHを順に読むCOM呼出しの時間差は別に生じます。また、多チャンネルリンクモードではサンプリング周期のずれが40ms以下、NR-CA04と他種ユニットの組み合わせでは設定に応じて最大40msまたは1サンプリング周期になる注記があります。現場の構成に適用できる条件を確認します。

コンソールの出力はCSV形式で、`elapsed_s`、`U1_CH1` から `U1_CH8` までの値を順に表示します。`elapsed_s` は8チャンネルを読み終えた時点のPC経過秒です。値はWAVE LOGGER PROでのスケーリング・平滑化・物理量変換前の測定値です。全サンプルを保存する用途には、WAVE LOGGER PROの保存波形を使います。

グラフは右端を現在として直近の時間幅を表示し、時間幅より古くなった点を除きます。縦方向の範囲は表示中の値に合わせて変わります。凡例の `U1_CH1` はユニット1の電圧CH1です。値を取得できない点はコンソールに `nan` と表示され、グラフでは線が途切れます。

## 終了とエラー時

グラフを閉じるか、実行したコンソールで `Ctrl+C` を押すと収集を停止します。WAVE LOGGER PRO側で収集が停止すると表示を終了します。読出しエラー時も停止を試みます。終了後はWAVE LOGGER PROの画面で停止を確認してから閉じます。

エラーが出た場合は、コンソールに表示された内容を確認し、原因を修正してから再実行します。機器IDの設定で `261`（`0x0105`）が出た場合は、WAVE LOGGER PROをすべて終了してから再実行します（NR-600マニュアル 6-18、Automationマニュアル p.14）。

## 旧版と検証

現在値の取得PoCの自動テストは、このフォルダで次のコマンドを実行します。

```powershell
python -m unittest discover -s tests -v
```

2026-11-05に模擬COMの自動テスト5件が通りました。指定CHの現在値、同値が続くときのCSV出力、無効値によるグラフの欠測、時間幅より古い点の除外、開始待ちと読出し失敗時の停止を確認しました。現在値を使う取得PoCの実機動作は未確認です。

2026-11-06に初期設定の1ユニット8CHで同じ5件が通りました。APIのCH番号0～7とCSVの `U1_CH1`～`U1_CH8` の対応、グラフ履歴と欠測の扱いを確認しました。

[コンソール版](archive/read_logger.py)、[波形のグラフ版](archive/plot_logger.py)、[現在値のグラフ版](archive/plot_logger_current.py)は `archive/` に保管しています。旧コンソール版の自動テストは次のコマンドで実行できます。

python -m unittest discover -s archive/tests -v
