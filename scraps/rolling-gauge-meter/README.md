# NR-600から数値を読むPoC

目的は、Pythonから収集を開始して、1チャンネルの数値が取得できるか確認することです。

[read_logger.py](read_logger.py)の先頭に設定をまとめ、接続 → 設定読込み → 収集開始 → 数値表示 → 停止の順に書いています。

## 現場での準備

1. Windows PCにWAVE LOGGER PROとPythonを用意します。WAVE LOGGER PROは一度手動起動して終了しておきます。
2. GUIで対象の入力ユニット・CH・収集周期を設定し、`.ucf`として保存します。初回はノーマルモード、リピートなし、保存切替が起きない短時間の条件にします。Excel転送はOFFにします。
3. ほかの収集とWAVE LOGGER PROを終了してから、Pythonで検証します。

このフォルダで依存パッケージを導入します。

```powershell
python -m pip install -r requirements.txt
```

## 書き換える場所と実行

`read_logger.py`の先頭を現場に合わせて変更します。

| 設定 | 意味 |
|---|---|
| `SETTINGS_FILE` | 保存した`.ucf`のパス |
| `CONNECTION` | `"USB"`または`"LAN"` |
| `DEVICE_ID` | USBなら本体ID。LANなら接続先IPの登録枠。いずれも0～3 |
| `UNIT` | 入力ユニット番号。1始まり |
| `CHANNEL` | APIのCH番号。0始まり。入力ユニット・入力種別の対応表で確認 |
| `READ_COUNT` | 読出しを試す回数。最初は10回 |
| `READ_INTERVAL` | Pythonの読出し間隔。装置の収集周期とは別 |
| `IP_ADDRESS`, `PORT` | LANの場合だけ指定 |

実行するだけです。コマンド引数は使いません。

```powershell
python read_logger.py
```

`index=..., raw=...`が表示され、最後に「数値を取得できました」が出れば、最初の疎通確認は成功です。設定ファイル・接続先・CHが正しいか、表示値をWAVE LOGGER PROと照合します。エラー時はPythonのエラー表示を確認して設定を修正します。

## このPoCで確認する範囲

取得するのはPCに届いている最新の1点です。同じindexが続くこともあります。全サンプルの取得・CSV保存・単位換算・OCR・板厚計算は行いません。`raw`はソフトのスケーリング等を通す前の値です。

収集開始が成功した後は、読出しエラーや`Ctrl+C`でも`finally`でStopを試みます。Stopから戻った後もPC側の残データ読出しが続く場合があります。Quitや自動切断は行わず、画面で状態を確認してからソフトを終了します。

対象はNR-600系1台のアナログ等のSingle型データです。NR-C512の整数型データには使いません。

## 確認状況

このPCでは接続・WAVE LOGGER PRO起動・依存パッケージのインストールを行っていません。構文を確認し、偽のCOMオブジェクトによる正常取得・取得失敗時の停止等の自動検証5件が成功しました。実際のCOM起動・接続・数値取得は現場での確認が必要です。

```powershell
python -m unittest discover -s tests -v
```

仕様の根拠と今後の板厚計算の検討は[分析文書](ANALYSIS.md)に残しています。

## LANの設定と複数項目の確認

LANは、本体・PCのネットワーク設定と、Python側の接続先指定を揃えます。

1. 本体の「機器設定 → ネットワーク → LAN設定」で、現在のIPアドレス・サブネットマスク・アクセス制限を確認します。既存設定で通信できるなら、その値を使います。本体側のLAN設定を変更した場合、マニュアルでは電源再投入後に有効になるとされています。
2. PCを同じネットワークへ接続します。1対1の例は、本体`192.168.0.120`、PC`192.168.0.10`、両方のサブネットマスク`255.255.255.0`です。例なので現場の実設定を優先します。
3. Pythonでは`CONNECTION = "LAN"`、`IP_ADDRESS`に本体IP、`PORT`に通常`24682`を指定します。`DEVICE_ID = 0`なら、PC側の登録枠0にこのIPを登録して接続します。`SetLanConfig`は本体のIPを書き換える処理ではありません。

「機器ID」はロガー本体の接続先、「ユニット番号」は入力モジュール、「CH番号」はモジュール内の入力を選ぶ番号です。8項目あるから機器IDを8つ使う、という関係ではありません。

現状のコードは1項目ずつ確認します。8項目をまとめて読む場合は、各項目のユニット・CH対応を確認し、同じ`sample_index`で`GetData`を繰り返す変更が必要です。例えばNR-HA08の電圧CH1～CH8ならCH引数は0～7ですが、同ユニットの電流CH1～CH4は8～11です。8項目という数だけで0～7とは決められません。別ユニットに分かれている場合はユニット番号も変えます。8項目が演算CHを含む場合、その演算値はこのAPIで直接取得できず、元の入力値から計算する必要があります。

根拠はNR-600マニュアル5-20～5-21・6-19、およびAutomationマニュアルp.7～8・14・17・43です。
