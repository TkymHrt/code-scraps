# 左右側辺を複数画像で比較する

side_lengths.pyの計測を土台に、4本の小さなスクリプトで定量分析を試します。
輪郭・左右端・長さの確認用3本もそのまま使えます。新しいコードも、設定と処理を上から順に読める構成です。
共通ライブラリ、クラス、コマンドラインの細かなオプションは作っていません。

## 今回試す4つの方法

| スクリプト | 調べたいこと | 入力 → 出力 |
| --- | --- | --- |
| `measure_batch.py` | 複数画像の左右の長さを同じ抽出条件で測る | 画像の一覧 → 長さ一覧・マスク・左右端の点列 |
| `compare_lengths.py` | 基準からの増減と、左・右の偏りを見る | 長さ一覧 → 差分・変化率 |
| `compare_sampling.py` | 点を拾う間隔で長さがどれくらい変わるか見る | 保存済み点列 → 間隔別の長さ・端点距離との比 |
| `compare_widths.py` | 全長だけでは見落とす局所的な幅の変化を見る | 保存済み点列 → 相対高さごとの幅・基準との差分 |

考え方は、まず従来の長さを複数枚で揃え、その数値の変化と、測り方への感度を別に調べることです。
同じ合計長さでも左右の変化が相殺される場合があります。
同じ長さでも幅の変化が違う場合があるので、幅の比較も独立して試します。

抽出は最初の1本だけです。残りの3本は、保存したCSVを読み、それぞれ単独で実行できます。
3本を全部使う必要はありません。比較手法を変えるだけならGrabCutをやり直す必要もありません。

## 1. 入力の一覧を作る

`opencv-grabcut` フォルダで実行します。依存関係は既存の `pyproject.toml` を使います。

```powershell
uv sync
Copy-Item practical/quantitative/samples.example.csv practical/quantitative/samples.csv
```

`samples.csv` を編集し、画像を指定します。
画像の相対パスは **入力CSVのあるフォルダが基準**です。
例えば、次の一覧なら画像を `practical/quantitative/images/` に置きます。

```csv
sample_id,image_path,mm_per_px
sample_A_pass00,images/sample_A_pass00.png,
sample_A_pass01,images/sample_A_pass01.png,
```

`sample_id` は重複しないIDです。結果フォルダ名にも使います。
Windowsでの上書きを避けるため、大文字と小文字だけが違うIDも重複として扱います。
まずは英数字と `_`、`-` の簡単なIDにしてください。
画像のパスにも英数字を使うと、WindowsのOpenCVで扱いやすくなります。
CSVのヘッダーはそのまま使い、不要な行は削除します。

`mm_per_px` は1pxあたりのmmです。未校正なら空欄にして、pxで比較します。
試料と同じ平面の基準寸法から、次のように求めます。

```text
mm_per_px = 基準の長さmm / 画像上の基準の長さpx
例: 10mmが200pxなら0.05
```

画像ごとに倍率が違う場合は、それぞれの換算値を指定します。
換算値を入れた画像ではpxとmmの両方の長さを保存します。空欄を0mmとして扱うことはありません。
画像の歪み・遠近によって場所ごとの倍率が変わる場合は、先に撮影条件や補正を揃えます。

## 2. 左右の長さを一括で測る

`measure_batch.py` 冒頭の初期指定を画像に合わせて調整してから実行します。
初期値はside_lengths.pyと同じです。確実な前景は試料内部だけに収めてください。

```powershell
uv run practical/quantitative/measure_batch.py
```

全画像へ同じ初期指定、反復回数、乱数シードを使い、縮小せずに抽出します。
画像の配置や背景が違う場合は、同じ設定で測れる画像だけを一覧にまとめ、グループごとに実行してください。
最大外側輪郭の内部を塗りつぶす扱いもside_lengths.pyと同じです。

`MEASURE_Y_RANGE = (0.0, 1.0)` は画像の上から下までを対象にします。
例えば `(0.2, 0.8)` にすると、画像の高さの20%以上80%未満の行で測ります。
値は0〜1、上端 < 下端で指定してください。これは画像上の範囲であり、試料の位置を追従する設定ではありません。
測る範囲が違うと長さも変わるので、比較する範囲を撮影時から揃えます。

出力は `results/` です。

```text
results/
  measurements.csv       1画像1行の長さ一覧
  conditions.json        全画像に使った抽出・測定条件
  sample_A_pass00/
    initial.png          GrabCutの初期指定
    raw_mask.png         抽出直後の領域
    mask.png             最大外側輪郭を塗りつぶした領域
    sides.png            測定した左端が橙、右端が水色
    edges.csv            y_px,left_x_px,right_x_px
```

`measurements.csv` には左・右・合計のpx/mm、画像サイズ、換算値、測定した最初と最後の行、
上下の距離 `vertical_span_px` を保存します。mm未設定の列は空欄です。
`edges_path` は `measurements.csv` のあるフォルダからの相対パスです。
保存先を移す場合は、点列のフォルダも一緒に移してください。

まず画像で抽出を確認してから、数値を比較します。
高さ121行のまっすぐな端は、最初と最後の画素中心の距離なので120pxです。
側辺だけを測り、上辺・下辺は含めません。

## 3. 基準からの増減と左右差を比べる

`compare_lengths.py` の `BASELINE_ID` を、基準にする画像のIDにします。
`UNIT = "px"` または `UNIT = "mm"` を選びます。mmでは全画像の換算値が必要です。

```powershell
uv run practical/quantitative/compare_lengths.py
```

`results/length_comparison.csv` に、左右・合計の長さ、基準との差、変化率を保存します。
基準はCSVの並び順に依存しません。1つの一覧に複数試料を混ぜず、同じ試料の比較に使ってください。

```text
差分 = 今回の長さ - 基準の長さ
変化率% = 差分 / 基準の長さ × 100
signed_left_minus_right_pct = (左 - 右) / (左 + 右) × 100
```

最後の値は正なら左が長く、負なら右が長いことを示します。
左右が同じだけ増える変化はこの値に出ないので、左右・合計の変化率も一緒に見ます。
撮影倍率を揃えるかmmに換算し、観測範囲も揃えてから解釈します。

## 4. 測る間隔を変えて比べる

```powershell
uv run practical/quantitative/compare_sampling.py
```

既定の `ROW_STEPS = (1, 2, 5, 10)` で点を拾い直し、
`results/sampling_comparison.csv` に左右別の長さを保存します。
どの間隔でも最初と最後の点を含め、測定範囲を揃えます。

`length_over_chord` は「点列に沿った長さ / 最初と最後を直結した距離」です。
直線なら1になり、端点距離に対して折れ線がどれほど長いかを表します。
`change_from_step1_pct` は毎行の計測からの変化率です。
細かな凹凸や画素の階段に敏感かを確かめるために使います。

間隔を広げると本物の細い切欠きも飛ばします。小さい値になったことを精度向上とは判断できません。
凹凸の周期と間隔の組み合わせでも値は変わります。
同じpx間隔が同じ実寸になるのは、撮影倍率・解像度が揃っている場合です。
倍率が違う画像どうしの「同じ尺度での凹凸比較」は、このスクリプトでは扱いません。

## 5. 高さごとの幅を比べる

`compare_widths.py` も `BASELINE_ID` と `UNIT` を設定して実行します。

```powershell
uv run practical/quantitative/compare_widths.py
```

幅は右端xと左端xの差、つまり画素中心間の距離です。画素数ではないので1を足しません。
観測した上端を0、下端を1に揃え、既定では21か所を線形補間して比較します。
`results/width_comparison.csv` に相対高さ、幅、基準幅、差分、変化率を保存します。

これは相対高さでの比較です。圧延による伸びや板の移動を補正した材料点の対応ではありません。
同じ亀裂の進展を追跡するには、別途位置合わせや撮影上の目印が必要です。
また、21か所の間にある細い切欠きは見逃します。
点数 `POSITION_COUNT` を増やして確認し、詳細を見るときは保存済み `edges.csv` も確認してください。

## 検証と分かったこと

次のコマンドで、基準・左端の切欠き・毎行の凹凸・倍率2倍の長方形を生成し、4本を実行できます。
実践用の設定は変更せず、検証用のコピーを `experiments/results/quantitative_demo/` に保存します。
長さと幅の比較はmmで実行します。

```powershell
uv run experiments/verify_quantitative.py
```

2026-10-11の確認結果:

| 合成画像 | 左の長さpx | 右の長さpx | 幅の比較・測り方への感度 |
| --- | ---: | ---: | --- |
| 基準の長方形 | 120.00 | 120.00 | 中央の幅6mm |
| 左端に10pxの切欠き | 138.10 | 120.00 | 中央の幅5mm、基準から−16.67% |
| 左端に毎行4pxの凹凸 | 494.77 | 120.00 | 2行間隔の左長さ120px、毎行から−75.75% |
| 同じ長方形を倍率2倍で作成 | 240.00 | 240.00 | 換算後は左右各12mm・幅6mmで基準と一致 |

毎行の凹凸は、21か所の幅の比較では今回すべて飛ばされました。
長さ・間隔への感度・幅を分けて見る理由が、この例でも確認できます。
この合成画像は計算と入出力を確かめるためのもので、実試料での検出精度を示すものではありません。

既存の `input_ai.png` とローカルの旧入力 `input.png` でも、一括計測と3種類の比較を実行しました。
AI画像ではside_lengths.pyと一括計測のマスクが完全に一致し、左右長も小数点以下2桁で一致しました
（左1979.97px、右1697.83px）。この確認も、正解付きの実試料での精度評価ではありません。

自動試験では、実際のGrabCutでの長方形と斜線の既知長、ID重複、明示した基準、左右差の符号、
測定範囲の下端が含まれないこと、倍率2倍の長方形のmm比較、mm未設定時に既存出力を変更しないこと、
末尾点の保持、凹凸への感度、相対高さの補間、画像別の幅のmm換算を確認します。

```powershell
uv run python -m unittest discover -s tests
uv run ruff check .
uv run ruff format --check .
uv run ty check .
```

## 運用で確認すること

細かな設定検証や保存失敗の回復処理は増やしていません。
画像を読めない場合、計測点が不足する場合、換算値が不正な場合など、数値を成立させるためのチェックだけを置きました。
CSVの列名やファイルの場所が違う場合はPythonのエラーを見て直します。

同じ保存先で再実行すると上書きします。試料や撮影条件ごとに保存先を分けてください。
一括計測が途中で失敗すると、その前までの画像・点列が残ります。
長さ一覧は全画像の計測成功後に更新するため、失敗した実行後は前回の一覧を新しい結果と混ぜず、修正して再実行してください。
実行後はマスク、側辺、CSVの更新と測定範囲を確認します。

測定しているのは各行の最外側の端です。折り返した裂け目の全経路、内部亀裂、欠損面積は測っていません。
反射の誤抽出も数値に反映されるので、まず既存の抽出結果確認を続けてください。
