# 実践用: フル解像度で輪郭と左右側辺を計測する

実画像で使うコードはこのフォルダの `ex03`〜`ex05` です。
3本とも元の解像度のまま抽出します。
設定・読み込み・抽出・描画・保存は各ファイルにすべて書いてあります。
縮小倍率やマスクの拡大による違いを比較条件から取り除いています。

## 1. 入力と実行

`opencv-grabcut` フォルダで実行します。
初回は `uv sync` を実行し、実際に使う画像を `practical/input.png` に置いてください。

```sh
uv run practical/ex03_outline.py
uv run practical/ex04_side_edges.py
uv run practical/ex05_side_lengths.py
```

既定の入力と保存先は、実行時の作業フォルダによらず `practical/` を基準にします。
結果は `practical/results/` に保存します。
3本は互いの出力を読み込まず、それぞれのファイル内で抽出から保存まで実行します。
入力・初期指定・反復回数・乱数シードを揃えると、3本で同じ抽出マスクになります。

別のフォルダへ移して使う場合も、スクリプトはその1本だけで動きます。
OpenCVとNumPyが入ったPython環境で `python ex05_side_lengths.py` のように実行できます。

コードは上から、入力の読み込み、初期マスクの作成、GrabCut、最大輪郭の選択、
描画や計測、保存の順です。クラスや共通処理ファイルは使いません。
ex04・ex05は各行を順番に調べ、試料のある行の左端と右端を集めています。
抽出方法自体を変更する場合は、比較条件が揃うように3本とも同じ変更を加えてください。

入力や保存先を変える場合は、使うスクリプトの冒頭を編集します。
**相対パスは、そのスクリプトがあるフォルダが基準**です。

```python
INPUT_PATH = "../images/sample_A_pass00.png"
OUTPUT_DIRECTORY = "results/sample_A/pass00"
```

出力先を試料IDと圧延回数で分けると、毎回の結果を保存できます。
同じ保存先で再実行すると同名の結果を上書きします。
圧延回数別の割合計算や集計は、この3本にはまだ含めていません。

## 2. 3本の違い

| ファイル | 抽出後に行うこと | 主な出力 |
| --- | --- | --- |
| `ex03_outline.py` | 試料の外側の輪郭を赤で描く | `result_03.png` |
| `ex04_side_edges.py` | 各行の左端と右端を赤い線で結ぶ | `result_04.png` |
| `ex05_side_lengths.py` | 左右端に沿った長さと合計を測る | `result_05.png` / `result_05.csv` |

ex05は左側をオレンジ、右側を水色で表示します。
上端と下端を横につなぐ線は長さに含めません。単位は **px** です。
各行の最外側を使うため、折り返しや奥まった裂け目の全経路を追う計測ではありません。
試料を縦向きに置いて、毎回同じ向きで撮影してください。
画像からはみ出した部分は計測できません。

## 3. 各スクリプトの冒頭で設定する

各スクリプトの冒頭に次の設定をまとめています。
初期値は3本とも同じです。比較に使う場合は、変更後も3本の値を揃えてください。

| 設定 | 意味 |
| --- | --- |
| `INPUT_PATH` | 既定の入力。`practical/` 基準のパス |
| `OUTPUT_DIRECTORY` | 既定の保存先。`practical/` 基準のパス |
| `ITERATIONS` | GrabCutの反復回数。1以上。初期値5 |
| `RANDOM_SEED` | 乱数シード。初期値0 |
| `CANDIDATE_RECT` | 前景候補の矩形 |
| `BACKGROUND_RECTS` | 確実な背景として固定する矩形 |
| `FOREGROUND_RECTS` | 確実な前景として固定する矩形 |

矩形は **左、上、右、下** の順で、画像全体に対する0〜1の割合です。
初期状態は背景候補です。前景候補、確実な背景、確実な前景の順で指定を重ねます。
重なった場合は後の指定が優先されます。
矩形は0〜1の範囲で、左 < 右、上 < 下になるように指定します。

初期値は旧ex03の指定を引き継いでいます。
中央の幅48〜56%を全高にわたって確実な前景とする設定も含まれます。
**実画像では、確実な前景を試料内部の小さな矩形へ変更してください。**
上下の余白や裂け目を確実な前景にすると、その部分は背景へ戻せません。
確実な前景を指定しない場合は `FOREGROUND_RECTS = ()` にできます。

幅が変わる試料では、最大幅が前景候補に収まり、最大幅でも試料に重ならない場所を背景にします。
確実な前景は、最小幅でも試料内部に残る場所だけに置きます。
0〜1の割合は画像サイズに対する指定であり、試料の幅や位置を自動で追従する機能ではありません。

床で撮影する場合も、試料と色の差があるつや消しの単色背景を使い、影や背景の模様を確認します。
反射除去の試験コードは実践版へ組み込んでいません。
試料の本物の突起を残したまま、まず初期指定と抽出結果を確認する構成です。

## 4. 保存する画像と条件

どのコードも、主な結果画像に加えて次を保存します。

| 末尾 | 内容 |
| --- | --- |
| `_initial.png` | 青が確実な背景、緑が確実な前景、橙が前景候補、灰が背景候補の初期指定 |
| `_raw_mask.png` | GrabCut直後のマスク。離れた領域も含む |
| `_mask.png` | 最大外側輪郭を塗りつぶしたマスク。3本とも同じ条件で選ぶ |
| `_conditions.json` | 入力のパスとサイズ、処理条件、ライブラリのバージョン |

処理条件には、倍率1.0、反復回数、乱数シード、全ての矩形指定を記録します。
最大外側輪郭の選択、内部の穴の塗りつぶし、各行の最外側で側辺を作る方法も記録します。
これは旧ex04・ex05と同じ外形の扱いです。内部の穴や亀裂の面積は計測対象に含めていません。
縮小・拡大・オープニング・輪郭の平滑化は行いません。

先に `_initial.png`、次に `_mask.png` と元画像を確認し、正しい外形が取れた状態でCSVを使います。
同じ画像で3本の `_mask.png` と `_conditions.json` が一致することを確認できます。
処理条件が揃っていても、反射の誤検知がなくなることを保証するものではありません。

独自のエラーチェックは、画像を読めない場合と試料の領域が見つからない場合だけです。
矩形の範囲、画素数、反復回数、保存の成功などの細かなチェックは省いています。
実行前に設定と保存先を確認し、実行後に結果画像やCSVが更新されていることを確認してください。
エラーが出た場合は、入力と初期指定を直して再実行します。

## 5. 長さの比較

`result_05.csv` は従来と同じ `edge,length_px` の2列です。
左・右・合計の値を保存し、画像とターミナルにも同じ値を表示します。
今回のフル解像度の値と、旧版で半分縮小して得た値は、抽出条件が異なるため直接混ぜないでください。
旧結果は `experiments/reference/result_05_halfsize.csv` に保存しています。

各試料の初期値と圧延後の値を比較する際は、同じ処理条件に加えて、
撮影倍率、カメラの高さ、画像の解像度と向きも揃えます。
mmへ換算するには、試料と同じ平面の基準寸法から1pxあたりの長さを求める必要があります。

## 6. AI画像での動作確認

AI画像と試験結果は `experiments/` 側に置いたまま、実践コードを動かせます。
動かすスクリプトの冒頭を、次のように設定します。

```python
INPUT_PATH = "../experiments/input_ai.png"
OUTPUT_DIRECTORY = "../experiments/results/practical_fullsize"
```

3本を比較する場合は3本とも同じ設定にし、`opencv-grabcut` フォルダから実行します。

```sh
uv run practical/ex03_outline.py
uv run practical/ex04_side_edges.py
uv run practical/ex05_side_lengths.py
```

この確認は処理サイズと条件の統一を確認するもので、実画像での精度評価ではありません。
