# code-scraps

コードを試し、保管し、必要になったものを実際に使うためのリポジトリです。
言語や分野を限定せず、題材ごとにまとめます。

## 置き方

```text
scraps/<題材名>/
  README.md        題材の説明・動かし方・メモ
  実行するコード    実際に使うスクリプトはここに置く
  sandbox/         自由な試作・学習・比較
  tests/           自動検証
```

調査やメモだけの題材も同じ場所に置きます。
必要なファイルやフォルダだけを作り、空の `sandbox/` や `tests/` は用意しません。
日付は必要に応じて題材のREADMEに記録し、変更履歴はGitで追います。
依存関係や実行手順も題材側で管理します。

## 書き方

試作は `sandbox/` で自由に作れます。途中で動かなくても構いません。
実際に使うコードは題材の直下に置き、次を基本にします。

- 1目的1スクリプトで、設定・入力・処理・保存までを追える形にする。ほかの自作モジュールに依存させない。
- 初学者や引き継ぐ人が分かる名前と処理順を優先する。
- 小さな関数や短い重複は許容する。不要なクラスや共通モジュールを増やさない。
- YAGNIを基本に、今必要な機能だけを作る。
- 誤った結果やデータ破壊を防ぐチェックは残し、過剰な例外処理・復旧・拡張性は持たせない。

実行前に入力・設定・保存先を確認し、実行後に出力を確認します。
失敗したら原因を直して再実行する運用で簡素に保ちます。
試作や自動検証に、実践用の実装方針を強制しません。

## 追加する

```powershell
./tools/New-Scrap.ps1 my-topic
# -> scraps/my-topic/README.md
```

題材名は英小文字・数字をハイフンでつなぎます。手動作成なら `templates/scrap.md` を使えます。
実行コード・試作・調査が増えても、同じ題材フォルダで育てます。

## 運用

`main` への直接commit・pushで構いません。
変更に関係する検証を行い、実行手順が変われば題材のREADMEも更新します。
秘密情報、実データ、仮想環境、大きな生成結果はコミットしません。
